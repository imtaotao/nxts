# 性能诊断

- 规范状态：部分定稿
- 实现状态：未实现
- 最后更新：2026-07-28
- 文档顺序：1

## 目标与边界

本规范定义不改变程序语义和接受结果的性能诊断、提示条件与基准入口。具体优化策略由 [`1-loweringStrategies.md`](../compiler/optimizer/1-loweringStrategies.md) 定义，最终性能目标是达到等价 Go 实现级别。

## 核心原则

性能诊断在语义检查和优化分析之后运行。编译器已经完成自动优化时不得提示用户手动修改代码。诊断不能改变程序接受结果，也不能默认增加运行时插桩。

高置信度诊断可以默认启用；启发式建议由独立性能诊断配置控制。PGO 可以提供热点证据，但是否启用采样必须是显式工具链选择。

## 数组

| 场景                             | 建议方向                                     |
| -------------------------------- | -------------------------------------------- |
| 无法推导容量且循环持续增长       | 候选 `std/array.withCapacity` 或 `reserve`。 |
| 热点混合联合数组                 | 评估同构数组、显式转换或数组联合。           |
| `Object.keys(array)` 仅用于遍历  | 使用 `keys()` 或普通索引循环。               |
| 循环中结构修改阻止优化           | 分离构建与遍历，或明确快照长度。             |
| async 判断回调或 async `forEach` | 使用 Promise 组合或显式异步循环。            |
| 已推导为 `number` 且适合原生类型 | 使用 `i32`、`f64` 等确定类型。               |

候选标准库 API 的最终名称由 T49 决定；诊断应绑定标准库符号身份，不按文本名称猜测。

## 类

| 场景                                | 建议方向                               |
| ----------------------------------- | -------------------------------------- |
| 热路径 mutable 箭头字段参与多态调用 | 评估普通方法或 `readonly` 箭头字段。   |
| 循环中反复创建并逃逸的局部类        | 提升稳定类声明或减少可观察动态身份。   |
| 动态字段使固定类进入扩展区域        | 评估显式字典或固定字段。               |
| 构造期间复杂跨方法调用阻止安全证明  | 简化初始化阶段或延后可覆盖调用。       |
| 已知目标仍保留虚调用                | 报告阻止去虚拟化的逃逸或模块边界事实。 |

诊断不能通过合并类身份、改变箭头函数身份或禁止合法 JavaScript 初始化顺序获得性能。

## 对象

| 场景                             | 建议方向                           |
| -------------------------------- | ---------------------------------- |
| 热路径使用动态计算 key 形成字典  | 评估固定字段或显式 Map / 字典。    |
| `Object.keys` 结果只用于立即遍历 | 使用 `for...in` 或允许循环融合。   |
| 精确对象频繁进入可写字典视图     | 评估从创建点直接使用字典类型。     |
| 反射阻止对象标量替换             | 缩小反射作用域或使用直接字段访问。 |

已经完成反射专门化、循环融合或对象分配消除时不得继续提示。

## 字典

| 场景                                    | 建议方向                         |
| --------------------------------------- | -------------------------------- |
| 字面量动态 key 数量静态已知但容量未预估 | 预分配原生字典容量。             |
| 对象视图未知 key 成为热点               | 评估直接使用原生字典。           |
| 热路径反复首次创建扩展状态              | 在创建点使用字典类型或固定字段。 |
| 枚举顺序不可观察但仍维护顺序元数据      | 允许优化器消除顺序状态。         |
| 碰撞导致强化重哈希                      | 提供安全诊断，不泄漏哈希密钥。   |

诊断不得建议关闭哈希安全、GC 精确扫描或 JavaScript 枚举顺序。

## 字符串

| 场景                                | 建议方向                            |
| ----------------------------------- | ----------------------------------- |
| 循环中反复 `result = result + part` | 建议使用待 T49 定名的线性构建 API。 |
| 连续拼接产生多个中间字符串          | 编译器实现回归。                    |
| Latin-1 热路径索引重复分配单字符    | 单字符缓存或逃逸优化候选。          |
| 字符串比较产生转码分配              | 编译器实现回归。                    |
| 全常量字符串操作仍保留 runtime 节点 | 常量折叠回归。                      |

基准至少覆盖 Latin-1、UTF-16、混合比较、有效与越界索引、数值格式化、连续拼接、模板、单字符缓存和长度失败。最终目标与等价 Go 字符串构建及比较路径对照，同时单独验证 JavaScript UTF-16 行为差异。

## 数值

当静态分析证明 `number` 值适合更具体原生类型且可能改善运算、存储或 ABI 时，可以建议 `i32`、`i64`、`f32` 或 `f64`。

该诊断：

- 默认是建议，不是类型错误。
- 必须说明建议类型和优化方向。
- 不能在语义无法证明等价时自动改写。
- 允许项目显式升级为错误。
- 不能改变现有 `number` 程序行为。

已经使用原生类型或转换不能改善实际热点时不得提示。

## 空值

工具链应把以下可证明情况视为编译器性能回归候选：

- 空值联合发生本可避免的重复 `UnionRepack`。
- 同一稳定控制流区域重复执行等价非空检查。
- 空值操作意外产生动态盒或堆分配。
- 标量空值数组退化为逐元素对象包装。

这些情况违反空值表示的零成本边界，不应要求用户改写语义正确的源码。

## 枚举

| 场景                                          | 建议或实现诊断                            |
| --------------------------------------------- | ----------------------------------------- |
| 热点可空数字枚举使用额外状态，且 `0` 未被使用 | 可建议从 `1` 开始显式编码；不能自动改值。 |
| 稀疏数字分支生成范围巨大的跳转表              | 编译器实现回归，应改用比较树等紧凑策略。  |
| 普通枚举值发生包装、分配或重复验证            | 编译器实现回归。                          |
| 未使用成员遍历却保留运行时成员表              | 链接或可达性分析回归。                    |
| 同表示联合增加无语义需求的来源 tag            | 布局或 lowering 回归。                    |

诊断不能建议关闭成员有效性验证边界，也不能改变公开成员值来换取性能。

## 动态值与转换

| 场景                           | 建议方向                                   |
| ------------------------------ | ------------------------------------------ |
| 热循环重复打包同一静态值       | 保持静态类型，或把打包移出循环。           |
| 大型聚合频繁进入 `unknown`     | 使用闭合联合、泛型或静态接口。             |
| 稳定值重复执行同一类型检查     | 编译器应复用证明；无法复用时报告失效原因。 |
| 打包后立即检查仍产生装箱       | 优化器实现回归。                           |
| 对象重建身份不可观察但未被消除 | 逃逸分析或标量替换候选。                   |

诊断必须基于已确认成本或热点事实；已经完成消除时不得提示。不得建议使用普通断言、未验证重解释或关闭外部数据验证。

## 接口

| 场景                               | 建议方向                                       |
| ---------------------------------- | ---------------------------------------------- |
| 热路径 witness 已知但仍间接调用    | 报告阻止去虚化的模块或逃逸事实。               |
| 缺失可写可选属性反复首次扩展       | 在具体对象中声明可选槽位，或以接口上下文创建。 |
| 动态接口检查重复执行               | 复用稳定证明；无法复用时报告失效原因。         |
| 普通固定对象访问因接口能力增加分支 | 编译器实现回归。                               |

诊断不能建议对象裁剪、隐藏写入、关闭反射一致性或运行时成员扫描。

## 递归类型

递归类型声明本身不产生性能告警。工具链可以依据实际布局和生成代码提示分散分配、指针追踪、复杂联合 payload 或无法去虚化的递归调用，但不能把数据结构成本误报为类型系统额外开销。

性能基准至少区分普通非递归对象、递归对象字段访问、可空递归引用、复杂递归联合、不可达循环回收、有限泛型实例和无限增长诊断。启用递归能力不能使普通对象增加字段、分支或分配。

## 函数

| 场景                       | 建议方向                                 |
| -------------------------- | ---------------------------------------- |
| 已知直接调用仍物化函数值   | 报告阻止直接调用或内联的逃逸事实。       |
| 无逃逸 rest 数组仍分配     | 标量替换或栈分配候选。                   |
| 短 ABI 适配入口未内联      | 报告阻止内联的模块或代码体积事实。       |
| 间接调用退化为通用动态分派 | 编译器实现回归。                         |
| 重复重载解析消耗异常       | 报告候选规模、索引命中与高成本类型关系。 |

基准至少覆盖普通直接调用、方法调用、函数值间接调用、rest 逃逸与不逃逸、参数数量适配、返回表示适配和重载入口。普通精确签名调用不能创建函数对象、参数数组、装箱或动态签名检查。

## 元组

| 场景                               | 建议方向                     |
| ---------------------------------- | ---------------------------- |
| 固定索引仍保留边界检查             | 编译器实现回归。             |
| 小型不逃逸元组仍堆分配             | 逃逸分析或标量替换候选。     |
| 固定 tuple rest 调用仍创建参数对象 | 报告导致身份可观察的使用点。 |
| 同构 readonly 数组视图发生复制     | 编译器实现回归。             |
| 固定元组携带容量或动态 offset 表   | 表示实现回归。               |

性能基准至少覆盖同构原生元组、异构固定位置、动态索引、optional/rest、tuple rest 参数、spread/rest 解构、GC 扫描和不可达循环。第一版可以接受整体吞吐约为等价 Go 实现的 50%，但不能引入阻止后续达到 Go 水平的统一装箱、动态元素表或强制堆分配。

## 泛型

| 场景                           | 建议方向                           |
| ------------------------------ | ---------------------------------- |
| 表示相同实例重复生成机器码     | 报告未共享原因和主要实例来源。     |
| 一等泛型值热调用无法去虚化     | 报告值流与固定槽位成本。           |
| 接口泛型方法产生大量闭合槽位   | 报告接收者和实例需求来源。         |
| 普通泛型调用携带隐藏参数或装箱 | 编译器实现回归。                   |
| 实例需求持续增长               | 显示声明、初始实参和重复增长路径。 |

工具链使用版本确定且可配置的实例数量、类型深度、Checked HIR 和机器码规模预算。软阈值产生性能诊断，硬资源上限产生编译错误；提高预算不能改变类型规则或预算内程序的结果。

基准至少覆盖手写具体函数、直接泛型调用、一等泛型函数值、接口泛型方法、泛型类构造、跨模块新实例和大量安全共享实例。普通直接泛型路径必须以与具体函数等价的调用形态为目标；动态多态路径与 Go 函数值或接口调用对照，并单独报告代码体积与分配。

## 类型运算符

类型运算复杂度诊断必须报告运算种类、输入类型、键或成员规模、递归路径和主要缓存未命中来源。预算在同一工具链版本中确定，不依赖目标机器或优化级别。

任何闭合 `keyof`、类型查询、索引访问类型或 `as const` 节点进入可执行 IR 都属于编译器实现回归。纯类型查询不能导致运行时模块保留、初始化、键数组、冻结、复制、分配或类型描述符。

## 高级类型

高级类型资源诊断必须区分条件分支、映射键、模板状态、`infer` 候选和递归增长，展示工具名称、主要输入、缓存命中与增长路径。预算超限不能输出部分类型或动态兜底。

以下情况属于实现回归：高级类型节点进入可执行 IR；类型级模板产生运行时正则或扫描；映射类型自动复制对象；大小写类型工具为已有值插入转换；readonly 或类型工具增加运行时字段。
