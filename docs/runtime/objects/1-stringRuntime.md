# 字符串 Runtime

- 任务编号：T13
- 规范状态：已定稿
- 实现状态：未实现
- 最后更新：2026-07-28
- 文档顺序：1

## 目标与边界

本规范定义字符串存储的创建、索引、比较、哈希、拼接、格式化和长度失败算法。用户可观察值行为见 [`2-stringSemantics.md`](../../language/semantics/2-stringSemantics.md)，物理头布局见 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)。

## 存储选择

runtime 按 T45 已确定的 Latin-1 / UTF-16 布局分配连续不可变 code unit 数据。创建时若所有 code unit 不大于 `0xFF` 使用 Latin-1，否则使用 UTF-16。编码选择不能改变 `length`、索引、比较、哈希或字符串身份语义。

字符串存储由 GC 管理，但不赋予 `string` 用户可观察对象身份。字面量和内容相同的结果可以共享存储。

## 索引与子串

有效索引 O(1) 读取一个 UTF-16 code unit，并返回对应单 code unit 字符串；越界返回 `undefined`。常用 Latin-1 单字符结果应缓存，其他单字符可驻留或通过逃逸分析消除分配。

当前子串实现复制目标区间，避免短子串长期持有大型源字符串。未来切片表示只能在不改变内存保活和复杂度保证时引入。

## 比较与哈希

相等、关系比较和哈希按 UTF-16 code unit 序列计算，不依赖编码标签。Latin-1 与 UTF-16 混合比较边读取边扩展，不分配转码字符串。

相等比较可以先检查共享引用和长度；最坏 O(n)。关系比较最坏 O(min(n, m))。哈希可以惰性缓存，但缓存值不构成稳定序列化格式。

## 拼接与格式化

连续拼接和普通模板消费一个扁平片段序列：

1. 按源码顺序求值片段。
2. 每完成一个前缀，执行 checked 累计 code unit 长度检查。
3. 确定最终 Latin-1 或 UTF-16 编码。
4. 成功路径只分配一次最终存储。
5. 基础数值使用栈上临时缓冲区直接写入目标，不创建中间字符串。

基础值格式必须使用 T13 的确定规则，不依赖系统区域设置。空字符串拼接允许直接复用另一侧不可变字符串。

循环反复追加可能形成 O(n²) 复制。标准库线性构建器与工具链诊断由 T49 确定，不通过隐藏 rope 改变普通字符串复杂度。

## 长度与失败

公开上限为 `i32::MAX` 个 UTF-16 code unit。动态创建、拼接或解码在分配和写入前使用 checked `usize` 计算；超过上限或算术溢出抛出 `RangeError`，OOM 进入 T46 独立失败路径。

失败不能产生整数回绕、截断、部分结果或越界写入。静态上界已证明安全时，前端或优化器可以消除重复检查。

## 优化边界

允许字符串驻留、短字符串内联、哈希缓存和替代拼接表示，但普通长度及索引必须保持 O(1)，比较不能分配，普通动态拼接不能装箱或创建参数数组，值结果与失败顺序不能随优化级别变化。
