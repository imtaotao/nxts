# 动态值与类型检查 Runtime

- 来源能力：T44–T46
- 规范状态：部分定稿
- 最后更新：2026-07-28
- 文档顺序：6

## 目标与边界

本规范定义动态打包、类型描述关系和接口 witness 查询的 runtime 职责。静态目标合法性由 checker 决定，值布局由 T45 决定。

## 动态打包

runtime 只处理 Layout IR 明确标记的打包：

- 可内联标量写入规范 payload。
- 管理引用保留对象身份。
- 需要装箱的聚合使用类型化 GC 对象。
- 品牌不形成运行时描述身份。

普通静态值不携带动态描述符。打包只能出现在显式动态边界或签名本身返回 `unknown` 的可信 API。

## 类型关系查询

常见检查使用：

- 直接动态标签比较。
- 类描述符祖先关系。
- 精确对象、容器与函数签名指纹。
- 预生成接口 witness。
- 联合成员到描述符关系表。

查询不能扫描对象字段、容器元素或用户属性，也不能调用用户代码。目标是常见路径 O(1)。

## 成功载荷

检查结果必须同时提供布尔结果和已验证 payload 或接口 witness，避免成功分支重复查询。接口检查只建立固定大小视图，不复制底层对象。

## 跨模块元数据

链接器预先验证类型指纹、接口契约和 witness ABI，并建立快速查询关系。运行时不能因元数据缺失退化为成员扫描、getter 调用或临时结构适配。

## 失败边界

普通不匹配返回失败结果。损坏描述符、无效 witness 或未通过链接验证的 ABI 属于 runtime 契约故障，不是普通类型不匹配。

## 性能验收

至少测量标量与引用打包、聚合装箱、类/对象/接口/函数/联合检查、重复检查消除、跨模块查询，以及打包后立即检查的分配消除。
