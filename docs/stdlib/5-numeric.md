# 数值标准库

- 来源能力：T08–T12
- 规范状态：部分定稿
- 文档顺序：5

## 目标与边界

本规范定义显式数值转换、精确转换和整数 checked / saturating 内建能力。T08–T12 已确定的行为保持定稿；最终模块路径、公开名称和结果承载类型由 T49 定稿。

## 转换入口

已经确定类型的数值通过两个入口族转换：

| 入口族               | 语义                                             | 成本                                |
| -------------------- | ------------------------------------------------ | ----------------------------------- |
| `toTarget(value)`    | 确定转换，可能舍入、截断或改变符号解释，不失败。 | 零到少量原生指令，不分配。          |
| `tryToTarget(value)` | 仅在值可由目标精确表示时成功，否则 `null`。      | 允许检查，不 trap、不装箱、不分配。 |

```ts
import { toF32, toF64, toI32, toI64, tryToI32 } from 'std/numeric';

const wide = toI64(smallI32);
const narrow = toI32(largeI64);
const rounded = toF32(valueF64);
const native = toF64(jsNumber);
const checked = tryToI32(externalValue);
```

候选入口覆盖全部 `i8..i64`、`u8..u64`、`f32`、`f64`、`number`、`isize` 和 `usize` 目标，以及对应 `tryTo*`。

编译器按绑定后的标准库符号身份识别 intrinsic；用户同名函数仍是普通函数。

`number` 与 `f64` 的转换无损且零指令，只改变语义类型身份。

## 整数到整数

`toTarget` 使用目标宽度补码规则：

| 源与目标       | 行为                               |
| -------------- | ---------------------------------- |
| 同宽、符号不同 | 保留全部位，按目标符号解释。       |
| 源更宽         | 丢弃高位。                         |
| 源更窄         | 有符号源符号扩展，无符号源零扩展。 |

```ts
const a = toI16(valueI8);
const b = toU16(valueU8);
const c = toI8(valueU16);
const d = toU32(valueI32);
```

`tryToTarget` 只在源整数数学值位于目标范围时成功，不使用位截断。

涉及平台整数时，宽度按当前目标确定，不生成运行时平台判断。

## 浮点之间转换

| 转换                | `toTarget`                                             |
| ------------------- | ------------------------------------------------------ |
| `f32 -> f64/number` | 精确扩宽，保留无穷和零符号。                           |
| `f64/number -> f32` | 就近向偶数舍入；溢出为无穷，下溢可为次正规或带符号零。 |
| `number <-> f64`    | 精确、零指令。                                         |

NaN 保持为 NaN，但不保证 payload、符号和 signaling 状态。`-0` 保留符号。

## 整数与浮点

整数到浮点按目标精度就近向偶数舍入。可能损失整数精度，但当前内建整数不会因范围超过目标浮点最大有限值而产生无穷。

浮点到整数的 `toTarget` 先向零截断，再按目标范围饱和：

| 源值                         | 结果               |
| ---------------------------- | ------------------ |
| 有限且截断后在范围内         | 截断整数。         |
| 大于目标最大值或正无穷       | 目标 `MAX`。       |
| 小于有符号目标最小值或负无穷 | 有符号目标 `MIN`。 |
| 转无符号目标的负值或负无穷   | `0`。              |
| `NaN`                        | `0`。              |
| `0` 或 `-0`                  | `0`。              |

该行为不是 JavaScript `ToInt32` 模运算。

## 精确转换

| 方向                | 成功条件                                           |
| ------------------- | -------------------------------------------------- |
| 整数 -> 整数        | 数学值位于目标范围。                               |
| 整数 -> 浮点        | 目标浮点与源整数数学值完全相等。                   |
| 浮点 -> 整数        | 有限、无小数且位于目标范围；`-0` 可转 `0`。        |
| `f32 -> f64/number` | 始终成功。                                         |
| `f64/number -> f32` | 有限值可精确还原；无穷、NaN 和保留符号的零也成功。 |
| `number <-> f64`    | 始终成功。                                         |

失败统一返回 `null`，不区分范围、精度、小数或特殊值原因：

```ts
const exact = tryToI32(value);
const fallback = tryToI32(value) ?? 0;
```

结果必须以内联 payload 与状态表示，不分配。立即检查 `null` 时可以直接使用成功标记，不物化联合值。

## Checked 整数 API

候选能力覆盖：

- checked 加、减、乘和有符号取负。
- checked 除法和取模。

成功返回精确目标整数，失败显式返回。失败不能 trap / panic，结果不分配。

## Saturating 整数 API

候选能力覆盖加、减、乘和有符号取负。结果越界时固定为目标类型 `MIN` 或 `MAX`，不产生失败。

普通加减乘使用回绕，因此不要求独立 wrapping API。

## `Number` 与 `Math` 待确认能力

T49 可以分批提供：

- `Number.isNaN`。
- `Number.isFinite`。
- 明确输入边界的 `Number(value)`。
- 常用纯 `Math` 函数。
- 原始浮点位读写。

`Number(value)` 若支持，必须明确输入类型、字符串解析、对象转换、NaN 结果、失败和成本，不能恢复隐式 `ToNumber`。

## 编译器契约

- checker 只按绑定后的标准库符号身份识别数值 intrinsic；用户同名函数仍是普通调用。
- 常量求值与运行时执行必须在同一编译目标上产生相同结果。
- `Target | null` 使用语言统一联合类型，不建立标准库私有类型或调用约定。
- 数值转换不能使用 `as`。

Checked HIR 操作类别由[阶段间 IR 契约](../compiler/ir/1-irContracts.md)定义，原生指令、溢出检查和后端无效值隔离由[Lowering 与优化策略](../compiler/optimizer/1-loweringStrategies.md)定义，结果布局与调用边界分别由[类型运行时表示](../compiler/representation/1-typeRepresentation.md)和[类型与调用 ABI](../compiler/abi/1-typeAbi.md)定义。
