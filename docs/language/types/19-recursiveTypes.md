# 递归类型

## 目标

定义递归类型的合法边界、类型相等与兼容、推导要求及泛型惰性实例化语义，使递归对象保持 TypeScript 风格用法，同时不接受透明无限类型或要求无限具体实例的程序。

类型身份见 [`2-typeIdentity.md`](./2-typeIdentity.md)，赋值兼容见 [`3-typeCompatibility.md`](./3-typeCompatibility.md)，类型推导见 [`5-typeInference.md`](./5-typeInference.md)，类型别名与接口分别见 [`16-typeAliases.md`](./16-typeAliases.md) 和 [`17-interfaces.md`](./17-interfaces.md)。

checker 图算法见 [`5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md)，物理表示见 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)，循环扫描见 [`1-gcTypeDescriptors.md`](../../runtime/gc/1-gcTypeDescriptors.md)，跨模块指纹见 [`1-typeAbi.md`](../../compiler/abi/1-typeAbi.md)。

## 核心原则

| 原则       | 约束                                                                                         |
| ---------- | -------------------------------------------------------------------------------------------- |
| 有限值布局 | 每条返回自身的运行时布局路径必须经过固定大小的引用间接层。                                   |
| 有限符号图 | 递归声明表示为有限类型模式图和带替换的回边，不展开为无限类型树。                             |
| 按需实例化 | 改变泛型实参的递归声明合法；具体实例只在类型检查、布局或代码生成确实需要时创建。             |
| 静态失败   | 真正要求无限类型计算或无限代码专门化的操作在触发位置编译报错，不退化为动态执行。             |
| 表示复用   | 递归类型复用对象、数组、字典、函数、接口和联合类型的既有表示，不增加递归专用 tag 或包装。    |
| 循环可回收 | 运行时允许自引用和互相引用；GC 必须能够回收不可达循环。                                      |
| 局部付费   | 未触发复杂递归运算的代码不承担额外运行时成本；类型图缓存和增长检测只影响编译期。             |
| 确定性诊断 | 复杂度预算和增长检测不依赖机器速度、优化级别或遍历偶然顺序，失败时必须显示递归或实例化路径。 |

递归声明是否容易构造，不决定该类型是否合法。T31 检查的是静态类型关系和有限运行时表示，不要求每个递归类型都包含 `null`、`undefined` 或其他终止成员。

## 三层递归模型

checker 必须区分三种图，不能使用一个无限展开的类型树同时承担全部职责：

| 图             | 节点与边                                             | 有限性要求                             |
| -------------- | ---------------------------------------------------- | -------------------------------------- |
| 符号类型图     | 声明模式、类型参数、成员类型和带类型替换的递归边     | 每个声明形成有限图                     |
| 按需具体实例图 | 当前编译确实使用的规范类型实参组合                   | 单次成功编译所需求的实例闭包必须有限   |
| 运行时对象图   | 堆对象、数组、字典、闭包和接口底层对象之间的实际引用 | 可以包含任意有限数量的循环，不要求为树 |

例如：

```ts
type Growing<T> = {
  next: Growing<T[]> | null;
};
```

该声明只有一个有限的符号节点和一条携带 `T -> T[]` 替换的递归边。`Growing<i32>`、`Growing<i32[]>` 和 `Growing<i32[][]>` 是不同的具体类型实例，但编译器不得仅因声明存在就提前创建无限实例。

## 引用间接层

引用间接层在当前值中只占固定大小的引用或固定大小的引用视图，其目标布局不以内联方式嵌入当前值。

下表定义 T31 判断递归是否合法时消费的类型构造属性；具体布局由 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md) 统一定义。

| 类型构造                        | 是否构成间接层 | 原因                                                             |
| ------------------------------- | -------------- | ---------------------------------------------------------------- |
| 精确对象与类实例                | 是             | 当前值保存对象引用，字段位于独立对象布局中。                     |
| 数组与字典                      | 是             | 当前值保存容器引用或固定大小容器视图，元素与条目位于独立存储中。 |
| 函数与闭包                      | 是             | 函数值使用固定大小代码与环境引用表示。                           |
| 接口值                          | 是             | 接口使用固定大小底层引用与 witness 视图，不内联具体实现对象。    |
| 标准库声明为引用表示的容器      | 是             | 对应规范必须明确固定大小引用 ABI 和 GC 行为。                    |
| 联合、交叉、透明别名            | 否             | 只组合或重命名类型，不自行提供存储间接层。                       |
| `null`、`undefined`、`readonly` | 否             | 只改变值域、空值状态或写权限，不改变递归成员的存储位置。         |
| 元组                            | 是             | T35 将元组确定为具有数组身份的引用容器，位置位于独立元组对象中。 |

编译器内部应由各类型构造显式提供 `isRuntimeIndirection` 或等价属性。checker 不能根据类型名称猜测，也不能为通过检查而插入隐藏 `Box`。

## 合法递归

### 对象、容器与函数递归

每条循环都经过引用间接层时，直接递归、互相递归和容器递归合法：

```ts
type Node = {
  value: i32;
  next: Node | null;
};

type Json = string | number | boolean | null | Json[] | { [key: string]: Json };

type RecursiveHandler = () => RecursiveHandler;
```

接口成员和类字段也可以引用自身或其他递归声明。接口 `extends` 循环和类继承循环不是值引用递归，分别由 T29、T36 拒绝。

### 不要求终止成员

以下类型虽然没有空值终点，但具有有限布局，因此合法：

```ts
type Loop = {
  next: Loop;
};

type State = {
  next: () => State;
};
```

类型合法不等于允许读取未初始化值。对象构造、确定赋值、TDZ 和属性初始化仍按 T26、T36、T54 检查；编译器不能为了构造 `Loop` 自动创建未初始化引用。

### 前向引用与互相递归

同一类型作用域中的类型声明允许前向引用，声明顺序不影响结果：

```ts
type Left = {
  right: Right | null;
};

type Right = {
  left: Left | null;
};
```

T57 必须先为作用域内全部类型声明建立符号，再解析成员引用和构造递归图。该规则不放宽值声明的 TDZ 和确定赋值要求。

纯类型导入可以按 T55 形成跨模块递归。模块运行时初始化循环仍由 T55 处理，不能因类型循环合法而自动视为安全。

## 非法透明递归

未经过引用间接层便返回自身的循环没有有限值表示，必须在声明图完成后编译报错：

```ts
type A = A;

type B = C;
type C = B;

type Value = Value | i32;
```

联合、交叉、空值和另一个透明别名不能使该循环合法。诊断必须显示最短可理解的循环路径，并指出哪条边缺少运行时间接层；不得通过以下方式接受：

- 隐藏装箱或隐式指针。
- 将循环归一为 `never`、`unknown` 或其他宽窄类型。
- 只因达到递归深度上限便假定相等或合法。
- 把检查推迟到运行时。

## 泛型递归与惰性实例化

### 稳定与有限交替

保持相同实参或在有限实参集合中形成回边的递归，可以直接建立有限具体实例图：

```ts
type Tree<T> = {
  value: T;
  children: Tree<T>[];
};

type Pair<A, B> = {
  next: Pair<B, A> | null;
};
```

`Pair<i32, string>` 只在 `Pair<i32, string>` 与 `Pair<string, i32>` 之间交替，第二次回到已有规范实例时结束展开。

### 改变实参的递归

不断改变实参的递归声明和有限使用合法：

```ts
type Growing<T> = {
  next: Growing<T[]> | null;
};

function inspect(value: Growing<i32>) {
  const first = value.next; // Growing<i32[]> | null
  if (first !== null) {
    const second = first.next; // Growing<i32[][]> | null
  }
}
```

checker 以“类型构造器 + 规范实参”缓存按需实例。引用字段布局不要求展开其目标实例；根实例的布局和 GC 描述可以在目标类型尚未具体展开时完成。

### 无限需求

当一次类型运算或代码生成需求形成无界的新实例链时，编译器必须在触发位置报错：

```ts
function walk<T>(value: Growing<T>) {
  if (value.next !== null) {
    walk(value.next);
    // walk<T> -> walk<T[]> -> walk<T[][]> -> ...
  }
}
```

该错误表示当前原生专门化方案无法形成有限代码，不表示 `Growing<T>` 声明本身非法。编译器必须报告函数或类型运算名称、初始实参和重复增长步骤。

T37 负责函数单态化、表示相同实例的安全共享和代码体积预算。没有静态证明时，不得通过运行时类型参数表、统一装箱、动态派发或擦除泛型函数来接受无限专门化。

## 类型身份与相等

递归结构使用带回边的规范图判断身份，不能无限展开成员。透明别名名称不参与身份，因此独立声明但结构相同的递归精确对象具有相同语义类型：

```ts
type NodeA = {
  value: i32;
  next: NodeA | null;
};

type NodeB = {
  value: i32;
  next: NodeB | null;
};
```

`NodeA` 与 `NodeB` 相等。递归接口按 T29 的规范契约身份应用同一规则。以下既有类别边界保持不变：

| 类型类别           | 递归比较规则                                   |
| ------------------ | ---------------------------------------------- |
| 精确对象与精确对象 | 比较成员、权限、可选性和对应回边。             |
| 接口与接口         | 比较展平后的结构契约和对应回边。               |
| 精确对象与接口     | 不相等；只能按 T29 建立结构实现关系。          |
| 类实例             | 保持类的名义身份，不因递归字段结构相同而相等。 |
| 品牌类型           | 保留品牌身份，不因递归底层结构相同而丢失标签。 |

### 图比较算法

结构相等按有限规范图的递归对应关系判断。回边只能关闭当前已建立的节点对，不能掩盖其他有限路径上的成员、权限、键或类型类别差异。节点对缓存和循环检测算法由 [`5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md) 定义。

## 赋值兼容与子类型

递归类型不创建新的兼容规则。checker 按 T03 已定义的读取、写入、`readonly`、函数方差、接口打包和类继承规则计算递归固定点。

再次遇到同一正在比较的有向节点对时，只关闭该递归分支；其他成员仍须完整检查。可写递归成员不能因为回边而从不变放宽为协变，接口转换也仍须生成 T29 定义的静态 witness。关系缓存键由 [`5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md) 统一定义。

兼容检查只遍历静态类型图，不扫描运行时对象图，不检查实际链表长度，也不因值可能形成循环而增加运行时验证。

## 推导边界

### 递归值

checker 不从后续写入反向修改已经完成的初始化推导：

```ts
type Node = {
  value: i32;
  next: Node | null;
};

const inferred = {
  value: 1,
  next: null,
};

inferred.next = inferred; // 编译错误：next 已推导为 null

const node: Node = {
  value: 1,
  next: null,
};

node.next = node; // 合法
```

递归值入口需要显式类型注解或明确的上下文类型。这样可以避免跨语句固定点推导，也使对象布局在初始化前确定。

### 递归函数组

直接或互相递归的函数形成调用强连通分量。该分量必须具有足够的显式返回类型或上下文函数类型，使每条递归返回依赖都能得到唯一类型；不要求每个内部函数重复标注，但不能通过无限固定点迭代猜测返回类型。

```ts
function even(value: i32): boolean {
  return value === 0 ? true : odd(value - 1);
}

function odd(value: i32): boolean {
  return value === 0 ? false : even(value - 1);
}
```

缺少足够注解时产生递归返回类型推导错误，不退化为 `any`、`unknown` 或隐式 `void`。函数签名与调用 SCC 的完整规则由 T32 定义。

## 递归类型运算

`keyof`、索引访问、映射类型、条件类型和 `infer` 由 [T40](./26-typeOperators.md)、[T41](./27-advancedTypes.md) 定义。它们处理递归输入时必须复用 T31 的符号图：

| 运算情况                                | 结果                                                 |
| --------------------------------------- | ---------------------------------------------------- |
| `keyof Node`、`Node["next"]` 等有限查询 | 正常计算。                                           |
| 运算再次遇到相同操作、类型和规范实参    | 建立结果回边，不重复展开。                           |
| `DeepReadonly<Node>` 一类稳定递归映射   | 对应类型工具受支持时生成递归结果，不因固定深度误报。 |
| 每轮产生新实参或新结构且没有有限闭包    | 在触发运算处报告无限类型计算。                       |

编译器不能使用任意较小的递归深度上限代替回边检测，也不能在增长链上静默返回部分结果。运算缓存和确定性预算由 [`5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md) 定义。

## 表示约束

递归类型不得创建专用运行时包装、隐藏 `Box`、额外 tag 或动态泛型参数表。每个节点复用所属类型构造的表示，布局在引用间接层停止展开；相同机器布局的共享不能改变语义类型身份。有限布局、LLVM 映射和零成本要求见 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)。

## 循环回收约束

运行时允许对象直接或间接指回自身：

```ts
type GraphNode = {
  edges: GraphNode[];
};

const left: GraphNode = { edges: [] };
const right: GraphNode = { edges: [left] };
left.edges.push(right);
```

当 `left` 和 `right` 都不可达时，即使两者互相引用也必须被回收。递归声明本身不得增加对象字段、引用计数、父指针或运行时类型标签。扫描描述、写屏障和循环回收算法由 [`1-gcTypeDescriptors.md`](../../runtime/gc/1-gcTypeDescriptors.md) 定义。

## 跨模块约束

导出的递归类型必须保留规范强连通分量和泛型替换边，使不同模块得到稳定且可验证的类型身份。指纹编码、版本校验和描述符链接由 [`1-typeAbi.md`](../../compiler/abi/1-typeAbi.md) 定义；模块解析、导出图和运行时初始化顺序仍由 T55 定义。

## 复杂度与性能边界

编译器必须通过有限图、关系缓存和按需实例化处理普通递归程序；不能依赖机器速度、宿主调用栈或任意较小的递归深度阈值。确定性预算及增长诊断见 [`5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md)。

递归能力对未使用代码和普通对象保持零额外运行时成本。布局与 lowering 约束分别见 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md) 和 [`1-loweringStrategies.md`](../../compiler/optimizer/1-loweringStrategies.md)，性能诊断与基准范围见 [`1-performanceDiagnostics.md`](../../toolchain/1-performanceDiagnostics.md)。

## 与 TypeScript 的兼容性

Nxts 保持 TypeScript 的递归类型别名、递归接口、前向类型引用、结构化递归兼容和严格模式推导边界。通过 Nxts checker 的递归类型源码，在提供 Nxts 标准类型声明后也必须通过 TypeScript 类型检查。

主要差异如下：

| 场景               | TypeScript                                      | Nxts                                                         |
| ------------------ | ----------------------------------------------- | ------------------------------------------------------------ |
| 引用递归           | 对象、数组、函数和接口递归通常合法。            | 保持相同源码能力，并要求运行时布局路径经过已知引用间接层。   |
| 透明循环           | 直接别名循环通常报错。                          | 明确拒绝所有缺少运行时间接层的循环。                         |
| 增长型泛型声明     | 可以惰性接受，在具体类型运算时才可能报告过深。  | 同样允许声明和有限使用，并以符号替换边表示。                 |
| 无界泛型函数专门化 | 类型被擦除，JavaScript 不需要生成每个原生实例。 | 无法形成有限原生代码时编译报错，不自动采用动态泛型表示。     |
| 复杂度失败         | 可能报告类型实例化过深。                        | 优先报告具体循环或增长路径；资源预算耗尽使用独立确定性诊断。 |
| 运行时表示         | 类型擦除，由 JavaScript 对象和 GC 承载。        | 使用静态对象布局、有限 GC 描述和原生专门化代码。             |

这些差异只缩小 Nxts 接受范围，不新增 TypeScript 无法解析的递归语法，也不为相同源码提供更宽松的静态类型结果。Nxts 的接受范围仍是 TypeScript strict 的静态子集。

## 诊断与测试

至少覆盖以下接受场景：

| 场景                                   | 预期                                         |
| -------------------------------------- | -------------------------------------------- |
| 对象、接口、数组、元组、字典和函数递归 | 建立有限符号图，不无限展开。                 |
| 无 `null` 终点的引用递归               | 类型合法；构造仍执行初始化检查。             |
| 前向与互相类型引用                     | 与声明顺序无关，规范身份稳定。               |
| 同结构不同名递归对象或接口             | 得到相同结构身份；精确对象与接口类别仍不同。 |
| 递归 readonly 和可写成员               | 按 T03、T27 的方向规则比较，不因回边放宽。   |
| 稳定泛型和有限实参交替                 | 复用已有实例回边。                           |
| 增长型泛型声明和有限成员访问           | 按需创建所需实例并正常编译。                 |
| 稳定递归类型运算                       | 复用结果回边，不因固定深度上限失败。         |
| 跨模块递归类型                         | 指纹不受声明、文件或遍历顺序影响。           |

至少覆盖以下拒绝与资源边界：

| 场景                           | 预期                                           |
| ------------------------------ | ---------------------------------------------- |
| 直接、互相、联合或交叉透明循环 | 编译错误并显示缺少引用间接层的循环路径。       |
| 从后续写入反推递归对象类型     | 编译错误，提示在递归入口添加类型注解。         |
| 递归函数组缺少足够返回类型信息 | 编译错误，不推导为动态类型。                   |
| 无限类型运算                   | 在触发运算处报告操作和增长链，不返回部分结果。 |
| 无限函数专门化                 | 在递归调用处报告函数和类型实参增长链。         |
| 复杂度预算耗尽                 | 报告确定性资源诊断，不假定类型关系结果。       |
| 依赖隐藏装箱才能形成有限布局   | 编译错误，不改变源码声明的表示。               |

运行时表示、循环回收和性能基准分别由 T45、T46 与 [`1-performanceDiagnostics.md`](../../toolchain/1-performanceDiagnostics.md) 验证。
