## 转换原则

- 隐式转换必须无失败、无隐藏堆分配、无对象复制，并保持值语义。
- `expression as Type` 不是类型系统逃生口。
- 改变表示、复制对象、损失精度或执行运行时检查必须使用对应能力的显式操作。
- 转换不能绕过写权限、对象布局、空值检查或确定赋值。
- 不提供任意内存重解释；未来 FFI 使用独立安全边界。

## 隐式转换

以下关系可以在赋值、参数和返回位置隐式成立：

- 透明类型别名展开。
- 精确结构相同且属性权限兼容的对象关系。
- 可变对象到对应只读视图。
- 派生类到静态基类。
- 对象或类到已满足的接口。
- 接口到已证明的上位接口。
- 联合规范授权的成员注入与表示重组。
- 其他规范明确标记为无损、无失败且无隐藏成本的转换。

普通视图不产生运行时代码。接口和联合可以生成固定大小的 `InterfacePack`、`InterfaceRepack`、`UnionInject` 或 `UnionRepack`，但不能扫描成员、复制对象、堆分配或失败。

不同数值表示、不同精确对象形状和需要运行时判断的关系不属于隐式转换。

## T43 类型断言

Nxts 不支持 TypeScript 的普通表达式断言。parser 可以识别语法并产生准确诊断，checker 只接受：

| 形式                        | 规则                                       |
| --------------------------- | ------------------------------------------ |
| `literal as const`          | T40 的 const assertion，不是普通断言。     |
| `value as Brand<Base, Tag>` | T28 的零成本品牌建立。                     |
| `value as OtherType`        | 编译错误，包括本可通过赋值表达的安全视图。 |
| `<Type>value`               | 编译错误。                                 |
| 链式或双重断言              | 编译错误。                                 |

安全视图使用赋值、参数、返回或显式类型注解表达：

```ts
const readonlyView: ReadonlyPoint = point;
const interfaceView: PointInterface = point;
```

普通 `as` 不能选择泛型推导结果、隐藏额外字段、提升写权限或恢复接口底层精确对象。

### 品牌建立

```ts
type UserId = Brand<i64, "UserId">;

function brand(rawI64: i64) {
  const userId = rawI64 as UserId;
  const direct = 100 as UserId;
  return userId;
}
```

checker 仅在以下条件全部满足时接受：

1. 目标规范化为标准库身份确定的 `Brand<Base, Tag>`。
2. 源值兼容于 `Base`，并与 `Base` 表示完全相同。
3. 源值不是另一个不同品牌。
4. 操作不执行数值转换、对象裁剪、写权限提升、运行时检查、包装或分配。

直接字面量可以使用 `Base` 作为上下文类型，在产生值前选择底层表示：

```ts
const direct = 100 as UserId; // 直接采用 i64

const inferred = 100; // i32
const invalid = inferred as UserId; // 编译错误
```

不同品牌必须先显式绑定到底层类型，再建立目标品牌：

```ts
const raw: i64 = userId;
const orderId = raw as OrderId;
```

品牌建立不生成值级转换节点。品牌身份只保留在语义类型中。

### 禁止绕过

以下写法均编译错误：

```ts
value as unknown as Target;
value as const as UserId;
userId as OrderId;
readonlyPoint as MutablePoint;
numberValue as i32;
animal as Dog;
```

联合使用 `typeof`、严格相等、空值判断或判别字段收窄；基类到派生类使用 `instanceof`。接口和动态值使用受信检查入口。

当前不提供用户可用的 `unsafe`、原生指针或任意位重解释。compiler、runtime 与标准库私有 ABI 不能通过源码访问。

## T44 表示转换分类

改变表示的操作不使用 `as`，也不提供跨任意类型的 `convert<T>` 或 `cast<T>`。每类值定义自己的显式操作、失败模型和成本。

| 类别           | 静态入口与结果                                                               |
| -------------- | ---------------------------------------------------------------------------- |
| 数值转换       | 使用 T12/T49 数值 API；普通转换得到目标类型，精确转换得到 `Target \| null`。 |
| 对象形状转换   | 使用目标对象构造表达式，结果是新的目标精确对象类型。                         |
| 动态打包       | 使用标准库受信入口，结果为 `unknown`。                                       |
| 运行时类型检查 | 使用标准库布尔类型谓词，在成功分支恢复目标类型。                             |
| 外部数据验证   | 使用 schema 或类型化解析 API，成功后构造目标类型。                           |

字面量采用上下文类型属于字面量检查，不是表示转换。字符串解析数值也不是数值表示转换。

## 对象形状转换

对象形状改变必须显式构造目标对象：

```ts
const point: Point = {
  x: labeled.x,
  y: labeled.y,
};
```

普通赋值、`as` 和通用 `toObject<T>` 不能裁剪或重建对象。checker 按普通对象字面量规则检查每个字段和结果精确形状。

## 动态打包

普通静态值不能隐式进入 `unknown`，必须使用 [`../../stdlib/7-dynamic.md`](../../stdlib/7-dynamic.md) 的显式受信入口。

品牌值按底层类型进入动态边界，已经擦除的品牌身份不能从 `unknown` 恢复。普通静态值不为未来动态打包预留标签、payload 或 GC 状态。

## 受信运行时类型检查

检查入口的合法来源为：

| 来源      | 规则                                                       |
| --------- | ---------------------------------------------------------- |
| `unknown` | 查询可信动态类型身份。                                     |
| 接口值    | 利用已保存的具体类型信息检查更具体接口、类或相同精确对象。 |

其他普通静态值不使用该入口：已知关系用赋值，基础联合用内建收窄，基类到派生类用 `instanceof`。

### 合法目标

目标必须在调用点规范化为闭合、具体且可运行时检查的类型：

| 目标类别                      | 成功类型条件                                                                                                         |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 基础类型、`null`、`undefined` | 动态标签精确匹配，不执行数值转换。                                                                                   |
| 字面量                        | 基础标签匹配且载荷严格相等。                                                                                         |
| 精确对象                      | 完整对象描述相同；只允许既有 mutable 到 readonly 视图。                                                              |
| 类                            | 实际类相同或是目标派生类。                                                                                           |
| 接口                          | 具体类型具有预生成目标 witness。                                                                                     |
| 数组、元组、字典              | 容器描述和既有 readonly 关系匹配，不扫描元素。                                                                       |
| 函数                          | 完整规范函数签名指纹相同；重载使用完整有序公开重载集，不含私有实现签名，也不在运行时执行方差、泛型推导或适配器生成。 |
| 枚举                          | 可信动态身份是该枚举；底层值相同不足以匹配。                                                                         |
| 联合                          | 每个成员可检查，值至少匹配一个成员；使用标签或预计算关系，不递归扫描容器内容。                                       |
| `symbol`                      | 动态载荷是普通或唯一 symbol。                                                                                        |

以下目标编译错误：

| 目标                     | 原因                                 |
| ------------------------ | ------------------------------------ |
| `unknown`                | 检查恒真，不能提供更具体类型。       |
| `never`、`void`、`any`   | 不对应可恢复运行时值，或语言不支持。 |
| `Brand<Base, Tag>`       | 品牌运行时擦除。                     |
| 具体 `unique symbol`     | 不能从宽 symbol 恢复声明身份。       |
| 未闭合泛型或开放类型配方 | 需要隐藏运行时类型实参或类型级求值。 |

泛型函数中的自由 `T` 不能作为检查目标；调用点必须已有闭合具体类型。

品牌值从动态边界恢复时，先检查底层类型并执行业务验证，再建立品牌：

```ts
if (isType<i64>(input) && isValidUserId(input)) {
  const userId = input as UserId;
}
```

### 控制流证明

checker 把成功证明与已提取 payload 或 witness 绑定到控制流：

```ts
if (!isType<User>(input)) return;
input.name; // User

const valid = isType<User>(input);
if (valid) {
  input.name; // User
}
```

直接条件、否定后提前退出和未改写的局部 `const` 布尔别名可以传播证明。可变布尔、对象属性和跨函数返回值不携带证明；源绑定重新赋值或可能被闭包改写后，旧证明失效。

失败分支保留原来源类型，不从开放 `unknown` 猜测补集。目标包含空值时，成功分支保留完整目标联合。

## 运行时收窄边界

判别联合、受信类型检查和 `instanceof` 都必须产生可证明的目标类型。未经检查的 `as` 不能替代收窄。

JSON、网络数据和其他外部结构没有 Nxts 具体对象身份。字段同名不足以通过动态类型检查；必须使用 schema 或类型化解析构造目标值。

## Checker 职责

checker 必须：

1. 区分 `NoOp`、有界隐式打包、表示转换、对象构造和受信检查。
2. 只接受两个已授权 `as` 形式。
3. 验证显式入口的来源、目标、失败类型和闭合性。
4. 把成功载荷、witness 与控制流证明关联。
5. 在 Checked HIR 中保留具体转换类别，不能只留下表面调用或布尔结果。

## 与 TypeScript 的差异

| 场景                    | TypeScript strict  | Nxts                                |
| ----------------------- | ------------------ | ----------------------------------- |
| `literal as const`      | 支持               | 支持，归 T40。                      |
| `value as Brand`        | 常用于幻象品牌     | 仅底层兼容且同表示时支持。          |
| 普通 `value as Type`    | 重叠足够时通常允许 | 编译错误。                          |
| `value as unknown as T` | 可绕过重叠检查     | 编译错误。                          |
| 普通值进入 `unknown`    | 隐式允许           | 要求显式动态打包。                  |
| 自定义 `value is T`     | 信任用户声明       | 不支持，只信任内建或 checker 摘要。 |
| JSON `as T`             | 不执行验证         | 必须 schema 解码并构造。            |

标准库入口使用 TypeScript 可解析的普通函数与类型谓词声明。Nxts 只缩小 TypeScript strict 的接受范围。

## 诊断与类型测试

至少覆盖：

- `as const`、同表示品牌建立和直接字面量品牌。
- 普通、尖括号、链式和双重断言拒绝。
- 不同品牌、readonly 提权、数值转换与基类下转拒绝。
- 每种隐式视图及对应 IR 分类。
- 数值、对象、动态和外部数据转换入口分流。
- 每类合法及非法运行时检查目标。
- 重载函数、联合、枚举、容器、接口与类检查。
- 控制流别名传播、重新赋值和闭包失效。
- JSON 同形对象不能冒充可信精确对象。
