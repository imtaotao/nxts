## 核心类型模型

普通数组具有以下静态不变量：

| 不变量       | 要求                                       |
| ------------ | ------------------------------------------ |
| 元素类型固定 | 创建完成后不因写入改变元素类型或规范布局。 |
| 稠密         | 普通数组类型不表达空洞。                   |
| 可变长度     | 可变数组可以通过受支持操作改变长度。       |
| 引用身份     | 赋值、传参和返回不产生数组值复制。         |
| 静态方法解析 | 数组方法不依赖可修改原型链或动态属性。     |

数组不是普通动态对象或字典。禁止给数组添加自定义属性、覆盖内建方法、修改原型或删除元素。数组只能按 T30 形成只读数值索引视图，不能形成可写数字字典。

## 类型语法与身份

以下写法规范化为相同类型：

```ts
i32[];
Array<i32>;

readonly i32[];
ReadonlyArray<i32>;
```

规则如下：

- `T[]` 与 `Array<T>` 是同一个规范类型。
- `readonly T[]` 与 `ReadonlyArray<T>` 是同一个只读数组视图类型。
- 裸 `Array` 和裸 `ReadonlyArray` 编译错误，不使用 `any` 补全元素类型。
- `ReadonlyArray<T>` 只能作为类型，不能构造。
- 与 TypeScript 一致，`readonly Array<T>` 编译错误，应写 `ReadonlyArray<T>`。
- 类型别名不创建新的数组身份、包装或布局。

括号决定联合位于元素层还是数组层：

```ts
let mixed: (i32 | string)[];
let batch: i32[] | string[];
```

`mixed` 的每个元素使用固定联合布局；`batch` 在外层区分同构 `i32[]` 和同构 `string[]`。两者不是同一类型或 ABI。

## 数组字面量推导

无上下文数组字面量默认推导为数组，不默认推导为元组。可变数组会 widening 元素字面量：

```ts
const integers = [1, 2, 3];
// i32[]

const floats = [1.0, 2.5];
// f64[]

const nativeFloats = [1, 2.5];
// f64[]

const jsNumbers = [1, NaN];
// number[]
```

checker 按以下顺序确定元素类型：

1. 存在数组元素上下文时，先按上下文检查每个元素。
2. 全部为普通整数字面量时，按 T08 推导 `i32`。
3. 存在普通浮点字面量且其他数值字面量能直接采用 `f64` 上下文时，推导 `f64`。
4. 存在 `NaN`、无穷值、`-0` 或只能保持 JavaScript Number 语义的候选时，推导 `number`。
5. 其他候选使用 T04 的零成本公共类型；不存在单一公共类型但成员均可存储时，构造规范联合类型。

混合数组可以自动推导固定联合布局：

```ts
const mixed = [1, "x"];
// (i32 | string)[]

const numeric = [nativeI32, nativeF64];
// (i32 | f64)[]，不执行隐式数值转换
```

推导不得使用 `any` 或 `unknown` 兜底，也不得在创建后根据后续写入重新计算元素类型。联合规范化超过类型工作预算时产生确定性诊断，要求提供目标元素类型或简化表达式。

空数组没有元素候选。无上下文空数组编译错误；显式上下文合法：

```ts
const invalid = []; // 编译错误
const values: i32[] = [];
```

数组空位语法编译错误：

```ts
const sparse = [1, , 3]; // 编译错误
```

## 元素类型与写入

元素类型在数组创建时确定，并决定全部写入检查和规范元素布局：

```ts
const values = [1, 2, 3]; // i32[]
values.push(4); // 合法
values.push("4"); // 编译错误
```

混合值需要数组元素联合：

```ts
const values: (i32 | string)[] = [1, "x"];
values.push(2);
values.push("y");
```

对数组联合执行写入时，写入值必须被每个可能成员以相同、无失败且无隐藏动态成本的表示接受。常见异构数组联合必须先收窄：

```ts
const appendUnknownBatch = (batch: i32[] | string[]) => {
  batch.push(1); // 编译错误
};
```

数组标准库的 `isArrayOf<T>` 可以检查精确元素布局并收窄数组联合：

```ts
import { isArrayOf } from "std/array";

const appendI32 = (batch: i32[] | string[]) => {
  if (isArrayOf<i32>(batch)) {
    batch.push(1);
  }
};
```

该检查对数组联合降低为外层 tag 比较，对抽象数组降低为规范类型描述符比较，不扫描元素、不分配内存。接口结构兼容或需要逐元素转换的布局不视为精确匹配。

## 长度与索引类型

`array.length` 的静态类型为 `i32`，有效范围为 `0..2^31-1`。只读数组不能写入 `length`。

数组索引类型为 `i32`。静态数值字符串字面量可以规范化为等价索引；宽动态字符串不能索引数组：

```ts
values[0]; // 合法
values["0"]; // 等价于 values[0]
values[key]; // key: string，编译错误
```

任意未证明索引的读取类型为 `T | undefined`：

```ts
const value = values[index]; // T | undefined
```

控制流证明 `0 <= index < length` 时，读取收窄为 `T`：

```ts
for (let index = 0; index < values.length; index++) {
  const value = values[index]; // T
}
```

数组结构缩短、无法证明的索引运算或可能通过别名缩短数组的调用会使该事实失效。仅增长数组不会让既有有效索引失效，但可能阻止长度与缓冲区缓存。

数值参数不执行 JavaScript 的隐式 `ToIntegerOrInfinity`。索引、起止位置、删除数量和 `flat` 深度使用 `i32`；`number`、`i64` 或平台整数需要显式转换。

## 只读数组

可变数组可以零复制形成相同元素布局的只读视图：

```ts
const mutable: i32[] = [1, 2];
const view: readonly i32[] = mutable;
```

`readonly` 是浅层静态写权限，不冻结底层数组。其他可变别名的修改对只读视图可见。

| 转换                           | 结果                                       |
| ------------------------------ | ------------------------------------------ |
| `T[] -> readonly T[]`          | 零成本允许。                               |
| `readonly S[] -> readonly T[]` | 仅当 `S -> T` 为无操作且元素机器布局相同。 |
| `readonly T[] -> T[]`          | 拒绝。                                     |
| `S[] -> T[]`                   | 可变数组不变；除规范类型相同外拒绝。       |

需要逐元素接口打包、联合注入、数值转换、装箱或分配时，不能形成隐式只读视图；程序必须使用显式数组转换创建目标数组。

只读数组可以使用查询、遍历、转换和复制方法。产生新数组的方法返回新的可变数组。禁止索引写入、`length=` 和所有原地修改方法。

Nxts 不支持 `Object.freeze`、`Object.seal`、`Object.preventExtensions` 及其状态查询 API。普通数组不保存动态冻结、密封或可扩展状态。

## 标准库方法的类型基础

数组方法的存在性、完整签名和方法级结果规则只由[数组标准库](../../stdlib/2-array.md)定义。本规范向这些声明提供以下静态基础：

- 元素类型 `T` 在方法调用期间保持同一规范类型，不因回调结果或写入扩大。
- 回调索引使用 `i32`，回调中的数组参数保留原接收者的 mutable / readonly 权限。
- 新数组结果必须得到闭合的具体元素类型，不能使用 `any`、`unknown` 或运行时类型表兜底。
- T06 证明的可信谓词摘要可以被标准库声明消费，但不能把现有数组重解释为不同物理元素布局。

## 类型收窄

绑定到标准库身份的 `Array.isArray(value)` 是 checker 受信类型守卫；公开 API 契约由[数组标准库](../../stdlib/2-array.md)定义：

| 输入             | 真分支结果                          |
| ---------------- | ----------------------------------- |
| 数组联合         | 保留其中的数组成员。                |
| `unknown`        | `readonly unknown[]` 存在类型视图。 |
| 元组             | 保留对应元组类型，结果恒为 `true`。 |
| 数字索引普通对象 | 不视为数组。                        |

只读能力必须保留。`Array.isArray(unknown)` 只证明值是某种 Nxts 数组，不证明具体元素布局，因此结果不可写，读取类型为 `unknown`。需要写入时必须再通过 `isArrayOf<T>` 证明精确布局。

普通 `boolean` 函数可以由 checker 自动证明并生成可信谓词摘要：

```ts
function isString(value: i32 | string) {
  return typeof value === "string";
}

values.filter(isString); // string[]
```

用户不能手写 `value is T` 声明。checker 只能使用自身证明出的真分支和互补分支事实，跨模块只导出编译器生成的摘要。

`filter` 可以创建物理元素布局更窄的新数组；`find` 返回窄类型与 `undefined`。`every` 为真只能建立当前元素读取事实，不能把 `(A | B)[]` 当成物理布局不同的 `A[]` 传递。数组写入或未知副作用调用会使该事实失效。

## 解构、递归与多维数组

普通数组解构的每个固定位置类型为 `T | undefined`；默认值可以消除 `undefined`：

```ts
const [first, second = fallback] = values;
// first: T | undefined，second: T
```

解构空位只跳过位置，不创建数组空洞。`...rest` 的类型为 `T[]`。元组的精确位置规则由 [`T35`](./22-tupleTypes.md) 定义。

数组是 T31 允许的递归间接层：

```ts
type Nested = i32 | Nested[];
```

`T[][]` 是外层数组保存内层数组引用，不是连续二维矩阵。每一行可以具有不同长度。

## Checker 职责

- 规范化 `T[]` / `Array<T>` 和只读写法。
- 推导固定元素类型、公共类型和规范联合。
- 检查索引、长度、可变性、方法签名和数组联合写入。
- 跟踪边界事实、元素内容事实、别名副作用和可信谓词摘要。
- 拒绝空洞、动态属性、可写字典视图、数组子类和动态冻结。

Typed IR 必须保留已解析的元素类型、只读能力、联合元素类型和可能失败边界，不能在后续阶段重新猜测数组类型。

## 与 TypeScript 的类型差异

| 主题         | TypeScript               | Nxts                              |
| ------------ | ------------------------ | --------------------------------- |
| 元素类型     | JavaScript 动态值承载    | 创建时固定规范元素类型。          |
| 空洞         | 类型系统允许部分稀疏写法 | 普通数组类型不表达空洞。          |
| 越界读取     | 通常仍推导为 `T`         | 未证明安全时为 `T \| undefined`。 |
| 索引类型     | `number`                 | `i32`，其他数值显式转换。         |
| mutable 方差 | 允许部分不安全协变       | 可变数组不变。                    |
| readonly     | 结构化静态只读           | 仅允许相同机器布局的零复制视图。  |
| 自定义属性   | 可以通过扩展类型表达     | 普通数组拒绝动态属性。            |

这些差异缩小 TypeScript strict 的接受范围，不引入 TypeScript 无法解析的数组类型语法。

## 诊断与测试

| 场景                          | 预期                            |
| ----------------------------- | ------------------------------- |
| `[1, 2, 3]`                   | `i32[]`。                       |
| `[1, 2.5]`                    | `f64[]`。                       |
| `[1, "x"]`                    | `(i32 \| string)[]`。           |
| 无上下文 `[]`                 | 编译错误。                      |
| `[1, , 3]`                    | 编译错误。                      |
| 未证明的 `array[index]`       | `T \| undefined`。              |
| 已证明循环内 `array[index]`   | `T`。                           |
| mutable 到 readonly           | 零复制允许。                    |
| readonly 到 mutable           | 编译错误。                      |
| `i32[] \| string[]` 写入      | 未收窄时编译错误。              |
| `isArrayOf<i32>(batch)`       | O(1) 收窄，无元素扫描。         |
| `Array.isArray(unknownValue)` | 只读未知元素数组视图。          |
| 不可达自引用数组              | 类型合法；回收行为由 T46 定义。 |
