# 交叉类型

## 目标与边界

定义交叉类型的支持范围、身份、归一化、对象形状组合、联合分配和泛型实例化，使 checker 能在已有下位关系中表达最大公共下界。

类型相等见 [`2-typeIdentity.md`](./2-typeIdentity.md)，赋值兼容见 [`3-typeCompatibility.md`](./3-typeCompatibility.md)，类型格见 [`4-typeLattice.md`](./4-typeLattice.md)，联合类型见 [`13-unionTypes.md`](./13-unionTypes.md)。交叉消解后的 IR 与表示契约见 [`../../compiler/ir/1-irContracts.md`](../../compiler/ir/1-irContracts.md) 和 [`../../compiler/representation/1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)。

## 核心原则

- 一般交叉类型表示多个静态约束同时成立，不表示运行时合并操作。
- checker 必须尽早把普通交叉规范化为具体基础类型、字面量、精确对象、接口契约、联合、类、容器或 `never`。
- 普通运行时值进入 Typed IR 前不能保留未解析的交叉类型。
- 交叉规范化不得生成 tag、包装、对象复制、字段裁剪、动态属性表或运行时类型检查。
- 普通对象的 `&` 是精确形状组合特例；它创建新的规范对象形状，但不建立到组成对象形状的隐式投影。
- 联合分配和泛型实例化必须受确定的编译期复杂度预算约束，不能使用动态类型或 widening 兜底。

## 语法与支持范围

交叉类型使用 TypeScript 的 `&` 语法：

```ts
type Ready = string & "ready";
type Entity = { id: i32 } & { name: string };
```

各类型类别按以下范围处理：

| 类型类别             | 当前规则                                                             |
| -------------------- | -------------------------------------------------------------------- |
| 基础类型与字面量     | 规范化为更窄成员或 `never`。                                         |
| 普通精确对象         | 合并为新的精确对象形状。                                             |
| 接口契约             | 纯接口交叉合并为新的结构契约；混入精确对象时作为静态约束检查。       |
| 有限联合             | 在复杂度预算内应用顶层分配律并规范化。                               |
| 类实例               | 存在静态继承关系时保留派生类；没有继承关系的类归一为 `never`。       |
| 泛型参数             | checker 可以暂存符号交叉；实例化后必须得到具体类型。                 |
| 幻象品牌             | 只允许 T28 的标准 `Brand<T, Tag>` 特例；静态保留身份，运行时擦除。   |
| 数组、元组、泛型实例 | 仅按相等或所属能力已经定义的下位关系归一化，不自动合并内部类型参数。 |
| 函数与构造签名       | 只处理相等或已有普通函数下位关系；不支持一般重载式函数交叉。         |
| `never`              | 合法底类型，参与规范化。                                             |
| `any`                | 永久不支持。                                                         |
| `unknown`            | 只允许重复归一或与 `never` 归一；不能作为普通静态顶层参与交叉。      |
| `void`、`bigint`     | 不是当前合法普通交叉成员。                                           |

一般函数交叉不是 `never`，而是当前不支持的类型构造：

```ts
type Parser = ((value: string) => string) & ((value: i32) => i32); // 编译错误：使用 T33 的明确重载能力
```

不同签名可能具有不同参数布局和调用 ABI。Nxts 不为函数交叉生成隐藏 thunk、入口表或动态签名分派；函数重载由 T33 独立定义，并要求调用点静态选择有效签名。

## 类型身份与一般归一化

除普通对象形状组合特例外，交叉类型的规范身份由无序约束集合及其规范化结果决定。checker 按以下顺序处理：

1. 验证成员类别是否合法。
2. 展开透明别名并展平嵌套交叉。
3. 按规范类型身份去重。
4. 遇到 `never` 时将结果归一为 `never`。
5. 如果一个成员是另一个成员的已定义下位类型，保留更窄成员。
6. 对已知互斥的原子类型归一为 `never`。
7. 对有限联合应用分配律并递归规范化。
8. 对纯接口交叉应用契约组合规则。
9. 对普通对象应用精确形状组合，并检查同时存在的接口约束。
10. 按稳定规范键排序并驻留仍需保留的符号交叉。

```text
A & A                 => A
(A & B) & C           => A & B & C
A & never             => never
string & "ready"      => "ready"
i32 & 1               => 1
Base & Derived        => Derived
string & i32          => never
unknown & unknown     => unknown
unknown & never       => never
```

`T & unknown` 在普通 `T` 下不是合法的顶层消去规则。普通值与 T17 的动态值信封具有不同表示；程序必须先通过受信任运行时类型检查或 schema 解码得到具体静态类型，不能借交叉语法擦除动态表示边界。

交叉成员顺序和括号分组不影响规范身份。源码顺序只用于诊断展示，不能影响规范化结果、对象字段布局或跨模块 ABI。

## 幻象品牌特例

T28 的标准 `Brand<T, Tag>` 在 TypeScript 工具侧可以声明为底层类型与 `unique symbol` 幻象属性的交叉。Nxts checker 在确认该标准库声明身份后，将它解析为专用静态 `BrandType(T, Tag)`，不进入普通对象交叉归一化：

```ts
type UserId = Brand<i64, "UserId">;
```

该特例不允许用户声明任意 symbol 属性键，也不使 `i64 & { readonly marker: "UserId" }` 一类基础类型与对象交叉合法。品牌兼容、构造和擦除规则由 T28、T43 定义。

品牌进入 Typed IR 前完全擦除为 `T`，不产生属性、tag、包装、分配、动态检查或独立 ABI。它是零运行时成本的静态身份约束，不是对象形状组合。

## 接口契约组合

只包含接口契约的交叉生成一个新的规范接口契约，等价于使用多接口继承组合相同成员：

```ts
interface Named {
  name: string;
}

interface Entity {
  readonly id: i64;
}

type NamedEntity = Named & Entity;
```

`NamedEntity` 是同时保证 `name` 和 `id` 的接口契约，不是精确对象形状。成员合并、权限、可选性、方法冲突和 witness 槽位遵循 T29；冲突无法满足时归一为 `never` 或在需要显式重声明的位置产生诊断。

交叉中存在精确对象成员时，checker 先按下一节得到唯一精确对象形状，再验证该形状是否满足全部接口约束。接口约束不会向精确对象隐式添加字段：满足时结果为该精确对象形状，不满足时结果为 `never`。

```text
ExactPoint & PointInterface
  => ExactPoint    // ExactPoint 已满足契约

ExactName & AgedInterface
  => never         // ExactName 缺少必选 age
```

该规则不执行接口打包；只有结果值之后进入接口位置时，才由 T29 生成 `InterfacePack`。

## 普通对象形状组合

普通对象的交叉先合并属性约束，再产生一个新的精确对象形状：

```ts
type Named = {
  name: string;
};

type Aged = {
  age: i32;
};

type Person = Named & Aged;
```

`Person` 规范化为：

```ts
type Person = {
  age: i32;
  name: string;
};
```

规范属性顺序由对象类型和布局规范确定，不按 `&` 的源码顺序排列。`Named & Aged` 与 `Aged & Named` 必须得到同一语义类型、布局身份和 GC 描述。

该规则是显式对象形状组合，不是 T03 赋值类型格中的公共下界。合并结果不自动兼容任一组成对象，因此 checker 不能在控制流或泛型约束需要最大公共下界时，擅自通过合并不同属性集合来构造对象交叉；只有源码类型表达式或明确类型工具请求对象组合时才应用本节规则。

### 同名属性

同名属性的值类型递归计算交叉：

```ts
type Narrowed = { value: string } & { value: "ready" };

// { value: "ready" }
```

必选属性值归一化为 `never` 时，整个对象不可构造并归一化为 `never`：

```ts
type Invalid = { value: string } & { value: i32 };

// never
```

属性存在性和写权限采用更强约束：

- 必选与可选组合后为必选。
- 可写属性能够满足对应只读视图，因此可写与只读组合后保留可写要求。
- 属性值仍须按本规范递归计算交叉。
- 可选 `never` 属性表示该属性不能存在，不会使整个对象自动成为 `never`。

可选属性存在位、属性删除以及 `readonly` 别名写入的完整规则由 T26、T27 定义；这些规则不得为对象交叉引入动态字段表或隐藏对象重建。

### 赋值与构造

对象交叉先规范化为最终形状 `M`，随后只按 T03 的精确对象规则检查源值是否兼容 `M`：

```ts
const person: Person = {
  name: "Tom",
  age: 20,
};
```

两个已有对象值不会因为目标类型使用 `&` 而被隐式合并：

```ts
const mergeValues = (named: Named, aged: Aged) => {
  const invalid: Person = named; // 编译错误：缺少 age

  const person: Person = {
    ...named,
    ...aged,
  };
};
```

需要从已有值构造时，程序必须显式创建目标对象。对象 spread 的求值顺序、冲突覆盖和复制成本由 T52 定义：

```ts
const createPerson = (named: Named, aged: Aged) => {
  const person: Person = { ...named, ...aged };
  return person;
};
```

合并后的精确对象也不能隐式投影为组成形状：

```ts
const projectPerson = (person: Person) => {
  const namedView: Named = person; // 编译错误：不能隐式裁剪 age
};
```

需要 `Named` 时必须显式构造 `{ name: person.name }`。该边界保持对象枚举、对象身份、可变别名和固定布局语义，不生成隐藏复制或布局适配。

未来的 `Merge<A, B>` 可以为泛型计算、属性冲突策略和计算型对象组合提供明确类型工具，但普通对象组合不依赖该工具；`A & B` 已能创建新的精确对象形状。`Merge` 不能绕过 T03 的精确对象赋值规则。

## 与联合类型组合

顶层有限联合按集合分配律参与交叉：

```text
(A | B) & C => normalize((A & C) | (B & C))
A & (B | C) => normalize((A & B) | (A & C))
```

每个组合分别规范化，随后按 T21 删除 `never`、重复成员和被上位成员吸收的成员：

```text
(string | i32) & string
=> (string & string) | (i32 & string)
=> string | never
=> string
```

对象联合可以通过交叉形状组合为每个成员增加明确字段：

```ts
type Result = (
  | { kind: "text"; value: string }
  | { kind: "count"; value: i32 }
) & { id: i32 };
```

规范化结果是：

```ts
type Result =
  | { id: i32; kind: "text"; value: string }
  | { id: i32; kind: "count"; value: i32 };
```

分配律只作用于顶层交叉成员，不进入普通类型构造器：

```text
Array<A | B> & Array<C>
```

上式只能使用 T34、T37、T38 已经定义的数组或泛型下位关系，不能自动改写成元素类型的笛卡尔组合。

交叉展开本身只发生在 checker。如果最终结果是一般联合，运行时仅承担 T21 已定义的联合表示成本；交叉类型不增加第二层 tag 或包装。

## `never` 与不可构造结果

规范化得到 `never` 本身不是编译错误。`never` 是合法底类型，可以用于类型别名、泛型计算、联合过滤、控制流收窄和穷尽检查：

```ts
type Impossible = string & i32; // never
```

只有程序尝试构造、赋值或从外部数据边界提供该值时才报错：

```ts
const value: Impossible = 1; // 编译错误
```

函数返回 `never`、不可达路径和外部 `never` 契约继续遵循 T16。交叉类型不能用于伪造 `never` 值，也不能通过类型断言绕过不可构造性。

## 泛型与具体类型边界

泛型定义检查期间可以保留符号交叉：

```ts
function use<T, U>(value: T & U) {
  return value;
}
```

checker 优先根据实参、约束和上下文推导类型参数。实例化后先替换 `T`、`U`，再执行完整交叉规范化：

```text
T = string, U = "ready"                  => "ready"
T = string, U = i32                      => never
T = { name: string }, U = { age: i32 }   => { age: i32; name: string }
```

所有进入 Checked HIR 的值必须具有已规范化的具体类型。具体类型可以是成员有限的联合，不要求编译期知道当前成员；未解析的 `T & U` 不能离开 checker。

实例化后仍无法得到具体类型时编译错误，不能使用 `any`、`unknown`、泛型擦除或动态推导兜底。泛型单态化、实现共享和跨模块配方由 T37、T47 定义。

## 复杂度边界

交叉规范化使用确定预算。耗尽时必须报告触发操作，不能省略约束、扩大类型、动态化或把尚可满足的结果错误归为 `never`。

成员驻留、对象属性合并、联合笛卡尔积、泛型展开和递归回边预算由 [`../../compiler/frontend/5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md) 定义。

## 运行时表示与跨模块一致性

普通交叉在离开 checker 前完全消解，没有独立 tag、payload、对象头、GC 描述或调用 ABI。规范化结果使用对应具体类型的表示。

`A & B` 与 `B & A` 必须得到同一规范结果。跨模块只序列化该结果；导出的泛型配方可以保留符号交叉，但闭合实例仍须完成消解。详细记录见 T45、T47。

## 编译器职责

checker 识别标准品牌特例，验证成员类别，展平、去重、组合接口契约与对象形状，并执行有限联合分配。控制流分析只能复用已有下位关系，不能自动组合不同对象形状。

Checked HIR 不定义 `IntersectionInject`、交叉 tag 或动态对象合并节点；完整阶段契约见 [`../../compiler/ir/1-irContracts.md`](../../compiler/ir/1-irContracts.md)。

## 与 TypeScript 的兼容性

Nxts 保持 TypeScript 的 `&` 语法、无序身份、重复消除、字面量收窄、互斥类型归为 `never`、有限联合分配和对象属性组合。使用 Nxts 内建类型声明后，通过 Nxts checker 的交叉类型源码仍应通过 TypeScript 类型检查。

主要差异如下：

| 场景           | TypeScript                                  | Nxts                                                        |
| -------------- | ------------------------------------------- | ----------------------------------------------------------- |
| 对象交叉       | 合并属性，并通常可作为任一组成结构使用。    | 合并为新精确形状，但不能隐式投影为组成形状。                |
| 接口交叉       | 与对象结构交叉采用统一结构关系。            | 纯接口生成组合契约；精确对象参与时只验证该精确形状。        |
| 运行时对象     | 类型擦除，继续使用 JavaScript 动态对象。    | 编译期生成单一固定对象布局。                                |
| 函数交叉       | 可以表达重载式可调用类型。                  | 一般函数交叉不支持；明确重载由 T33 定义。                   |
| 数组和泛型实例 | 结构类型和高级类型规则可产生复杂交叉。      | 只使用对应能力明确建立的下位关系，不自动合并内部参数。      |
| `unknown`      | 普通类型与 `unknown` 的交叉归一为普通类型。 | `unknown` 是显式动态表示，不能作为普通顶层成员消去。        |
| `any`          | 可以吸收或改变交叉结果。                    | 永久不支持。                                                |
| 未解析符号交叉 | 类型擦除后不需要确定原生布局。              | 泛型实例化后必须得到具体、可布局类型。                      |
| 复杂度超限     | 使用实现内部启发式限制。                    | 明确报资源诊断，不 widening、不动态化、不错误归为 `never`。 |
| 幻象品牌       | 通常使用 `unique symbol` 属性交叉约定。     | 只接受标准 `Brand<T, Tag>` 特例，并擦除为底层表示。         |

对象投影、一般函数交叉和动态顶层规则的差异只收紧 Nxts 的接受范围，不增加 TypeScript 无法解析的语法。对象 `&` 的形状组合仍保持零运行时成本；需要组成对象形状时的显式重建是 T03 已有规则，不是交叉类型产生的额外转换。

## 依赖边界

| 相关能力      | T22 已确定内容                                   | 对应能力负责内容                                |
| ------------- | ------------------------------------------------ | ----------------------------------------------- |
| T03 对象兼容  | 合并形状不提供隐式组成对象投影。                 | 精确赋值、只读视图和类下位关系。                |
| T28 类型别名  | 标准 `Brand<T, Tag>` 不按普通交叉处理。          | 品牌身份、兼容、断言和运行时擦除。              |
| T29 接口      | 纯接口交叉生成组合契约，接口约束不扩展精确对象。 | 成员冲突、结构实现、witness 和接口运行时表示。  |
| T21 联合类型  | 顶层分配后得到规范联合，不增加第二层运行时表示。 | 联合成员归一化、tag、payload 和复杂度基础预算。 |
| T26–T27 对象  | 属性集合、值类型和权限按更强约束组合。           | 可选存在位、删除、别名写入和精确对象布局。      |
| T31 递归类型  | 交叉不能无限展开递归结构。                       | 合法递归、类型图、固定点和 GC 回边。            |
| T33 函数重载  | 一般函数交叉不作为重载入口。                     | 重载声明、解析、实现签名和调用 ABI。            |
| T37、T41 泛型 | 符号交叉实例化后必须具体化。                     | 推导、约束、类型工具、单态化和代码体积预算。    |
| T45–T47 表示  | 交叉自身无运行时表示，跨模块使用规范化结果。     | 精确布局、GC 描述、类型摘要和跨模块 ABI。       |
| T52 对象构造  | 已有对象组合为目标形状必须显式表达。             | spread、覆盖顺序、临时值、复制成本和异常行为。  |

## 诊断与测试

至少覆盖以下场景：

| 场景                     | 预期                                        |
| ------------------------ | ------------------------------------------- |
| 嵌套、重复和成员换序     | 得到相同规范类型身份。                      |
| 字面量与基础类型交叉     | 保留更窄字面量。                            |
| 互斥基础类型             | 归一化为 `never`，类型声明本身合法。        |
| 不同属性对象交叉         | 合并为新的精确对象形状。                    |
| 同名属性兼容收窄         | 属性类型使用规范交叉结果。                  |
| 必选属性冲突             | 整体归一化为 `never`。                      |
| 可选 `never` 属性        | 对象仍可构造，但该属性不能存在。            |
