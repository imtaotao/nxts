# 字符串类型

- 任务编号：T13
- 规范状态：已定稿
- 实现状态：未实现
- 最后更新：2026-07-28

## 目标与边界

本规范定义 `string` 的静态类型身份、成员、索引、比较、拼接分类和普通模板插值要求。UTF-16 值行为见 [`2-stringSemantics.md`](../semantics/2-stringSemantics.md)，物理表示见 [`1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)，公开转换 API 见 [`10-string.md`](../../stdlib/10-string.md)。

## 类型身份

`string` 是不可变基础值类型，不是具有用户可观察身份的对象。字符串字面量类型零成本兼容到 `string`；除本规范明确开放的拼接格式化外，`string` 与数值、布尔、对象、`null` 或 `undefined` 不存在一般隐式转换。

变量可以重新绑定到新字符串，但字符串内容、`length` 和索引位置只读：

```ts
let text = 'abc';
text = 'def';
text.length = 1; // 编译错误
text[0] = 'x'; // 编译错误
```

不支持基础值装箱类型或 `new String(value)`。

## 长度与索引

`string.length` 的静态类型为 `i32`。索引只接受 `i32`；`number`、其他定宽整数和平台整数必须通过 T12 显式转换。

```ts
function read(text: string, index: i32) {
  const char = text[index];
  // string | undefined
}
```

普通动态索引结果始终为 `string | undefined`。当前不根据数值范围关系把读取结果自动收窄为 `string`；调用方使用空值检查收窄。编译期已知索引可以折叠为字符串字面量或 `undefined`。

## 比较

字符串只与字符串或字符串字面量执行以下比较：

| 运算符               | 静态结果  |
| -------------------- | --------- |
| `===`、`!==`         | `boolean` |
| `<`、`<=`、`>`、`>=` | `boolean` |
| `==`、`!=`           | 编译错误  |

与数值、对象或其他类型比较不会触发隐式转换。联合类型必须先满足 T21、T24 和 T50 的比较规则。

## 静态字符串转换

`toString(): string` 只在静态接收者能够唯一确定实现时可调用：

| 接收者                             | 静态调用路径                                     |
| ---------------------------------- | ------------------------------------------------ |
| `string`                           | 返回原字符串。                                   |
| 数值和 `boolean`                   | 使用 T13 规范格式。                              |
| 数组                               | 使用 T34 `join(",")` 规则。                      |
| 普通对象                           | 固定默认对象文本。                               |
| 未覆盖方法的类实例                 | 使用普通对象默认结果。                           |
| 显式实现 `toString(): string` 的类 | 调用已解析方法；基类或接口视图使用既有动态派发。 |

`null` 和 `undefined` 没有可调用方法；显式转换使用标准库 `String(value)`。函数和 `symbol` 当前没有通用字符串转换。联合或泛型不能唯一确定路径时必须先收窄。

## `+` 运算分类

checker 必须把每个 `+` 唯一确定为数值加法或字符串拼接。至少一侧为 `string` 或字符串字面量，且另一侧属于以下单一静态类别时，结果为 `string`：

- `string` 或字符串字面量。
- `number`、原生整数、原生浮点或平台整数。
- `boolean`、`null` 或 `undefined`。
- 具有本规范静态 `toString` 路径的数组、对象或类实例。

`symbol`、函数和不能唯一确定表示或转换实现的联合/泛型被拒绝。checker 不能通过通用运行时 `ToPrimitive` 或类型分派扩大接受范围。

`+` 左结合，每个子表达式独立分类：

```ts
1 + 2 + '3'; // "33"
'1' + 2 + 3; // "123"
```

## 模板字符串

无插值模板和普通插值模板产生 `string`。每个插值必须满足 `+` 拼接允许的静态转换规则；多表示联合或泛型参数不能唯一确定路径时必须先收窄或显式转换。

普通模板不自动获得 T41 模板字符串类型。上下文明确要求模板字符串类型，且源码片段与插值静态类型能够证明模式时，可以产生对应窄类型。

Tagged template 当前不支持，由语法规范产生明确错误。

## 与 TypeScript 的差异

Nxts 保持字符串字面量、UTF-16 索引直觉和严格比较语法，但索引固定为 `i32`，动态读取始终包含 `undefined`，拼接必须静态确定转换路径，也不提供字符串装箱对象或 JavaScript 动态 `ToPrimitive`。

这些差异缩小接受范围。通过 Nxts checker 的字符串源码在提供原生类型与标准声明后仍应通过 TypeScript strict 检查。
