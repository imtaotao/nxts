# 联合类型

- 规范状态：已定稿
- 实现状态：未实现
- 最后更新：2026-07-21
- 文档顺序：13

## 目标与边界

定义联合类型的构造、身份、包含、归一化、赋值和直接操作，并为布局阶段提供无隐藏堆分配的表示约束。

子类型与赋值兼容见 [`3-typeCompatibility.md`](./3-typeCompatibility.md)，公共上界见 [`4-typeLattice.md`](./4-typeLattice.md)，控制流收窄见 [`6-typeNarrowing.md`](./6-typeNarrowing.md)。物理联合布局见 [`../../compiler/representation/1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md)，跨模块 tag 与布局摘要见 [`../../compiler/abi/1-typeAbi.md`](../../compiler/abi/1-typeAbi.md)。

## 核心原则

- 联合类型表示一个值属于有限成员集合中的至少一个类型，不表示动态未知值。
- 联合成员顺序不参与类型身份；checker 始终使用规范成员集合。
- 用户可以按 TypeScript 方式隐式把成员值赋给联合目标，编译器必须在 Typed IR 中显式记录需要的表示构造。
- 联合构造、转换和检查不得产生隐藏堆分配、对象裁剪或通用动态装箱。
- 可以证明成员共享同一运行时表示且不需要额外区分时，联合不得增加 tag。
- 无法静态确定唯一操作语义时必须先收窄，不能生成通用动态运算分派。
- 复杂度超限必须产生明确诊断，不能静默 widening 为基础类型、`unknown` 或其他兜底类型。

## 语法与合法成员

联合类型使用 TypeScript 的 `|` 语法：

```ts
type Result = string | i32;
type State = 'idle' | 'running' | 'done';
```

能够作为普通值存储的类型可以成为联合成员，包括基础类型、字面量类型、对象、接口视图、类、函数、数组、元组、泛型实例、`null`、`undefined` 和 `unique symbol`。具体类型仍须满足其所属能力的可构造性和存储规则。

特殊成员按以下规则处理：

| 成员      | 处理                                                                          |
| --------- | ----------------------------------------------------------------------------- |
| `never`   | 允许出现在类型表达式中，规范化时消去；全部成员均为 `never` 时结果为 `never`。 |
| `void`    | 不是普通值类型，不能作为联合成员。                                            |
| `any`     | 永久不支持，出现即为编译错误。                                                |
| `unknown` | 不能与普通类型混合；与 `never` 组合时规范化为 `unknown`。                     |
| `bigint`  | 当前语言不支持，对应类型和字面量均为编译错误。                                |

`null` 与 `undefined` 是相互独立的原子成员。它们与普通类型组成联合时不互相吸收，也不隐式合并为单一空值类型。

## 类型身份与归一化

联合类型的语义身份是规范化后的无序成员集合。checker 按以下顺序处理：

1. 展开透明类型别名并递归展平嵌套联合。
2. 消去 `never`。
3. 按规范类型身份去重。
4. 使用已经成立的零成本子类型关系，或 T29 明确允许的接口上位关系，消去被上位成员完全覆盖的成员。
5. 应用基础类型明确规定的有限全集规则。
6. 按稳定规范键排序并驻留规范联合类型。

```text
A | A                 => A
(A | B) | C           => A | B | C
T | never             => T
"ready" | string      => string
1(i32) | i32           => i32
true | false           => boolean
Derived | Base         => Base
Concrete | Interface   => Interface  // Concrete 静态满足 Interface
```

除 T29 的接口特例外，吸收只能依据已经定义的零成本子类型或有限全集规则，不能依据名称相似、公共字段、可执行转换或运行时检查。接口特例必须具有已经存在的目标接口契约，并在值进入结果类型时明确生成 `InterfacePack` 或 `InterfaceRepack`；checker 不搜索或合成匿名公共接口，也不执行成员扫描、对象复制、堆分配或可能失败的转换。不同基础数值类型即使数学值相同也保持不同成员：

```text
1(i32) | 1(f64) => 保留两个成员
i32 | f64       => 保留两个成员
```

规范化后只有一个成员时，结果就是该成员类型，不保留联合包装。源码成员顺序可以用于诊断展示，但不能影响类型相等、运行时布局或 ABI。

## 包含与赋值

联合兼容沿用 T03 的公共上位规则：

```text
S -> A | B
```

当 `S` 能兼容至少一个目标成员时成立。

```text
A | B -> T
```

当每个源成员都能兼容 `T` 时成立。

```text
A | B -> C | D
```

当每个源成员都能兼容至少一个目标成员时成立。该规则不能把联合值隐式收窄为其中一个成员：

```ts
const assignUnion = (value: string | i32) => {
  const wider: string | i32 | null = value; // 合法
  const text: string = value; // 编译错误：必须先收窄
};
```

联合赋值分为两种 checker 结果：

| 结果                        | 条件                                                        |
| --------------------------- | ----------------------------------------------------------- |
| `AssignableNoOp`            | 源值和目标联合具有相同物理表示，不需要 tag 或布局变化。     |
| `AssignableWithUnionInject` | 源值属于目标成员，但目标表示需要初始化 tag 或写入 payload。 |

联合到联合的兼容如果需要改变 tag 编号、payload 布局或 GC 描述，使用 `AssignableWithUnionRepack`。`UnionInject` 和 `UnionRepack` 是明确的 Typed IR 表示转换，不是 T03 的零成本子类型转换；二者都不得进行堆分配、对象重建或可能失败的转换。成员因接口上位关系被吸收时，先使用 T29 的 `InterfacePack` 或 `InterfaceRepack` 得到规范接口成员表示，再执行必要的联合表示构造。

```ts
let value: string | i32 = 1; // UnionInject，必要时写入 tag 和 payload
value = 'ready'; // UnionInject

const wider: string | i32 | null = value; // 必要时 UnionRepack
```

普通赋值所需的值移动仍遵循对应类型 ABI。大型 payload 是否通过地址间接传递由 T45 定义，不能通过把联合成员装箱为堆对象来规避布局。

## 未收窄值的直接操作

只有当 checker 能证明操作对每个可能成员都合法，并且结果类型可以确定时，未收窄联合值才能直接参与操作。

### 相等、判断与收窄

`typeof`、`instanceof`、判别字段、严格相等和严格空值判断按 T06、T14、T24 的规则收窄联合成员。联合参与 `===` 或 `!==` 时，两个操作数之间必须至少存在一组由成员类型规范允许的比较；不存在任何可比较成员对时为编译错误。

```ts
const compareUnion = (value: string | i32) => {
  value === 'ready'; // 合法，可以收窄 string 成员
  value === true; // 编译错误：没有可比较成员
};
```

运行时成员类别明确不同时，`===` 直接为 `false`，`!==` 直接为 `true`；类别可能相同时才执行成员类型规定的比较。该过程不得执行跨类型转换、装箱或用户定义转换。

### 属性读取

只有每个成员都提供可读属性时，才能从未收窄联合读取该属性。结果是各成员属性类型规范化后的最小公共上界：

```ts
type Item =
  | { kind: 'text'; id: i32; value: string }
  | { kind: 'count'; id: i32; value: i32 };

const readItem = (item: Item) => {
  item.kind; // "text" | "count"
  item.id; // i32
  item.value; // string | i32
};
```

缺少属性、属性不可读或结果类型无法合法构造时，必须先收窄。不同成员的物理属性访问由 IR 与布局阶段实现，不改变读取结果类型。

### 属性写入

读取类型为联合只表示“结果可能属于任一成员”，不表示任一成员值都能安全写回。对未收窄联合写属性时，必须同时满足：

- 每个成员都存在该属性并允许写入。
- 写入值分别兼容每个成员中的属性目标类型。
- 写入不会改变当前值所属联合成员的类型不变量。

```ts
const updateItem = (item: Item) => {
  item.id = 10; // 合法：10 对两个成员的 id 都是有效 i32
  item.value = 10; // 编译错误：text 成员要求 string

  if (item.kind === 'count') {
    item.value = 10; // 合法：已经收窄
  }
};
```

写入目标相当于所有可能属性目标类型的安全交集，而不是读取类型的联合。需要改变联合成员时，应替换整个联合值：

```ts
const replaceItem = (item: Item) => {
  item = { kind: 'count', id: 1, value: 10 };
};
```

该规则防止产生 `{ kind: "text", value: 10 }` 之类不属于任何声明成员的状态，也避免隐藏运行时失败。

### 索引与调用

索引访问只有在每个成员都支持同一种索引输入时才合法，结果取各成员索引结果的最小公共上界。具体字符串、数组、元组和字典规则由 T13、T30、T34、T35 和 T51 定义。

联合函数只有在每个成员都可调用、同一组实参对每个签名都安全，并且调用约定可以统一时才能直接调用；结果取各返回类型的最小公共上界：

```ts
const callUnion = (
  fn: ((value: i32) => string) | ((value: i32) => boolean),
) => {
  const result = fn(1); // string | boolean
};
```

完整的参数逆变、可选参数、重载、接收者绑定和调用 ABI 由 T32、T33、T38 和 T53 定义。本节不允许通过动态尝试不同签名来放宽调用。

### 运算符

普通算术、关系比较、字符串拼接和其他运算符必须在编译期选择唯一实现。只有成员共享同一基础表示和运算语义时，联合才可直接参与对应运算：

```ts
const calculate = (literal: 1 | 2, numeric: i32 | f64) => {
  literal + 1; // 合法：统一使用 i32 加法
  numeric + 1; // 编译错误：不能确定唯一数值实现
};
```

checker 不得为普通运算生成基于联合 tag 的动态类型分派。各运算符的最终操作数和结果规则由 T50 定义。

## 运行时表示

T21 只规定以下表示约束：

- 联合不能因成员异构而自动堆分配或使用通用动态盒。
- 同表示且无需恢复来源的成员不得增加 tag。
- 一般联合使用可内联、可精确扫描的确定表示。
- 表示选择不能改变类型身份、赋值结果、严格相等或收窄。

niche、tag、payload、对齐、GC 形状和抽象传参由 [`../../compiler/representation/1-typeRepresentation.md`](../../compiler/representation/1-typeRepresentation.md) 唯一定义。checker 不根据 LLVM 或目标机器类型判断语言类型相等。

## 规范标签与跨模块一致性

语义相同的联合必须产生相同规范成员顺序和布局身份：

```ts
type A = string | i32;
type B = i32 | string;
```

`A` 与 `B` 是同一类型。实现必须满足：

- 透明类型别名不创建新的联合身份或 tag 空间。
- tag 仅是内部表示，源码不能读取、伪造或依赖其数值。
- 内部 tag 不能直接作为稳定序列化格式、网络协议值或 FFI 判别值。
- 不同成员集合之间的赋值兼容不能擅自省略必要的 `UnionRepack`。

稳定 tag 分配、布局摘要和链接拒绝由 [`../../compiler/abi/1-typeAbi.md`](../../compiler/abi/1-typeAbi.md) 定义。优化器只有证明物理布局一致时才能把 `UnionRepack` 降为零成本视图。

## 泛型联合

泛型定义检查期间保留符号联合。实例化时先替换类型参数，再执行完整规范化和布局选择：

```ts
function choose<T, U>(left: T, right: U, useLeft: boolean): T | U {
  return useLeft ? left : right;
}
```

```text
T = string, U = string  => string
T = i32, U = string     => i32 | string
T = 1, U = 2            => 1 | 2，运行时使用 i32 表示
```

checker 优先从实参和上下文推导类型参数；无法可靠推导时产生诊断，用户可以显式提供类型实参或类型标注。不能通过 `any`、`unknown`、泛型擦除或运行时类型推导兜底。

联合不会自行对类型构造器应用分配律：

```text
Array<A | B> != Array<A> | Array<B>
```

左侧数组允许每个元素分别选择成员，右侧表示整个数组只属于其中一种数组类型；二者具有不同写入规则和元素布局。

实例化后必须得到闭合规范联合，不能通过 `any`、`unknown` 或泛型擦除兜底。布局和代码共享由 T37、T45 决定，不能反向改变本节规范化结果。

## 复杂度边界

官方编译器至少支持 `65535` 个简单规范成员的平坦联合。达到复杂关系预算时必须明确诊断，不能删除成员、扩大为基础类型或改用动态表示。

驻留、排序、关系缓存、实例化预算和穷尽检查的数据结构由 [`../../compiler/frontend/5-checkerSemanticModel.md`](../../compiler/frontend/5-checkerSemanticModel.md) 定义。成员数量本身不决定运行时成本。

## 编译器职责

checker 负责展平、去重、吸收和驻留规范联合，并检查赋值、公共操作、安全写入和复杂度边界。控制流分析按 T06、T24、T25 排除成员、合并路径和检查穷尽性。

Checked HIR、布局、GC 与 ABI 职责分别见 [`../../compiler/ir/1-irContracts.md`](../../compiler/ir/1-irContracts.md)、T45、T46 与 T47。

## 与 TypeScript 的兼容性

Nxts 保持 TypeScript 的联合语法、无序身份、展平去重、`never` 消去、公共属性读取、控制流收窄、泛型符号联合和上位赋值方向。使用 Nxts 内建类型声明后，通过 Nxts checker 的源码仍应通过 TypeScript 类型检查。

主要差异如下：

| 场景             | TypeScript                                                      | Nxts                                                    |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------- |
| 运行时表示       | 类型擦除，值继续使用 JavaScript 动态表示。                      | 选择无标签表示或内联 `tag + payload`。                  |
| 联合构造与转换   | 不生成类型专用运行时代码。                                      | 必要时生成 `UnionInject` 或 `UnionRepack`，但不堆分配。 |
| 未收窄属性写入   | 部分场景按读取到的属性联合类型宽松接受。                        | 写入值必须对每个可能成员都安全。                        |
| 运算符           | 依赖 JavaScript 的动态值和统一 `number` 模型。                  | 必须静态选择唯一原生实现，不生成普通动态运算分派。      |
| `any`、`unknown` | `any` 可吸收成员；普通类型与 `unknown` 的联合归一为 `unknown`。 | `any` 不支持；普通类型不能与 `unknown` 直接混合。       |
| `void`、`bigint` | 可以参与相应联合。                                              | `void` 不是普通联合成员，当前不支持 `bigint`。          |
| 复杂度限制       | 使用实现启发式和内部计算预算。                                  | 保证简单联合最低能力，并对复杂操作给出明确资源诊断。    |

这些差异收紧 Nxts 的接受范围，不增加 TypeScript 无法解析的联合语法。运行时标签属于原生编译实现，不改变源码类型检查严格子集的定义。

## 依赖边界

| 相关能力                                 | T21 已确定内容                           | 对应能力负责内容                                   |
| ---------------------------------------- | ---------------------------------------- | -------------------------------------------------- |
| [T23 空值联合](./10-nullAndUndefined.md) | 空值是独立成员且不得装箱。               | 安全 niche、内联状态、泛型实例布局和 ABI 选择。    |
| T26–T28、T30–T35 复合类型                | 公共读取与安全写入的一般原则。           | 属性、索引、函数、数组、元组的完整成员规则。       |
| T29 接口                                 | 已有目标接口可以吸收静态满足它的成员。   | 结构满足、`InterfacePack`、witness 和反射规则。    |
| T37 泛型                                 | 替换后规范化且禁止动态兜底。             | 推导、单态化、代码共享和代码体积策略。             |
| T45–T47 表示                             | 无标签优化、一般标签联合和规范身份要求。 | 精确大小、对齐、GC 描述、布局摘要和跨模块 ABI。    |
| T50–T53 表达式                           | 操作必须对全部成员合法且语义唯一。       | 运算符、成员访问、赋值、调用和构造的完整检查入口。 |

## 诊断与测试

至少覆盖以下场景：

| 场景                           | 预期                                              |
| ------------------------------ | ------------------------------------------------- |
| 嵌套、重复、`never` 和成员换序 | 得到同一规范联合身份。                            |
| 字面量、基础类型和基类吸收     | 按零成本下位关系消除成员。                        |
| 具体对象或子接口被接口吸收     | 生成有界接口打包或重打包，不扫描、不堆分配。      |
| 不同基础数值类型               | 保持独立成员，不隐式提升。                        |
| 成员值赋给联合                 | 接受并标记所需联合注入类别。                      |
| 小联合赋给大联合               | 合法时标记无操作或联合重组类别。                  |
| 联合隐式赋给单一成员           | 拒绝，必须先收窄。                                |
| 公共属性读取                   | 结果为规范化后的属性类型联合。                    |
| 不安全属性写入                 | 在写入处报错；收窄后或替换整个成员时接受。        |
| 联合函数调用                   | 只接受所有签名都安全的实参，结果取返回联合。      |
| 多实现算术或拼接               | 拒绝并要求先收窄。                                |
| 大型简单联合                   | 至少 65535 个规范成员可被接受并保持精确类型。     |
| 复杂度预算耗尽                 | 明确报错，不 widening、不删成员、不改用动态表示。 |

IR、布局、GC 和跨模块一致性测试由 T45–T47 与 [`../../compiler/ir/1-irContracts.md`](../../compiler/ir/1-irContracts.md) 覆盖。
