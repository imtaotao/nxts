# 数值语义

- 覆盖能力：T08、T09、T10、T11
- 规范状态：已定稿
- 文档顺序：1

## 目标与边界

本规范定义 `number`、整数、原生浮点和平台整数运算的可观察结果、溢出、特殊值与失败行为。

静态操作数和结果类型由[数值类型](../types/8-nativeNumericTypes.md)定义，显式转换与 checked / saturating API 由[数值标准库](../../stdlib/5-numeric.md)定义，机器表示由[类型运行时表示](../../compiler/representation/1-typeRepresentation.md)定义。

## JavaScript `number`

`number` 完整保持 JavaScript Number 的 IEEE 754 binary64 语义：

```ts
NaN === NaN; // false
0 === -0; // true
1 / -0; // -Infinity
```

支持的 `number` 算术、关系比较和严格相等必须保持：

- `NaN` 传播与比较。
- 正负无穷。
- `-0`。
- binary64 舍入和精度损失。
- JavaScript `%` 余数行为。

普通优化不能：

- 假设值不会是 `NaN`、无穷或 `-0`。
- 重排依赖舍入顺序的表达式。
- 把浮点运算替换为结果不同的整数运算。
- 使用改变舍入、精度或比较结果的 fast-math。

如果某项 JavaScript Number API 无法保持完整语义，应拒绝该 API，而不是改变 `number`。

## 固定宽度整数溢出

固定宽度整数 `+`、`-`、`*` 使用确定回绕：

```text
无符号：结果 mod 2^N
有符号：结果 mod 2^N 后按二进制补码解释
```

```ts
const signed: i8 = 127;
const signedNext = signed + 1; // -128

const unsigned: u8 = 255;
const unsignedNext = unsigned + 1; // 0
```

Debug 与 Release 结果相同。普通加减乘不插入隐藏溢出检查，编译器也不能假设有符号运算不会溢出。

编译期常量运算与运行时运算使用相同回绕规则。静态可证明回绕可以产生非错误诊断，但不能改变结果。

## 整数除法与取模

整数除法向零截断：

```ts
7 / 3; // 2
-7 / 3; // -2
7 / -3; // -2
```

取模满足：

```text
a = (a / b) * b + (a % b)
```

余数符号与被除数一致：

```ts
7 % 3; // 1
-7 % 3; // -1
```

无效输入：

| 场景              | 静态可证明 | 运行时       |
| ----------------- | ---------- | ------------ |
| 除数为零          | 编译错误   | trap / panic |
| 取模除数为零      | 编译错误   | trap / panic |
| 有符号 `MIN / -1` | 编译错误   | trap / panic |
| 有符号 `MIN % -1` | 编译错误   | trap / panic |

普通 `/` 和 `%` 直接返回整数，不返回隐式 checked 结果。实现可以插入最低成本失败检查，并在证明安全时消除。

## Checked 与 saturating 整数语义

| 类别                        | 结果                                       |
| --------------------------- | ------------------------------------------ |
| checked 加、减、乘、取负    | 可表示时成功，否则失败。                   |
| checked 除法、取模          | 非零且不是 `MIN / -1`、`MIN % -1` 时成功。 |
| saturating 加、减、乘、取负 | 越界时固定为 `MIN` 或 `MAX`。              |

checked 失败不能转为 trap / panic；saturating 不产生溢出失败。普通加减乘已经回绕，不需要独立 wrapping API。

公开入口和结果载体由[数值标准库](../../stdlib/5-numeric.md)定义。

## 原生浮点基础语义

`f32` 每个结果按 binary32 舍入，`f64` 每个结果按 binary64 舍入。默认舍入模式是就近舍入，中间值向偶数。

两者支持 `NaN`、正负无穷、正负零和次正规数：

| 场景                 | 结果                           |
| -------------------- | ------------------------------ |
| 非零有限值除以正负零 | 对应符号无穷。                 |
| 正负零除以正负零     | `NaN`。                        |
| 有限结果超过范围     | 舍入为对应符号无穷。           |
| 非零结果低于正规范围 | 次正规数，继续下溢为带符号零。 |

普通优化不能：

- 假设不存在特殊值。
- 重排依赖舍入的表达式。
- 把次正规数刷新为零。
- 自动把乘法加法融合为结果不同的单次舍入。

快速浮点必须通过未来显式模式、类型或 API 表达，不能由优化级别静默启用。

## 浮点比较

```ts
const nan: f32 = NaN;
const positiveZero: f32 = 0;
const negativeZero: f32 = -0;

nan === nan; // false
nan !== nan; // true
positiveZero === negativeZero; // true
```

任一关系比较操作数为 `NaN` 时，`<`、`<=`、`>`、`>=` 都返回 `false`。

## 浮点余数

浮点 `%` 使用 JavaScript 截断余数语义：

```text
remainder = dividend - trunc(dividend / divisor) * divisor
```

该公式定义数学结果，不要求实现按已经舍入的除法和乘法逐步计算。

| 场景                     | 结果                                   |
| ------------------------ | -------------------------------------- |
| 有限被除数、有限非零除数 | 按目标精度舍入，非零结果符号同被除数。 |
| 正负零、有限非零除数     | 保留被除数零符号。                     |
| 有限被除数、无穷除数     | 返回被除数。                           |
| 无穷被除数、非零除数     | `NaN`。                                |
| 任意值、正负零除数       | `NaN`。                                |
| 任一操作数为 `NaN`       | `NaN`。                                |

浮点 `%` 不 trap / panic。

## NaN 位模式与负零

Nxts 保证 `NaN` 分类、传播和比较结果，不保证算术产生的 payload、符号位或 signaling / quiet 形式。

如果标准库提供原始位读写：

| 场景                   | 保证                                     |
| ---------------------- | ---------------------------------------- |
| 读取浮点当前位         | 返回实际位模式。                         |
| 位模式构造后直接读取   | 未经算术时保留输入。                     |
| 复制、存储、传参和返回 | 未经算术时不主动规范化 NaN 或丢失 `-0`。 |
| NaN 算术后读取         | 只保证仍为 NaN。                         |

`-0` 符号必须在存储、参数、返回、除法和原始位观察中保留，不能因 `0 === -0` 而统一改写。

## 平台整数运算

平台整数使用目标指针宽度的整数语义：

| 运算                 | `usize`            | `isize`                        |
| -------------------- | ------------------ | ------------------------------ |
| 加减乘溢出           | 按目标宽度回绕     | 按目标宽度补码回绕             |
| 除法与取模           | 向零截断；除零失败 | 向零截断；除零与 `MIN/-1` 失败 |
| 一元负号             | 不支持             | 支持，`MIN` 取负按目标宽度回绕 |
| checked / saturating | 复用固定整数语义   | 复用固定整数语义               |

平台宽度在编译目标确定，不产生 32/64 位运行时分支。

涉及分配大小、元素数量乘积和地址偏移的计算应使用 checked 运算。API 仍需验证自己的边界，不能因参数是 `usize` 就假设前序计算未回绕。

## 数值失败边界

| 场景               | 结果                            |
| ------------------ | ------------------------------- |
| 普通整数加减乘溢出 | 回绕。                          |
| 整数无效除法或取模 | 静态错误或运行时 trap / panic。 |
| 普通浮点除零       | IEEE 754 无穷或 NaN。           |
| 普通浮点溢出、下溢 | IEEE 754 舍入结果。             |
| checked 运算失败   | 返回显式失败，不 trap。         |
| 显式精确转换失败   | 返回 `null`。                   |

trap / panic 的统一运行时机制由 T61 和 runtime 规范确定。

## 性能语义边界

- 普通标量数值不装箱、不分配。
- 普通整数加减乘不执行隐藏溢出检查。
- 浮点不执行特殊值检查。
- `number` 与 `f64` 可以共享机器表示，但不能因此改变语义。
- Debug 与 Release 保持同一语言结果。
- 静态证明安全时可以消除整数除法失败检查。

## 语义测试

| 场景               | 结果           |
| ------------------ | -------------- |
| `NaN === NaN`      | `false`。      |
| `0 === -0`         | `true`。       |
| `1 / -0`           | `-Infinity`。  |
| `i8(127) + i8(1)`  | `-128`。       |
| 整数运行时除零     | trap / panic。 |
| `i32::MIN / -1`    | trap / panic。 |
| `f32(1) / f32(0)`  | `Infinity`。   |
| `f32(0) / f32(0)`  | `NaN`。        |
| `f32(-5) % f32(2)` | `-1`。         |
| Debug 与 Release   | 相同数值语义。 |
