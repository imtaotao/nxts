## 目标与边界

本规范定义接口视图的对象身份、可选属性、反射事实和动态检查行为。静态契约与兼容见 [`../types/17-interfaces.md`](../types/17-interfaces.md)，`Object.*` API 契约见[对象标准库](../../stdlib/4-object.md)，runtime 算法见 [`../../runtime/objects/7-interfaceRuntime.md`](../../runtime/objects/7-interfaceRuntime.md)。

## 接口不是运行时对象

接口名称只存在于类型空间，不能构造、传值或作为 `instanceof` 目标。具体对象转为接口不会创建字段裁剪对象，也不会改变底层对象身份。

## 对象身份

接口视图始终引用原具体对象：

- 接口复制不复制底层对象。
- 接口与另一个视图比较时使用底层对象身份，不比较 witness。
- 通过接口写入成员，原对象和其他视图立即观察到同一状态。
- 具体对象包含的额外成员继续存在。

## 可选属性

具体对象可以缺少接口声明的可选属性。读取缺失属性得到 `undefined`；写入后，该属性成为原对象实际存在的自身属性：

```ts
const raw = {};
const options: Options = raw;

Object.hasOwn(raw, "cache"); // false
options.cache = "memory";
Object.hasOwn(raw, "cache"); // true
```

接口转换本身不分配。若具体对象没有预留槽位，首次写入可以按需分配有限扩展状态；该成本发生在写入，不发生在转换或普通字段访问。

新增、删除和重新添加的枚举顺序遵循对象语义。接口契约未声明的任意键不能借有限可选属性扩展写入。

## 反射

反射基于底层具体对象，不按接口成员裁剪：

- 自身属性枚举包含实际存在的可枚举属性。
- 自身属性存在查询不把继承方法或尚未写入的可选成员算作自身属性。
- `in` 观察自身成员、类继承成员和已存在的有限扩展成员。
- `===`、`!==` 比较底层对象身份。

`Object.keys` 和 `Object.hasOwn` 按[对象标准库](../../stdlib/4-object.md)将前两项事实暴露为公开 API。接口显式包含索引签名时，还要观察 T30 字典扩展状态。

## 动态检查

静态对象转接口不执行运行时成员扫描。受信动态检查通过具体类型描述和预生成 witness 判断契约：

- 不逐个读取用户属性。
- 不调用 getter、代理或其他用户代码。
- 成功产生接口视图。
- 普通失败返回 `false`。

接口名称仍不进入值空间，不支持 `value instanceof Interface`。

## 性能语义

普通接口转换不堆分配，复制为固定大小视图。具体类型已知时可以去除接口间接层。未使用接口的普通对象不承担 witness、扩展状态或动态查询成本。

目标是常见接口传参与调用达到等价 Go interface 的成本级别。

## 语义测试

至少覆盖接口转换保留身份、额外字段反射、缺失可选属性读写、首次写入可观察性、`hasOwn`/`in`/`keys`、接口严格相等、动态检查不执行用户代码和未使用接口无额外成本。
