# 语法子集

- 规范状态：已定稿
- 最后更新：2026-07-29
- 文档顺序：1

## 目标与边界

本规范记录 Babel 能解析但 Nxts 接受、限制或拒绝的语法。类型合法性仍由 `language/types` 定义。

## 验证策略

实现必须为当前锁定 Babel 版本中的每种具体 Node 类型指定一种策略：

| 策略             | 处理                                                            |
| ---------------- | --------------------------------------------------------------- |
| `accept`         | 语法接受，保留节点并交给 Binder 或 Checker。                    |
| `contextual`     | 节点形式可用，但 Validator 必须检查源码位置和父级上下文。       |
| `reject`         | Babel 可以形成节点，Validator 产生稳定 `NXT1xxx` 诊断。         |
| `parserDisabled` | 不启用所需 Babel plugin，并把缺失 plugin 错误映射为不支持诊断。 |

不得对未识别 Node 默认放行。实现维护当前 Babel 节点类型到策略的完整映射；文档按用户可见语法类别描述规则，一致性测试负责验证每个具体 Node 都被某个规则覆盖。

Babel 升级新增 Node、改变访问键或节点形状时，覆盖测试必须失败。只有明确选择支持、限制或拒绝并更新对应规范后才能升级。

## 文件与模块顶层语法

- 小节结论：已定

Nxts 源文件的 Babel AST 根节点必须为 `File -> Program`。所有源文件固定按 ES Module 和 ECMAScript 严格模式解析，不根据源码内容推断 script 或 CommonJS 模式。

| 语法                                      | 处理                                                                                                                          |
| ----------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 首行 hashbang，例如 `#!/usr/bin/env nxts` | 仅允许位于 BOM 处理后的文件首行；保留 `InterpreterDirective`，不产生类型或运行时语义                                          |
| `"use strict"`                            | 接受并保留 directive；Nxts 已固定使用严格模式，因此不改变编译行为                                                             |
| 其他 directive prologue                   | 接受并保留，不得用于启用编译器私有能力                                                                                        |
| 标准静态 ES Module 语法                   | 接受默认导入、命名导入、命名空间导入、副作用导入、静态导出、重新导出、`import type` 和 `export type`；具体模块语义由 T55 定义 |
| CommonJS、顶层 `return`                   | 拒绝并产生明确的 `NXT1xxx` 诊断                                                                                               |
| `import()`                                | 语法接受并完整保留 AST；能力尚未实现时由 T55/T59 语义检查产生诊断并阻止生成 HIR                                               |
| 顶层 `await`                              | 语法接受并完整保留 AST；能力尚未实现时由 T55/T59 语义检查产生诊断并阻止生成 HIR                                               |
| import attributes                         | 语法接受并保留 `ImportAttribute`；资源能力未实现时由 T55 产生诊断并阻止生成 HIR                                               |

静态 `import` 和 `export` 声明必须位于 ES Module 允许的顶层位置。`import()` 的语法接受不代表动态加载能力已经实现；在 Promise、异步执行和运行时模块加载语义形成闭环前，Checker 必须产生能力诊断，且编译链不得为该程序生成 HIR。

hashbang 只用于 Host 或命令行入口识别，不决定文件是否为程序入口，也不能改变模块解析、类型检查或生成代码。directive prologue 中除 ECMAScript 已定义语义外的字符串不形成 Nxts 编译选项或 intrinsic。

## 变量声明语法

- 小节结论：已定

| 语法                             | 处理                                                 |
| -------------------------------- | ---------------------------------------------------- |
| 带初始化器的 `const`             | 接受；初始化器不可省略                               |
| 带初始化器的 `let`               | 接受；未显式注解时由初始化值推导类型                 |
| 无初始化器的 `let value: T`      | 接受；Checker 必须执行确定赋值分析                   |
| 无注解且无初始化器的 `let value` | 语法接受；Checker 无法得到具体类型时产生类型推导诊断 |
| `var`                            | Parser 阶段拒绝；Validator 产生明确的 `NXT1xxx` 诊断 |
| 对象和数组解构声明               | 接受 JavaScript 解构、默认值和末尾 rest 形式         |
| `using`、`await using`           | 当前拒绝；Nxts 尚未定义显式资源管理协议              |

无初始化器的 `let` 不代表运行时已经写入 `undefined`。变量只有在控制流证明已经赋值后才能读取，确定赋值分析不得引入运行时初始化标记或读取检查。

Nxts 不建立 `var` 的函数作用域、声明提升或重复声明兼容规则。Babel 解析得到的 `VariableDeclaration(kind: "var")` 必须由 Parser 阶段的 Validator 拒绝，不能静默改写为 `let`，也不能进入 Binder、Checker 或 HIR。保留该 Babel 节点只用于准确诊断和无效子树隔离。

## 普通声明语法

- 小节结论：已定

| 语法                            | 处理                                                   |
| ------------------------------- | ------------------------------------------------------ |
| 函数声明与类声明                | 接受；具体成员和类型规则交给对应语义检查               |
| 接口与类型别名声明              | 接受                                                   |
| `enum` 与 `const enum`          | 接受；两者的类型和运行时规则由 T39 定义                |
| 无函数体的重载签名              | 上下文接受；必须属于相邻重载组并具有唯一实现           |
| 应用源码中的显式 `declare`      | Parser 阶段拒绝并产生结构化 `NXT1xxx` 诊断             |
| `namespace`、模块扩充与全局扩充 | Parser 阶段拒绝并产生结构化 `NXT1xxx` 诊断             |
| `abstract class` 与抽象成员     | Parser 阶段拒绝并产生结构化 `NXT1xxx` 诊断             |
| 重复声明和 TypeScript 声明合并  | 保留单个声明节点；Binder 按重复符号产生 `NXT2xxx` 诊断 |

Validator 不能仅根据 Babel 节点类型 `TSDeclareFunction` 拒绝函数，因为没有显式 `declare` 的 TypeScript 函数重载签名也可能使用该节点形状。Parser 必须保留显式修饰符和相邻声明顺序，由 Validator 区分应用源码中的 ambient 声明与候选重载签名，再由 Binder 和 Checker 验证重载组。

标准库、runtime 或 Host 的可信声明属于工具链私有输入，不代表应用源码可以使用 ambient 声明，也不能通过公开 Parser 选项切换到更宽松的语法模式。

## 基础语句与同步控制流语法

- 小节结论：已定

| 语法                               | 处理                                                         |
| ---------------------------------- | ------------------------------------------------------------ |
| 代码块、表达式语句与空语句         | 接受                                                         |
| `if` / `else` 与 `switch`          | 接受                                                         |
| `while`、`do...while` 与普通 `for` | 接受                                                         |
| `return`                           | 函数体内接受；其他位置由 Parser 阶段产生结构化语法诊断       |
| `break`、`continue`                | 上下文接受；Validator 检查循环、`switch` 和标签目标          |
| 标签语句                           | 接受；标签目标由 Validator 检查                              |
| `for...in`                         | 语法接受；Checker 根据被遍历对象类型判断是否合法             |
| `for...of`                         | 语法接受；内建容器和通用迭代能力分别由对应语义规范检查       |
| `with`                             | ECMAScript 严格模式下由 Parser 阶段拒绝                      |
| `debugger`                         | 语法接受并保留 AST；调试工具链未实现时由后续能力检查产生诊断 |

标签、循环、分支、`break` 和 `continue` 必须直接表示为静态控制流边，不创建运行时标签对象或动态跳转表。

接受 `for...in` 语法不代表所有类型都可以使用：普通对象和字典按各自枚举语义检查，数组与元组为编译错误。接受 `for...of` 语法也不代表已经支持任意 JavaScript 迭代器；数组、元组等内建类型按现有能力检查，通用迭代协议由 T60 定义。

`debugger` 不能在编译期间被静默删除或改写为无条件 trap。调试执行语义尚未实现时，Checker 必须产生能力诊断并阻止生成 HIR；语法高亮、源码工具和调试器仍可读取原始节点和源码范围。

## 异常、异步与生成器语法

- 小节结论：已定

| 语法                                 | 处理                                                      |
| ------------------------------------ | --------------------------------------------------------- |
| `throw`、`try` / `catch` / `finally` | 语法接受；完整同步异常流由 T61 定义                       |
| `catch {}`                           | 接受省略 catch 绑定的形式                                 |
| async 函数、箭头函数与方法           | 语法接受；Promise、返回包装和执行语义由 T59 定义          |
| `await`                              | 上下文接受；Validator 检查位置，类型和执行语义由 T59 定义 |
| 生成器函数、`yield` 与 `yield*`      | 语法接受；生成器类型和执行语义由 T60 定义                 |
| `for await...of` 与异步生成器        | 语法接受；联合语义由 T59 和 T60 定义                      |

Parser 必须保留异常、异步和生成器节点的原始形状、修饰符、源码范围和 NodeId。换行限制、缺失操作数以及 `await`、`yield`、`return` 所处函数类别等上下文语法错误由 Babel Parser 或 Validator 产生结构化诊断。

在 T59、T60 或 T61 尚未形成完整语义闭环时，Checker 必须对对应未实现能力产生结构化诊断并阻止生成 HIR，不能把语义能力缺失误报为语法错误，也不能让未检查节点穿透到后端。

## 基础运算符语法

- 小节结论：已定

| 语法                                   | 处理                                                          |
| -------------------------------------- | ------------------------------------------------------------- |
| `+`、`-`、`*`、`/`、`%`、`**`          | 语法接受；操作数和结果类型由 T50 检查                         |
| 一元 `+`、一元 `-`                     | 语法接受；转换和数值类型边界由 T50 检查                       |
| `<`、`<=`、`>`、`>=`、`===`、`!==`     | 语法接受；可比较类型和收窄由 Checker 检查                     |
| `&&`、`\|\|`、`??`、`!` 与条件表达式   | 语法接受；保持短路和单次求值结构                              |
| `typeof`、`void`、`delete`             | 语法接受；名称绑定、操作数和可删除性由 Binder 或 Checker 检查 |
| `in`、`instanceof`                     | 语法接受；对象、字典和类身份要求由 Checker 检查               |
| `++`、`--`                             | 语法接受；Checker 检查可写左值和数值类型                      |
| 逗号表达式                             | 接受；保持从左到右求值和最后一个表达式结果                    |
| `==`、`!=`                             | Parser 阶段拒绝并产生结构化 `NXT1xxx` 诊断                    |
| `&`、`\|`、`^`、`~`、`<<`、`>>`、`>>>` | Parser 阶段拒绝并产生结构化 `NXT1xxx` 诊断                    |

运行时 `typeof undeclaredName` 的源码形状可以解析，但未绑定名称仍由 Binder 产生 `NXT2xxx` 诊断；Nxts 不提供 JavaScript 对该表达式的动态未声明名称特例。

接受 `delete` 语法不代表任意属性都可删除。可写可选对象或类字段、字典条目、数组和元组分别按其类型规范检查；Parser 不根据操作数类型决定可删除性。

运行时位运算符的拒绝不影响类型位置的联合 `|`、交叉 `&`、映射类型修饰符或其他 TypeScript 类型语法。Validator 必须按 AST 节点类别和表达式上下文判断，不能按源码字符直接拒绝。

## 成员访问、调用与构造语法

- 小节结论：已定

| 语法                              | 处理                                                   |
| --------------------------------- | ------------------------------------------------------ |
| `object.field`、`object[key]`     | 语法接受；成员存在性、可见性和 key 类型由 Checker 检查 |
| `object?.field`、`object?.[key]`  | 接受并保留可选链结构                                   |
| `fn?.(args)`、`object.method?.()` | 接受；空值和调用签名由 Checker 检查                    |
| 普通函数与方法调用                | 接受；参数、重载和接收者规则由 T53 检查                |
| `new Class(args)`                 | 接受                                                   |
| `new constructorValue(args)`      | 语法接受；右侧必须是 Checker 已证明的类构造器值        |
| 普通函数用于 `new`                | 语法接受；Checker 产生不可构造诊断                     |
| 类构造器不带 `new` 调用           | 语法接受；Checker 产生不可直接调用诊断                 |
| `this`、`super`、`super()`        | 上下文接受；位置、接收者和初始化规则由 T56 检查        |
| `new.target`                      | 上下文接受；仅允许类构造器及其词法箭头函数             |
| `import.meta`                     | ES Module 中语法接受；可用字段和 Host 语义由 T55 定义  |

Parser 不得根据标识符源码文本识别 `eval`、`Function`、`Proxy` 或其他动态内建能力。Parser 只保留引用、成员访问、调用和构造节点；Binder 与 Checker 必须根据解析后的符号身份和标准环境声明判断能力。Nxts 标准环境不提供动态 `eval`、`Function` 构造器或 `Proxy` 绑定。

`call`、`apply` 和 `bind` 的成员访问与调用节点可以解析，但这些名称不是 Nxts 普通函数类型的成员。Checker 必须按函数类型能力产生结构化诊断，Parser 不能按属性名称拒绝。

可选成员、可选索引和可选调用必须保留链边界、短路位置和参数求值范围。Parser 不展开可选链，Checker 和后续 HIR 必须保证短路时不求值对应 key、参数或后续链段。

## 赋值、解构、rest 与 spread 语法

- 小节结论：已定

| 语法                                    | 处理                                                |
| --------------------------------------- | --------------------------------------------------- |
| `target = value`                        | 接受                                                |
| `+=`、`-=`、`*=`、`/=`、`%=`、`**=`     | 语法接受；左值和操作数类型由 Checker 检查           |
| `&&=`、`\|\|=`、`??=`                   | 接受并保留逻辑赋值运算符和单次求值边界              |
| `&=`、`\|=`、`^=`、`<<=`、`>>=`、`>>>=` | Parser 阶段拒绝，与运行时位运算边界一致             |
| 对象和数组解构声明                      | 接受                                                |
| 对象和数组解构赋值                      | 接受；保留赋值表达式与模式边界                      |
| 函数参数解构与解构默认值                | 接受                                                |
| 数组解构空位                            | 接受；表示跳过对应位置，不创建数组空洞              |
| 对象和数组 rest                         | 接受；单个 rest 必须位于模式末尾                    |
| 对象和数组字面量 spread                 | 接受                                                |
| 函数调用和构造调用 spread               | 接受                                                |
| 多个 spread                             | 语法接受；具体类型与求值规则由 T52、T53 和 T60 定义 |
| 可选链作为赋值目标                      | 拒绝并产生结构化语法诊断                            |
| 其他非法赋值目标                        | 由 Babel Parser 或 Validator 产生结构化语法诊断     |

Parser 必须保留解构属性与位置顺序、默认值表达式范围、数组模式空位、rest 位置、spread 源码顺序和原始赋值运算符。Parser 不执行解构展开，也不把逻辑赋值改写为读取、判断和写入。

赋值目标是否绑定到 `const`、是否 readonly、属性能否写入以及 spread 来源类型是否合法，分别由 Binder 和 Checker 判断，不属于 Parser 语法验证。

## 对象、数组与基础字面量语法

- 小节结论：已定

| 语法                                               | 处理                                                            |
| -------------------------------------------------- | --------------------------------------------------------------- |
| `{}` 与普通数据属性                                | 接受                                                            |
| 属性简写与对象方法简写                             | 接受                                                            |
| 计算属性 `{ [key]: value }`                        | 语法接受；key 类型和结果对象类别由 Checker 判断                 |
| 对象字面量 getter、setter                          | Parser 阶段拒绝；类访问器不受该规则影响                         |
| 对象 spread                                        | 接受                                                            |
| `[]` 与普通数组字面量                              | 接受                                                            |
| 数组尾随逗号                                       | 接受；尾随逗号不形成空位                                        |
| 数组字面量空位                                     | Parser 阶段拒绝，Nxts 普通数组不支持稀疏位置                    |
| 数组 spread                                        | 接受                                                            |
| `true`、`false`、`null`                            | 接受                                                            |
| 十进制、二进制、八进制、十六进制、指数和数字分隔符 | 接受；数值类型和范围由 Checker 检查                             |
| legacy octal，例如 `077`                           | ECMAScript 严格模式下由 Parser 阶段拒绝                         |
| bigint 字面量，例如 `123n`                         | Parser 阶段产生结构化不支持诊断                                 |
| 正则字面量                                         | 语法接受并保留 `RegExpLiteral`；能力未定义时由 Checker 产生诊断 |

`undefined` 使用普通标识符节点，由 Binder 解析到标准环境符号，不是 Parser 特殊字面量。

`__proto__`、`constructor` 和其他原型敏感名称可以形成普通属性节点。Parser 不按属性源码名称拒绝；后续阶段根据普通对象、字典或类上下文产生对应诊断或兼容性提示。

重复属性和计算属性冲突可能需要规范化 key 后才能确定，交给 Checker 处理。Parser 必须保留属性种类、computed 标记、源码顺序、数字原始文本、正则 pattern 与 flags、数组空位以及尾随逗号信息。被拒绝的可恢复节点仍可用于源码高亮和诊断，但不得进入正常语义分析。

## 类语法

- 小节结论：已定

| 语法                                        | 处理                                          |
| ------------------------------------------- | --------------------------------------------- |
| 类声明、命名或匿名类表达式                  | 接受                                          |
| 局部类声明                                  | 接受                                          |
| `extends`、`implements`                     | 语法接受；目标合法性由 Checker 判断           |
| 构造器、实例方法和静态方法                  | 接受                                          |
| 实例字段和静态字段                          | 接受                                          |
| 类 getter、setter                           | 接受；与对象字面量访问器的拒绝规则区分        |
| 静态初始化块                                | 接受                                          |
| 计算成员名                                  | 语法接受；key 类型和布局合法性由 Checker 判断 |
| `public`、`protected`、TypeScript `private` | 接受                                          |
| `readonly` 与可选字段 `?`                   | 接受                                          |
| 构造器参数属性                              | 接受                                          |
| 方法和构造器重载签名                        | 上下文接受；保留相邻声明顺序                  |
| async 方法和生成器方法                      | 语法接受；对应能力由 T59 和 T60 定义          |
| `abstract`                                  | Parser 阶段拒绝并产生结构化不支持诊断         |
| JavaScript `#private`                       | Parser 阶段拒绝并产生结构化不支持诊断         |
| 装饰器                                      | 不启用 Babel plugin，并映射为结构化不支持诊断 |
| `override`                                  | Parser 阶段拒绝；覆盖关系由 Checker 自动识别  |
| definite assignment `!`                     | Parser 阶段拒绝                               |
| `declare` 字段或方法                        | Parser 阶段拒绝                               |
| `accessor field` 自动访问器                 | Parser 阶段拒绝                               |
| `final`、`sealed`                           | 不提供相关语法                                |

静态初始化块中不接受 `await`、`yield`、`return`、`super()` 或 `new.target`；Babel Parser 未报告时必须由 Validator 产生上下文语法诊断。静态块可以使用当前类的 `this`、静态成员和 `super.staticMember`。

Parser 必须保留成员类别、static、computed、optional、readonly、访问修饰符、初始化器、重载顺序和源码范围。字段初始化、访问控制、继承目标、覆盖关系以及计算成员能否形成固定布局均由 Checker 判断。

## TypeScript 表达式与注解语法

- 小节结论：已定

| 语法                               | 处理                                                            |
| ---------------------------------- | --------------------------------------------------------------- |
| 变量、参数、返回值和字段的类型注解 | 接受                                                            |
| 可选参数和可选属性 `?`             | 上下文接受；位置和顺序由 Validator 检查                         |
| 调用和构造的显式类型实参           | 接受                                                            |
| 实例化表达式 `fn<T>`、`Class<T>`   | 接受                                                            |
| 直接字面量 `as const`              | 语法接受；适用范围由 Checker 检查                               |
| `value as Brand<Base, Tag>`        | 语法接受；Checker 判断是否为合法的零成本品牌建立                |
| 普通 `value as Type`               | Parser 保留 `TSAsExpression`；Checker 产生不支持诊断            |
| `<Type>value`                      | Parser 阶段拒绝并产生结构化不支持诊断                           |
| 非空断言 `value!`                  | Parser 阶段拒绝，要求显式收窄或受信检查                         |
| `satisfies`                        | Parser 接受并保留节点；Checker 产生不支持诊断                   |
| `value is T` 与 `asserts` 类型谓词 | Parser 接受并保留；Checker 按受信内建与用户源码规则判断是否合法 |
| 链式和双重断言                     | Parser 保留完整结构；Checker 拒绝整个表达式                     |
| JSX、TSX                           | 不启用 JSX plugin，并映射为结构化不支持诊断                     |
| Flow 类型语法                      | 不启用 Flow plugin，并映射为结构化不支持诊断                    |

Parser 不能统一拒绝 `TSAsExpression`，因为品牌建立是否合法必须在名称绑定、别名展开和目标类型规范化后确定。Parser 也不能提前擦除 `as const`、品牌候选或无效断言 wrapper。

非空断言没有运行时检查，可能使静态类型与真实的 `null` 或 `undefined` 值不一致，因此不属于 Nxts 的有效表达式。源码必须使用控制流收窄、`??`、显式空值判断或受信类型检查。

Parser 必须保留类型注解、类型实参、断言源表达式、目标类型、链式顺序、wrapper NodeId 和源码范围。

## 特殊类型相关语法

| 语法                                 | 处理                                                                    |
| ------------------------------------ | ----------------------------------------------------------------------- |
| `void`、`never`、`unknown` 类型节点  | 解析并交给 Checker 做位置和使用检查。                                   |
| 一元 `void expression`               | 接受。                                                                  |
| `symbol`、`unique symbol` 类型节点   | 解析并交给 T18 检查。                                                   |
| `any` 类型节点                       | Parser 阶段产生结构化不支持诊断。                                       |
| bigint 类型与 `123n`                 | Parser 阶段产生结构化不支持诊断。                                       |
| 宽 `object` 类型节点                 | Parser 阶段产生结构化不支持诊断。                                       |
| `BigInt(...)`                        | 保留调用节点，由 Binder/Checker 按符号身份产生能力诊断。                |
| `new Symbol(...)`                    | 保留构造节点；Binder/Checker 按标准 `Symbol` 符号身份产生不可构造诊断。 |
| 不支持的 `Symbol.*` 与 symbol 属性键 | 保留成员节点；Binder/Checker 按符号身份产生能力边界诊断。               |

拒绝 bigint 字面量时不能删除 `n` 后缀后按普通数值继续编译。

宽 `object` 只能表达“非原始值”，无法给 Checker 提供确定字段、容器类别或运行时布局。Nxts 因此拒绝该类型关键字；需要静态结构时使用精确对象类型、接口、有限联合或泛型，需要先承接未知外部值时使用 `unknown` 并显式收窄。该限制不影响 `{}` 空对象字面量。

## 字符串相关语法

| 语法                             | 处理                                                            |
| -------------------------------- | --------------------------------------------------------------- |
| 单引号、双引号与 JavaScript 转义 | 接受并保留 cooked UTF-16 值。                                   |
| 无插值和普通插值模板             | 接受，保留片段、表达式顺序和源码范围。                          |
| 未标记模板非法转义               | 按 JavaScript early error 拒绝。                                |
| Tagged template                  | 识别后产生明确不支持诊断，不改写为普通调用。                    |
| `new String(value)`              | 语法接受；Binder/Checker 对标准 `String` 符号产生不可构造诊断。 |

## 函数相关语法

| 语法                                      | 处理                                                                  |
| ----------------------------------------- | --------------------------------------------------------------------- |
| 函数声明、函数表达式、箭头函数            | 接受，参数与返回类型交给 T32 检查。                                   |
| 对象、接口和类方法                        | 接受；类覆盖、`super` 与构造器由 T36/T56 检查。                       |
| 单一或多个纯调用签名接口                  | 接受并归一为单签名或重载函数契约。                                    |

| 接口内同名方法重载                        | 接受并保留源码顺序；不通过声明合并追加。                              |
| 箭头、函数表达式和对象字面量专用重载声明  | 不提供新语法。                                                        |
| 显式 `this` 伪参数                        | 接受，只用于类型和接收者检查。                                        |
| `arguments` 特殊绑定                      | 不建立；名称解析失败时按 T57 报错。                                   |
| 普通函数作为构造器、`Function` 动态构造器 | 语法接受；Binder/Checker 根据静态类型或标准符号身份产生不可构造诊断。 |
| 混合调用签名与普通成员的可调用对象        | checker 拒绝。                                                        |

## 元组相关语法

| 语法                                | 处理                                                |
| ----------------------------------- | --------------------------------------------------- |
| 固定、标签和 `readonly` 元组类型    | 接受；标签只保留给诊断与 IDE。                      |

## 未启用语法与 AST 契约兜底

- 小节结论：已定

| 语法或节点族                                | 处理                                                         |
| ------------------------------------------- | ------------------------------------------------------------ |
| import attributes                           | Parser 接受并保留 `ImportAttribute`；资源加载语义由 T55 定义 |
| 旧 import assertions                        | Parser 阶段拒绝                                              |
| `import = require()`、`export =`            | Parser 阶段拒绝                                              |
| JSX、TSX 与 Flow                            | 不启用对应 Babel plugin                                      |
| decorators                                  | 不启用对应 Babel plugin                                      |
| do expression、pipeline 与 function bind    | 不启用对应 Babel plugin                                      |
| partial application 与 argument placeholder | 不启用对应 Babel plugin                                      |
| module block 与 source/defer import         | 不启用对应 Babel plugin                                      |
| export-default-from proposal                | 不启用对应 Babel plugin                                      |
| record/tuple 与 decimal proposal            | 不启用对应 Babel plugin                                      |
| V8 intrinsic                                | 不启用对应 Babel plugin                                      |
| `ClassAccessorProperty`                     | 拒绝                                                         |
| `PrivateName`、私有字段与私有方法           | 拒绝                                                         |
| `TSObjectKeyword`                           | 拒绝；使用精确对象、接口、有限联合、泛型或显式 `unknown`     |
| Babel `VoidPattern`                         | 拒绝；Nxts 未定义 `using` 所需的显式资源管理语法             |
| Babel `Placeholder`                         | 源码 Parser 不得产生；出现时属于 AST 内部契约错误            |
| 旧动态导入 `Import` 节点                    | 不接受；固定配置必须产生 `ImportExpression`                  |
| 当前锁定版本之外的未知 Babel Node           | 不得默认接受；覆盖测试失败并阻止 Babel 版本升级              |

缺少 plugin、未启用 proposal 或当前不支持语法产生的 Babel 错误必须映射为稳定的 `NXT1xxx` 诊断，不得向调用方暴露 Babel 原始异常。

import attributes 的语法接受不代表 Nxts 已经支持 JSON、CSS、Wasm 或其他资源模块。Parser 保留说明符、属性 key、属性值、顺序和源码范围；在 T55 定义资源类型、加载方式、缓存和产物格式前，模块语义检查必须产生能力诊断并阻止生成 HIR。旧 `assert` 形式不作为兼容别名。

未知节点只可能来自未按契约锁定的 Babel 更新、外部伪造 AST 或编译器实现错误。公开 Parser 不接受外部 Babel AST；内部发现未知节点时必须标记分析不完整并进入实现错误通道，不能把它当作普通合法节点继续到 Binder。

### Babel 8.0.4 节点覆盖审计

当前锁定版本的 `VISITOR_KEYS` 包含 248 种具体 Node。按本规范和固定 Parser 配置审计后的实现基线如下：

| 策略             | Node 数量 |
| ---------------- | --------: |
| `accept`         |       114 |
| `contextual`     |        23 |
| `reject`         |        22 |
| `parserDisabled` |        89 |
| 未分类           |         0 |

实现中的 Node 策略映射必须与该版本的 `VISITOR_KEYS` 精确匹配。以上数量只用于锁定版本的一致性检查，不能代替逐节点映射；规则调整或 Babel 升级时允许数量变化，但未分类数量必须保持为零。
