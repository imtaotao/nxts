# Lowering 与优化策略

- 规范状态：部分定稿
- 最后更新：2026-07-28
- 文档顺序：1

## 目标与边界

本规范定义不改变语言语义、类型结论、值布局或 ABI 的 lowering 与优化策略。具体策略可以按目标平台和优化级别选择，但必须满足确定的成本和代码体积边界。

## 字面量与常量

checker 保留的常量事实可以用于常量折叠、分支删除、`switch` 分派、穷尽检查、字符串驻留和有收益的泛型专门化。SSA 分析也可以重新发现 widening 后的局部常量，但不能据此改变公开类型、诊断或跨模块签名。

运行时布局和执行路径相同时，不得仅因类型参数携带不同字面量就强制复制机器码。只有专门化能够消除分支或带来明确收益时才生成独立实现，并受统一代码体积预算约束。

## 字符串

| 场景                         | 优化要求                                                  |
| ---------------------------- | --------------------------------------------------------- |
| 全常量索引、比较、拼接和模板 | 前端常量折叠。                                            |
| 连续 `+` 与普通模板          | 合并为扁平 `StringConcat`，保持左到右求值和前缀失败顺序。 |
| 基础数值格式化               | 使用栈上临时缓冲并直接写入最终存储。                      |
| 空字符串拼接                 | 在值语义允许时复用另一侧存储。                            |
| 立即空值检查的索引           | 直接复用边界分支，避免物化联合。                          |

动态拼接成功路径只为最终字符串分配一次。比较不能分配，索引不能创建包装对象。优化不能改变 UTF-16 code unit 语义、`RangeError` 时机、后续表达式副作用或 Debug/Release 结果。

## 枚举

枚举分支应按规范值分布选择策略：

| 场景           | 候选策略                       |
| -------------- | ------------------------------ |
| 少量成员       | 直接比较与条件跳转。           |
| 密集数字成员   | 跳转表。                       |
| 稀疏数字成员   | 有序比较树或等价紧凑分派。     |
| 少量字符串成员 | 直接字符串比较。               |
| 大量字符串成员 | 静态哈希分派并验证最终字符串。 |
| 编译期已知成员 | 常量折叠并删除不可达分支。     |

稀疏数字枚举不能按最小值到最大值无条件生成巨型跳转表。同表示枚举联合在语义不要求恢复来源时不能增加外层 tag；空值和异构联合必须使用 T45 已确定的布局。

受信检查转换和成员遍历只在实际调用时生成检查代码或静态表。未使用遍历能力时应通过可达性分析删除枚举成员表和名称数据。

## 性能验收

枚举至少测量：

- 成员读取、复制、参数和返回。
- 相等、大小比较与模板插值。
- 小型、密集、稀疏数字分支。
- 少量和大量字符串分支。
- 数字与字符串枚举数组遍历。
- 泛型直接调用和跨模块调用。
- 检查转换的成功、失败和常量路径。
- 成员遍历首次引用、重复调用与未使用时的二进制体积。
- 空值 niche、紧凑状态和数组状态平面路径。

报告吞吐、延迟、分配、代码体积和关键分支数量，并与等价 Go 实现及手写 Nxts `i32` / `string` 实现对照。

普通数字枚举的最终目标是达到等价 Go 命名整数和常量的性能；第一版不得引入阻碍该目标的统一包装、动态分派或逐值描述符。

## 转换与动态检查

优化器可以在保持求值、身份、异常和失败语义时：

- 删除真正的 `NoOp` 转换。
- 消除表示相同的冗余接口或联合 repack。
- 折叠静态已知的数值精确转换结果。
- 通过逃逸分析和标量替换消除不可观察的对象重建。
- 折叠静态已知的类型检查。
- 复用稳定值的检查结果。
- 消除未逃逸的动态打包后立即检查及其聚合装箱。
- 在检查成功分支恢复固定字段、直接调用和接口去虚化。

优化器不能删除输入求值、改变字段求值顺序、合并可观察对象身份、把外部同形数据视为可信对象，或把需要成员验证的枚举转换改为无检查重解释。

动态值热点基准必须区分标签检查、描述符关系、witness 查询、聚合装箱和成功分支专门化，避免用统一平均值掩盖普通静态路径回归。

### 数值 intrinsic

绑定后的标准数值转换、checked 运算和 saturating 运算必须直接降低为目标原生指令、后端溢出 intrinsic 或等价的有限检查序列，不能通过普通 Nxts 函数重复实现机器级溢出判断。

lowering 必须满足：

- 编译期常量结果与同一目标上的运行时结果一致。
- 浮点转整数先建立规范的 NaN、无穷、范围和舍入结果，不能让后端未定义值或 poison 进入可观察路径。
- checked 失败和精确转换失败产生规范成功标记，不转换为 trap。
- `Target | null` 使用 T45 的统一联合布局和 T47 的统一调用分类，不建立 intrinsic 私有 ABI。
- 证明输入范围安全时可以消除检查，但不能改变边界值、负零、NaN 或溢出结果。

## 联合类型

优化器应消除：

- 同表示字面量联合的外层 tag。
- 已知成员的冗余状态写入和读取。
- 注入后立即收窄的中间联合存储。
- 物理布局相同的冗余 `UnionRepack`。
- 公共属性偏移相同时的状态分支。
- 循环内不变的联合状态与 payload 基址计算。

优化不能合并语义上仍需区分的成员、改变重叠来源候选、删除活动引用的 GC 状态，或让结果依赖源码成员顺序。

## 接口

具体来源类型或 witness 静态已知时，优化器应：

- 消除冗余 `InterfacePack` / `InterfaceRepack`。
- 把成员访问恢复为固定字段偏移。
- 把方法槽位调用去虚化为直接调用并允许内联。
- 复用已建立的动态契约检查结果。
- 在证明不需要时消除有限可选扩展定位。

优化不能裁剪底层对象、合并对象身份、隐藏首次可选属性扩展成本，或改变反射可见属性集合。

## 递归类型

递归类型沿用所属对象、容器、函数、接口和联合的 lowering，不建立递归专用代码路径。优化器可以共享表示、GC 形状和操作语义均相同的布局或泛型代码，但不能合并 checker 中不同的语义类型身份。

递归调用按普通调用优化。尾调用、内联和去虚化遵循一般成本模型，不依赖运行时递归深度，也不能为了接受无限泛型专门化而改用动态表示。

## 函数

| 场景                 | 优化要求                                           |
| -------------------- | -------------------------------------------------- |
| 已知目标直接调用     | 直接调用并允许内联，不物化函数值。                 |
| 已知方法调用         | 直接传递接收者，不创建绑定闭包。                   |
| 短 ABI 适配入口      | 在不改变求值顺序时内联并消除冗余打包。             |
| 不逃逸 rest 数组     | 允许栈分配、标量替换或完全消除。                   |
| 身份不可观察的函数值 | 允许消除对象或复用静态实例。                       |
| 间接调用             | 保留一次已知物理签名的间接调用，不引入通用分派器。 |

适配和入口共享不能改变函数严格相等、`name`、`length`、默认参数副作用或 rest 数组的可观察独立身份。需要装箱、堆分配、对象复制、运行时检查或可能失败的返回转换不能由优化器隐式引入。

## 元组

| 场景                 | 优化要求                                     |
| -------------------- | -------------------------------------------- |
| 固定位置访问         | 使用常量偏移并在证明安全时消除边界检查。     |
| 不逃逸小元组         | 允许栈分配、标量替换、寄存器拆分或完全消除。 |
| 固定 tuple rest 参数 | 按普通参数传递，仅在身份可观察时物化。       |
| 固定小元组遍历       | 允许展开循环并消除迭代器和 entry 元组。      |
| 动态异构索引         | 只为实际可能位置生成分支。                   |
| spread 与 rest 解构  | 仅在新身份、别名和写入不可观察时消除复制。   |

优化不能改变 `Array.isArray`、严格相等、optional 实际长度、枚举、字符串转换、写入顺序或动态越界失败。固定元组不得为潜在 rest 预留容量、动态尾部、逐位置 tag 或 offset 表。

## 泛型

普通闭合泛型调用必须生成与手写具体函数相同的调用形态：直接调用、无隐藏类型参数、无泛型字典、无统一装箱、无运行时约束检查，也不因泛型本身分配。

实例只有在以下条件全部相同时才可共享机器码：

- 参数和返回物理 ABI。
- 字段、元素和联合访问布局。
- GC 扫描与写屏障需求。
- 运算、比较、溢出、空值和异常语义。
- 调用约定、接收者及 intrinsic/witness 语义。

共享不能合并静态类型、函数、类或公开 ABI 身份。表示不同或语义不同的实例必须生成独立实现；表示相同的字面量和透明别名实例应优先共享。

有限大量实例先经过规范缓存、代码共享和不可达删除，再执行代码体积预算。一等泛型函数或接口泛型方法的已知目标应去虚化；无法去虚化时保留一次固定槽位读取和间接调用，不引入运行时类型查找。

## 待纳入

字符串、函数、泛型、联合、对象和集合的其他 lowering 策略在对应规范完成职责拆分时纳入。
