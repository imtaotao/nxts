# 类型运行时表示

- 覆盖能力：T45
- 规范状态：已定稿
- 实现状态：未实现
- 最后更新：2026-07-28
- 文档顺序：1

## 目标与边界

本规范把 T01–T44 已确定的语义类型映射为确定的值布局、表示转换需求和后端无关 ABI 分类。布局必须支持精确 GC、跨模块校验和最终接近 Go 的性能目标，同时保持已接受 JavaScript / TypeScript 源码的可观察语义。

本规范不重新定义类型兼容、对象行为、容器 API 或动态检查入口：

| 能力             | 上游规范      | T45 负责                                   |
| ---------------- | ------------- | ------------------------------------------ |
| 空值与联合       | T14、T21、T23 | niche、tag、payload 和容器元素布局         |
| 对象、接口与字典 | T26、T29、T30 | 固定字段、witness、扩展状态和哈希表表示    |
| 函数、数组与元组 | T32–T35       | 函数值、序列头、元素区和调用分类           |
| 类与泛型         | T36–T39       | 类描述符、继承段、闭合实例布局和代码共享键 |
| 断言与转换       | T43–T44       | 表示关系、动态值和运行时检查所需元数据     |

T46 消费本规范产生的 GC 形状并确定扫描与回收机制；T47 消费规范布局记录并确定跨模块 ABI、版本和链接校验。二者不能产生另一套值布局。

## 核心原则

| 原则             | 约束                                                                          |
| ---------------- | ----------------------------------------------------------------------------- |
| 静态专用表示     | 普通值按已确定类型直接表示，不使用统一 JavaScript value 或通用动态盒。        |
| 局部付费         | tag、witness、动态描述符、扩展表和装箱只出现在静态类型确实需要的路径。        |
| 确定布局         | 相同规范类型、目标布局和 ABI 版本必须得到相同大小、对齐、字段偏移和表示类别。 |
| 身份与值语义分离 | 对象身份、字符串值语义和接口视图不能因内部布局优化而改变。                    |
| 精确 GC          | 每个可能保存管理引用的位置和有效状态都必须可由静态 GC 形状描述。              |
| 后端无关         | checker 不依赖机器字段偏移，后端不重新推导语言类型关系。                      |

性能是布局选择的第一优先级。最终目标是常见静态路径达到等价 Go 程序的性能级别；第一版可以接受核心吞吐约为等价 Go 实现的 50%，但不能引入阻止继续优化的统一装箱、动态字段查找或通用调用分派。

## 编译器分层

```text
Parser
  ↓
Bound AST
  ↓
Checked HIR
  ↓
Layout IR
  ↓
Backend
```

| 层级           | 职责                                                                | 禁止事项                               |
| -------------- | ------------------------------------------------------------------- | -------------------------------------- |
| Parser         | 识别 JavaScript / TypeScript 语法并保留源码结构。                   | 决定类型或机器布局。                   |
| Binder         | 建立声明、符号、作用域和导入绑定。                                  | 根据字段偏移解释名称。                 |
| Checker        | 产生语义类型、操作类别、收窄事实和表示需求。                        | 选择字节偏移、指针 tag 或后端类型。    |
| Layout Planner | 产生 `LayoutId`、大小、对齐、字段、tag、niche、GC 形状和 ABI 分类。 | 改变源码类型兼容和可观察行为。         |
| Backend        | 按 Layout IR 生成目标代码。                                         | 重新猜测对象形状、联合成员或转换语义。 |

Checked HIR 中的值至少保留以下信息：

```text
CheckedValue {
  semanticType
  operationKind
  representationRequirement
}
```

Layout IR 把它闭合为：

```text
LayoutValue {
  layoutId
  size
  alignment
  gcShape
  parameterAbi
  returnAbi
}
```

### LLVM 说明

LLVM 只接收已经确定的整数、浮点、指针、结构体、函数签名和控制流。它不理解 Nxts 的接口、可选属性、联合类型或 `unknown`；这些语义必须在进入 LLVM 前由 checker 和布局阶段确定。

## 类型身份与表示身份

语义相同、布局相同和代码可以共享是三个独立判断：

| 身份             | 用途                                  | 示例                             |
| ---------------- | ------------------------------------- | -------------------------------- |
| `SemanticTypeId` | 类型相等、兼容、诊断和收窄。          | 不同品牌具有不同语义身份。       |
| `LayoutKey`      | 大小、对齐、GC、tag 和 ABI 布局缓存。 | 品牌与其底层类型可以共享布局。   |
| `CodeKey`        | 机器码共享和单态化缓存。              | 不同字面量实例可以共享相同实现。 |

共享 `LayoutKey` 不合并语义身份，共享 `CodeKey` 也不合并函数、类、对象或符号的可观察身份。

## 目标布局

布局阶段使用显式 `TargetLayout`，不能读取宿主编译器进程的隐式平台属性：

```text
TargetLayout {
  pointerWidth
  pointerAlignment
  integerAlignments
  floatAlignments
  aggregateAlignment
  endianness
  abiVersion
}
```

当前约束：

| 项目       | 规则                                                         |
| ---------- | ------------------------------------------------------------ |
| 目标位数   | 规范支持 32 位和 64 位目标；第一版实现可以只提供 64 位目标。 |
| 字节序     | 当前 ABI 只支持小端目标。                                    |
| 平台整数   | `usize`、`isize` 与目标指针宽度相同。                        |
| 管理引用   | 大小和对齐等于目标指针；有效对象地址至少 2 字节对齐。        |
| 聚合对齐   | 按目标布局逐字段计算，不使用宿主默认结构体布局。             |
| 自定义布局 | 源码不支持 packed、显式 offset 或用户自定义 alignment。      |

不同 `TargetLayout` 或 ABI 版本的模块不能直接链接；T47 必须在产生可执行程序前拒绝不一致产物。

## 基础布局

### 标量

| 类型                          |     内存大小 | 表示约束                                      |
| ----------------------------- | -----------: | --------------------------------------------- |
| `i8`、`u8`                    |       1 字节 | 完整固定位宽值域。                            |
| `i16`、`u16`                  |       2 字节 | 完整固定位宽值域。                            |
| `i32`、`u32`、`f32`           |       4 字节 | 按目标自然对齐。                              |
| `i64`、`u64`、`f64`、`number` |       8 字节 | 按目标规则对齐；32 位目标不改变宽度。         |
| `isize`、`usize`              |   1 个机器字 | 只随目标位数变化。                            |
| `boolean`                     |       1 字节 | 内存中只使用 `0` 和 `1`，普通字段不按位压缩。 |
| 数字枚举                      |        `i32` | 复用其规范标量表示。                          |
| 字符串枚举                    | 1 个管理引用 | 复用字符串表示。                              |
| `symbol`                      |       8 字节 | 非零 `u64` 身份；零位模式不是合法 symbol。    |

寄存器和表达式中可以使用目标更高效的临时宽度，但落入内存、调用边界或跨模块传递时必须恢复规范布局。`readonly`、透明别名和品牌不改变底层大小、对齐或 GC 形状。

### 零载荷类型

`null`、`undefined`、`void` 和 `never` 不使用普通 payload：

| 类型或位置                       | 表示                                                   |
| -------------------------------- | ------------------------------------------------------ |
| 独立 `null`                      | `ZeroPayload`，大小 0、对齐 1。                        |
| 独立 `undefined`                 | `ZeroPayload`，大小 0、对齐 1。                        |
| `void` 返回                      | 无返回 payload；只表示正常返回。                       |
| `never`                          | 不存在值和正常返回路径。                               |
| 必需的 `null` / `undefined` 字段 | 字段本身可省略 payload，属性仍按对象规则存在并可枚举。 |
| 泛型字段实例化为空值             | 使用同一零载荷规则。                                   |

`null[]` 和 `undefined[]` 只保存数组身份与长度，不分配元素 payload；`null | undefined` 仍需要状态位区分两个成员。`Array<never>` 只能表示长度为零的数组。

## 枚举

枚举复用底层标量布局，不携带名称、`TypeId`、有效性位或枚举描述符：

| 类别       | 规范布局           | GC                     |
| ---------- | ------------------ | ---------------------- |
| 数字枚举   | 一个 `i32`         | 不扫描。               |
| 字符串枚举 | 一个管理字符串引用 | 按普通字符串引用扫描。 |
| 空枚举     | 无可构造值布局     | 不进入普通运行时值。   |

对象字段、元组位置和闭合泛型实例直接使用该布局。数字枚举数组使用连续 `i32`，字符串枚举数组使用连续字符串引用；普通容器路径不装箱，也不携带枚举描述符。

同表示的不同枚举组成联合时，如果语言语义不要求恢复来源身份，则直接复用底层表示。底层值重叠意味着运行时不能区分来源，控制流必须由上游保留全部候选。数字与字符串枚举组成联合时使用一般联合布局。

数字枚举的未使用值可以作为空值 niche，但必须由完整成员集合证明安全。若 `0` 是合法成员，则不能占用零；若 `0` 未使用，单个空值成员可以使用零编码。字符串枚举按管理引用空值规则处理。内部空值编码不能经序列化、反射或 FFI 暴露。

## 运行时值类别

| 值类别                         | 规范值表示                                   | 是否具有引用身份                     |
| ------------------------------ | -------------------------------------------- | ------------------------------------ |
| 原生标量、枚举、symbol         | 直接值                                       | 否；symbol 自身是标量身份。          |
| string                         | 指向不可变字符串存储的管理引用               | 没有用户可观察对象身份，按内容比较。 |
| 精确对象、类、数组、元组、字典 | 指向稳定逻辑对象的管理引用                   | 是。                                 |
| 函数值                         | 闭包身份/环境 + 类型化入口                   | 是。                                 |
| 接口值                         | `dataRef + witness`                          | 沿用 `dataRef` 身份。                |
| 联合值                         | niche、现有判别、指针 tag 或 `tag + payload` | 取决于当前成员。                     |
| `unknown`                      | `dynamicDescriptor + payloadWord`            | 按动态成员语义。                     |

管理引用是直接机器指针，不经过全局 handle 表。T46 可以选择移动 GC，但必须保证重定位和引用更新，不得因此改变字段访问或调用 ABI。

不可观察的对象、数组、元组、字典、闭包和动态盒可以通过逃逸分析、标量替换或死分配消除；可观察身份存在时必须保留唯一性。

## 管理引用与 niche

非空管理引用的有效地址低位为零。布局阶段只能使用 ABI 明确声明的保留编码：

| 静态类型                             | 优先编码                                                  |
| ------------------------------------ | --------------------------------------------------------- |
| `T \| null`，`T` 为非空管理引用      | 一个机器字；零表示 `null`。                               |
| `T \| undefined`，`T` 为非空管理引用 | 一个机器字；零表示 `undefined`。                          |
| `T \| null \| undefined`             | 零表示 `undefined`，一表示 `null`，其余合法编码表示 `T`。 |
| 不满足安全 niche 的类型              | 使用独立状态和 payload。                                  |

相同位模式可以在不同静态类型中表示不同空值，但同一规范类型内的所有成员必须可区分。标量合法值域不能为了制造 niche 被缩小；指针 tag 和保留编码必须进入 `LayoutRecord` 与 GC 形状。

## 描述符分类

Nxts 不使用每个值都携带的万能描述符。元数据按实际能力拆分：

| 元数据                  | 生命周期与用途                                             |
| ----------------------- | ---------------------------------------------------------- |
| `SemanticType`          | 仅编译期使用，保存语言类型关系。                           |
| `ValueLayout`           | 编译与链接期使用，保存规范机器布局。                       |
| `GcDescriptor`          | 按布局共享；T45 提供逻辑 GC 形状，T46 确定编码和扫描。     |
| `ClassDescriptor`       | 每个运行时类身份使用，保存类身份、继承和方法槽位。         |
| `WitnessTable`          | 仅接口契约使用，保存预生成成员访问和方法入口。             |
| `DynamicDescriptor`     | 仅 `unknown` 和受信任动态检查使用。                        |
| `EnumerationDescriptor` | 按对象或类分配形态共享，保存逻辑枚举顺序。                 |
| `FunctionDescriptor`    | 按函数签名或入口共享，保存 `name`、`length` 和检查元数据。 |

普通精确对象不需要仅为固定字段访问携带对象头或描述符指针。GC、显式反射或运行时检查需要描述符时，可以从静态操作数、分配元数据、类描述符或动态容器中获得。

## 精确对象布局

### 固定字段

普通精确对象由固定字段区域、可选存在位和按需扩展定位组成。字段物理顺序不等于源码初始化或枚举顺序。

同一固定区域内按以下顺序布局：

1. 先放置管理引用字段。
2. 再按对齐和大小从高到低放置非引用字段。
3. 同一类别使用规范属性身份作为稳定次序。
4. 固定字段之后放置该区域的可选存在位。
5. 只有该分配形态需要动态扩展能力时才放置扩展引用。

布局算法不得依赖源码字段顺序、编译器哈希表遍历顺序、优化级别、调试信息或性能采样。源码初始化顺序由控制流保存；属性枚举顺序由独立 `EnumerationDescriptor` 保存。

没有固定字段的精确空对象仍具有独立对象身份，必须获得可区分的最小逻辑分配。共享描述符或零字段布局不能合并两个可通过 `===` 观察的对象；身份不可观察时才允许消除分配。

### 可选属性

可选属性使用固定 payload 槽位和紧凑存在位：

```text
OptionalField {
  payload: T
  present: 1 bit in shared presence storage
}
```

| 操作                   | 表示行为                               |
| ---------------------- | -------------------------------------- |
| 初始缺失               | 清除存在位；引用 payload 保持零。      |
| 写入                   | 先写入有效 payload，再设置存在位。     |
| `delete`               | 清除存在位；引用 payload 同时清零。    |
| 存在但值为 `undefined` | 存在位为真，payload 表示 `undefined`。 |

没有可选属性的对象不携带存在位。必需字段读取不执行存在检查；可选字段读取只执行对应状态位检查，不查询哈希表。

初始属性次序按分配点描述符共享。首次晚写入的可选属性和删除后重新写入的属性需要记录实例级追加顺序；紧凑顺序空间耗尽时可以按需创建侧状态。未发生晚写入或重加的对象不承担该状态成本。

### 扩展状态

动态扩展能力按使用情况选择：

| 场景                                     | 定位方式                                  |
| ---------------------------------------- | ----------------------------------------- |
| 只有静态可选属性                         | 直接使用固定 payload 与存在位。           |
| 分配点已知可能进入接口可写扩展或字典能力 | 在固定前缀后保存一个可空 `extensionRef`。 |
| 跨模块传入且原布局没有扩展槽             | 使用按对象身份附着的稀疏侧表。            |
| 从未使用扩展能力                         | 不增加实例字段、哈希表或普通访问分支。    |

`extensionRef` 可以容纳有限接口扩展、字典条目、shadow 和 tombstone 的类型化区域，但各能力保持独立权限和 GC 描述。侧表不能保持已不可达对象存活，其弱键或等价机制由 T46 确定。

## 类实例布局

类实例始终以一个 `ClassDescriptor` 指针开头，随后按继承层级形成稳定分段：

```text
ClassInstance
├─ classDescriptor
├─ BaseSegment
│  ├─ reference fields
│  ├─ scalar fields
│  └─ base optional bits
├─ DerivedSegment
│  ├─ reference fields
│  ├─ scalar fields
│  └─ derived optional bits
└─ dynamic extension slot?
```

每个类层级只排列自身声明的字段和存在位。基类段在全部派生类中保持相同偏移；基类方法读取可选字段时不依赖最终派生类大小。派生类到基类转换保持同一对象地址，不复制字段、不裁剪对象，也不调整指针。

继承链只保留一个有效动态扩展定位。基类已有扩展槽时派生类复用；仅派生类首次引入索引签名或其他扩展能力时，扩展槽位于该派生段之后。普通继承不增加动态哈希表。

`ClassDescriptor` 至少提供：

| 信息               | 用途                                     |
| ------------------ | ---------------------------------------- |
| 类身份和祖先摘要   | `instanceof`、`constructor` 和继承检查。 |
| 实例大小与 GC 形状 | 分配和精确扫描。                         |
| 展平方法槽位       | 固定 O(1) 虚调用。                       |
| 枚举描述引用       | 恢复实际实例属性顺序。                   |
| 布局与契约指纹     | T47 跨模块校验。                         |

静态字段属于运行时类身份，不进入每个实例。不同闭合泛型实例可以具有不同实例布局和入口，但仍共享 T36 定义的运行时类家族身份。

## 序列与集合

### 通用序列前缀

数组与元组共享逻辑序列前缀，但只有数组具有容量：

```text
SequencePrefix {
  data: pointer
  length: i32
}

ArrayObject {
  sequence: SequencePrefix
  capacity: i32
}

TupleObject {
  sequence: SequencePrefix
}
```

字段物理顺序与填充由 `TargetLayout` 确定。元组不保存 `capacity`，也不为潜在增长预留动态尾部。

| 集合                                      |       用户可见数量上限 | 内部计算                                          |
| ----------------------------------------- | ---------------------: | ------------------------------------------------- |
| string code unit、数组元素、rest 元组元素 |             `i32::MAX` | 字节数和地址使用 checked `usize`。                |
| 字典有效条目                              |             `i32::MAX` | 桶容量和分配大小使用 checked `usize`。            |
| 精确对象和类                              | 无较小语言级字段数上限 | 总布局必须能由目标 `usize` 和运行时对象上限表示。 |

动态创建超过上限时必须在修改可观察状态前抛出 `RangeError`。静态不可能布局在编译期报错。

### 数据区分配

规范布局通过 `data` 和元素布局定位连续数据。对象头与数据区是否同块分配、扩容时如何迁移、空数据区是否共享以及是否栈分配，均不能改变该访问形态和对象身份。

分配、扩容与迁移算法由 [`2-arrayRuntime.md`](../../runtime/objects/2-arrayRuntime.md) 定义；栈分配和标量替换由 [`1-loweringStrategies.md`](../optimizer/1-loweringStrategies.md) 定义；GC 可移动性由 [`1-gcTypeDescriptors.md`](../../runtime/gc/1-gcTypeDescriptors.md) 定义。

### 数组元素布局

数组元素在实例化前必须具有固定规范布局：

| 元素类型                       | 规范存储                                                |
| ------------------------------ | ------------------------------------------------------- |
| `null` 或 `undefined`          | 只保存数组长度，无元素 payload。                        |
| `null \| undefined`            | 每个元素使用 1 位状态，无元素 payload。                 |
| `boolean \| null` 等紧凑小状态 | 每个元素使用足够的紧凑状态位或字节。                    |
| `ObjectRef \| null`            | 连续一个机器字引用，复用空指针 niche。                  |
| `i32`、`f64` 等普通固定类型    | 连续无装箱 payload。                                    |
| `i32 \| null`                  | 连续 `i32` payload 区 + 每元素 1 位状态。               |
| `i32 \| null \| undefined`     | 连续 `i32` payload 区 + 每元素 2 位状态。               |
| 一般异构联合                   | 独立连续 tag 平面 + 按最大布局对齐的连续 payload 平面。 |

状态平面与 payload 平面属于同一个元素缓冲区分配，容量同时覆盖全部平面。编译器应把各平面基址和循环不变量提升到循环外；普通索引不能逐元素装箱或查询动态类型表。

inactive 引用 payload 必须清零。GC 依据状态平面只扫描当前有效引用；标量平面不执行写屏障。

### 元组

元组始终是具有 JavaScript 数组身份行为的稳定管理引用：

| 类别         | 表示                                               |
| ------------ | -------------------------------------------------- |
| 同构固定元组 | 连续同一元素布局，可零复制形成 readonly 数组视图。 |
| 异构固定元组 | 编译期固定槽位与偏移。                             |
| 可选元组     | 最大槽位布局 + 实际 `length` 作为合法成员判别。    |
| rest 元组    | 固定前缀、重复元素区和固定后缀的确定布局。         |

固定元组不携带逐位置 tag 或 offset 表。动态异构索引可以按实际位置选择固定槽位并构造结果联合，但不改变底层元组表示。

全部位置均为零载荷类型的元组仍保留元组身份和实际长度，但不需要元素 payload 区。

## 字符串表示

`string` 使用不可变值语义和 GC 管理存储。规范逻辑头为：

```text
StringStorage {
  lengthAndEncoding: u32
  cachedHash: u32
  data: inline Latin1 or UTF16 code units
}
```

`lengthAndEncoding` 保存不超过 `i32::MAX` 的 UTF-16 code unit 长度和 Latin-1 / UTF-16 编码位。`cachedHash` 使用运行时私有的未计算标记；惰性写入哈希缓存不改变语言可观察的字符串不可变性。

字符串对象可以包含运行时私有可变缓存，因此“静态字符串”表示共享且不可修改的 code unit 内容，不要求整个存储对象位于操作系统只读页。

创建、索引、比较、哈希、子串和拼接算法见 [`1-stringRuntime.md`](../../runtime/objects/1-stringRuntime.md)。UTF-16 可观察语义见 [`2-stringSemantics.md`](../../language/semantics/2-stringSemantics.md)，公开转换与方法见 [`10-string.md`](../../stdlib/10-string.md)，外部编码与所有权见 [`1-ffiTypes.md`](../../interop/1-ffiTypes.md)。

## 字典表示

原生字典是指向稳定字典对象的管理引用。逻辑对象保存当前表引用和 `i32` 有效条目数；表元数据保存 checked `usize` 容量、迁移状态、随机 salt 和顺序信息。

键和值按闭合类型专用：

| 部分         | 表示                                                         |
| ------------ | ------------------------------------------------------------ |
| 字符串键     | 保存字符串引用和缓存的进程密钥哈希；最终命中仍比较完整内容。 |
| 数组索引键   | 直接保存 `u32` 数值，不分配格式化字符串。                    |
| 标量值       | 在桶 payload 中直接存储，不装箱。                            |
| 引用或联合值 | 使用对应规范布局与精确 GC 形状。                             |
| 空字典       | 保留唯一字典身份，可以共享不可变空表。                       |

哈希、扩容、迁移、删除和枚举算法由 [`4-dictionaryRuntime.md`](../../runtime/objects/4-dictionaryRuntime.md) 唯一定义。语言可观察的 key 规范化、顺序和身份由 [`5-dictionarySemantics.md`](../../language/semantics/5-dictionarySemantics.md) 定义。

## 函数值

一等函数值使用两个机器字：

```text
FunctionValue {
  closureIdentityOrEnvironment
  typedEntry
}
```

`closureIdentityOrEnvironment` 保存可观察函数身份和捕获环境定位；`typedEntry` 是已经闭合参数与返回 ABI 的入口。严格相等比较闭包身份，不只比较代码地址。

已知直接调用可以绕过函数值并调用静态入口。无捕获函数可以使用共享静态身份；只捕获接收者的箭头函数可以使用接收者作为环境。是否物化闭包和捕获环境由逃逸与 T58 规则确定，不改变二字函数值 ABI。

函数 `name`、`length`、按需类型化入口和受信任动态检查信息通过稳定身份共享 `FunctionDescriptor`。多个入口不能扩大函数值本身，也不能改变严格相等。Nxts 不支持 `arguments`，因此函数值不为参数反射保存通用值数组。runtime 逻辑结构见 [`2-functionRuntime.md`](../../runtime/values/2-functionRuntime.md)。

### LLVM 说明

LLVM 直接调用使用固定函数目标，间接调用从函数值取得类型化代码入口。两者的参数和返回布局都必须完全匹配；Nxts 在进入 LLVM lowering 前完成参数数量和返回表示适配，因此 LLVM IR 不需要模拟 JavaScript 动态实参数组。

## 接口值

接口值固定为两个机器字：

```text
InterfaceValue {
  dataRef
  witness
}
```

`dataRef` 指向实际对象或类实例；`witness` 指向编译期生成的契约表。接口视图的 `===`、`!==` 和对象身份使用 `dataRef`，不比较 witness。

接口成员访问通过固定 witness 槽位完成，不扫描成员名。具体来源和目标契约静态已知时，编译器可以去除打包或 witness 间接调用。接口当前只由引用对象实现，不支持标量实现或为标量隐式装箱。

可空接口优先使用 `dataRef` 的安全 niche；空状态下 witness 不得被读取。接口到上位接口的 repack 只重写固定大小视图，不分配对象或复制底层数据。

## 联合类型表示

布局阶段在联合规范化后按固定优先级选择表示：

| 优先级 | 条件                                                       | 表示                           |
| -----: | ---------------------------------------------------------- | ------------------------------ |
|      1 | 归一化后只剩一个成员，或成员表示可安全合并且不需要恢复来源 | 直接复用成员表示。             |
|      2 | 存在安全空值或无效编码 niche                               | 使用 niche，不增加外层 tag。   |
|      3 | 值内已有稳定且无歧义的判别信息                             | 复用现有判别，不增加外层 tag。 |
|      4 | 管理引用缺少现有判别且安全低位可用                         | 使用指针低位 tag。             |
|      5 | 其他联合                                                   | 使用内联 `tag + maxPayload`。  |

可复用判别包括：

- readonly 或稳定字面量判别字段。
- 类描述符和对象种类描述。
- 容器种类或规范布局身份。
- 互不重叠的封闭枚举值。
- 已有内层联合 tag。

判别字段必须在值存活期间保持稳定；可写普通字段不能作为无外层 tag 的唯一依据。重叠值域的枚举成员不能通过值恢复来源；只有上游联合语义不要求保留该来源时才能合并表示。

一般 `tag + payload` 在值内联保存最大成员 payload，不为联合单独分配堆对象。inactive 引用槽位清零，GC 按 tag 扫描当前成员。表示选择只由规范类型、目标布局和 ABI 版本决定。

规范成员按稳定 `SemanticTypeId` 键排序，tag 由该顺序分配，不按源码成员顺序、别名展开顺序或哈希遍历顺序分配。规范化后只有一个成员时直接使用成员布局，不保留联合包装。

tag 使用能覆盖物理可区分状态的紧凑整数宽度；payload 只容纳最大活动成员并满足其对齐，不同时保存每个成员。已知状态、注入后立即收窄和同布局 repack 必须可由优化器消除。

动态打包必须能恢复当前具体成员的 `DynamicDescriptor`。使用现有对象判别的联合在进入 `unknown` 时读取一次固定判别或对象描述，之后 `isType` 只查询动态描述符，不重复扫描字段。

## 交叉类型

交叉类型没有独立运行时表示。布局阶段只接收 checker 已规范化的具体基础值、精确对象、接口契约、联合、类、容器或 `never`：

- 对象交叉使用合并后的单一精确对象布局。
- 接口交叉使用规范接口值与 witness。
- 联合分配结果使用普通联合布局。
- 品牌交叉特例复用底层布局。
- `never` 不产生值布局。

布局阶段不得创建交叉 tag、对象合并包装或运行时成员检查。

## `unknown` 动态表示

`unknown` 是显式动态边界，不是所有值的公共底层表示。其规范值固定为两个机器字：

```text
UnknownValue {
  dynamicDescriptor
  payloadWord
}
```

| 动态成员                           | payload                                              |
| ---------------------------------- | ---------------------------------------------------- |
| 不超过一个机器字的标量             | 直接内联位模式。                                     |
| 对象、类、数组、元组、字典、字符串 | 直接保存管理引用。                                   |
| 接口                               | 保存底层 `dataRef`，描述符恢复实际具体类型。         |
| 函数                               | 保存闭包身份引用，描述符恢复函数签名和入口。         |
| 大于一个机器字的聚合               | 在显式动态打包边界分配类型化盒。                     |
| 品牌值                             | 使用底层类型动态身份；品牌不形成可伪造的运行时证据。 |

全零 `UnknownValue` 表示 `undefined`，使 GC 安全零初始化具有确定状态。其他空值和标量由规范动态描述符解释。

64 位目标可直接内联 `i64`、`u64`、`f64` 和 `number`。32 位目标保持相同二字 ABI，这些 64 位标量进入 `unknown` 时使用类型化盒；普通静态数值代码和 64 位目标不承担该成本。统一扩大所有 `unknown` 会增加常见 64 位平台的复制与缓存成本，因此不采用三字表示。

`DynamicPack`、`CheckedTypeTest` 和成功后的类型化 payload 必须在 Checked HIR 与 Layout IR 中显式存在。运行时检查使用描述符、类身份或预生成 witness，不通过字符串名称、成员扫描或用户自定义类型谓词猜测类型。

## 递归类型

递归类型不创建专用运行时包装。每个节点复用所属类型构造的布局；布局计算遇到固定大小的引用间接层时记录引用槽位并停止展开目标。

| 类型构造                                                | 是否提供运行时间接层                            |
| ------------------------------------------------------- | ----------------------------------------------- |
| 精确对象、类实例、数组、元组、字典、函数、闭包和接口值  | 是                                              |
| 联合、交叉、透明别名、`null`、`undefined` 和 `readonly` | 否                                              |
| 标准库容器                                              | 仅在其规范明确固定大小引用 ABI 和 GC 行为时为是 |

编译器内部必须由各类型构造显式提供 `isRuntimeIndirection` 或等价布局属性，不能根据类型名称猜测，也不能插入隐藏 `Box` 使透明递归通过检查。不经过允许间接层的无限大小递归由 T31 在进入布局阶段前拒绝。

例如：

```ts
type Node = {
  value: i32;
  next: Node | null;
};
```

概念布局为：

```text
Node object
├─ value: i32
└─ next: nullable object reference
```

`Node | null` 复用可空引用 niche，不增加联合 tag。包含多个表示类别的递归联合复用普通联合的 tag 和 payload，不增加递归包装。

布局与语义类型身份分离。不同递归实例具有相同机器布局时可以共享 `LayoutRecord`，但不能因此在 checker 中成为同一类型。

LLVM 只接收有限结构和普通指针，上例概念上等价于：

```llvm
%Node = type { i32, ptr }
```

LLVM 不负责递归合法性、空值联合、对象身份或 GC 语义。

递归能力本身必须保持零额外运行时成本：字段访问沿用所属类型的固定偏移或原生容器路径，调用沿用直接、间接或接口调用，不增加递归深度计数、动态类型展开、结构相等扫描、统一装箱或运行时泛型参数表。链表、树和图的分散分配及缓存局部性成本属于所选数据结构，不是递归类型检查附加的成本。

## 泛型

泛型运行时布局必须在进入 Layout IR 前闭合：

| 项目       | 规则                                                     |
| ---------- | -------------------------------------------------------- |
| 类型实参   | 每个运行时实例具有具体 `SemanticTypeId` 和 `LayoutKey`。 |
| 字段与元素 | 使用闭合实参的直接规范布局。                             |
| 普通调用   | 不携带运行时类型参数、泛型字典或统一盒。                 |
| 代码共享   | 仅当操作语义、布局、GC 和 ABI 全部兼容时共享 `CodeKey`。 |
| 泛型类     | 不同布局实例保留同一运行时类家族身份。                   |

动态多态必须通过已经定义的接口、联合或显式 `unknown` 表示，不得由未闭合类型参数隐式产生。

无法去虚化的一等泛型函数值仍使用两个机器字：身份/环境引用和固定专门化表引用。接口泛型方法的闭合槽位存放在 witness 描述中，不扩大接口值。具体 runtime 调用路径见 [`3-polymorphicFunctionRuntime.md`](../../runtime/values/3-polymorphicFunctionRuntime.md)。

## 高级类型结果

条件类型、`infer`、映射类型、模板字符串类型和标准类型工具没有专用运行时表示。布局阶段只消费最终规范类型：

| 最终结果                 | 表示                                   |
| ------------------------ | -------------------------------------- |
| `Readonly<T>` 且布局相同 | 原值的静态只读视图。                   |
| 闭合条件得到具体类型     | 直接使用该类型布局。                   |
| 联合                     | 只使用普通联合表示。                   |
| `Partial<T>`             | 使用最终对象或元组的 optional 状态。   |
| 有限 `Record` / 映射对象 | 普通固定对象布局。                     |
| 宽 `Record<string, V>`   | 原生字典布局。                         |
| 模板和大小写字符串类型   | 普通字符串布局，不保存模式或证明标签。 |

LLVM 只接收最终整数、浮点、指针、结构体和函数签名。高级类型的分支、映射和字符串证明必须在 lowering 前消失，LLVM 不重新判断类型级关系。

## 静态值与字面量

| 值                                  | 存储与身份规则                         |
| ----------------------------------- | -------------------------------------- |
| 数值、boolean、枚举、symbol 常量    | 直接内联到指令或静态数据。             |
| 字符串字面量                        | 共享静态字符串存储。                   |
| 布局、类、witness、函数和枚举描述符 | 使用只读或运行时私有静态元数据。       |
| 模块级可变值                        | 使用 GC 可识别的模块根。               |
| 对象、数组、元组字面量              | 每次实际求值创建独立可观察身份。       |
| 函数与类表达式                      | 按 T32、T36 保留每次求值的运行时身份。 |

`readonly` 和 `as const` 不授权合并可观察对象身份。只有证明 `===`、别名写入、枚举、反射和逃逸均不可观察时，优化器才能共享或消除分配。

## 零初始化与有效值

每种布局必须具有 GC 安全的全零内存状态，但该状态不一定是源码可读取的合法值：

| 布局                         | 全零含义                          |
| ---------------------------- | --------------------------------- |
| 整数、浮点                   | 数值零。                          |
| boolean                      | `false`。                         |
| 可空管理引用                 | 对应静态类型声明的空值成员。      |
| `unknown`                    | `undefined`。                     |
| 可选属性                     | 属性缺失。                        |
| 数字枚举                     | 仅当零是合法成员时为有效值。      |
| 非空引用、函数、接口、symbol | GC 安全但不是可读取的合法源码值。 |

确定赋值分析不能因内存已经清零而放宽。堆对象在对 GC 可见前必须把所有引用区域初始化为可扫描状态；栈槽只在控制流证明已初始化后进入精确根集合。

## 分配与失败

| 场景                               | 失败行为                                              |
| ---------------------------------- | ----------------------------------------------------- |
| 静态类型大小无法由目标表示         | 编译错误。                                            |
| 动态长度、容量或条目数超过语言上限 | 修改任何可观察状态前抛出 `RangeError`。               |
| `usize` 字节数乘加溢出             | 与超长创建相同，不能截断或回绕后分配。                |
| 真实内存耗尽                       | runtime 不可恢复失败；具体入口和清理边界由 T46 定义。 |

分配函数不能用空指针表示普通可恢复结果，也不能发布部分初始化对象。显式动态打包、字典增长和容器创建必须在 IR 中保留可能分配或失败的事实。

## 抽象调用 ABI

T45 定义后端无关的值传递分类：

| 值布局                      | 参数与返回分类                       |
| --------------------------- | ------------------------------------ |
| 标量与单个管理引用          | 直接传递。                           |
| 函数、接口、`unknown`       | 两个机器字直接传递。                 |
| 不超过两个机器字的小聚合    | 直接传递。                           |
| 更大的固定聚合              | 通过调用方提供的间接存储传递或返回。 |
| `null`、`undefined`、`void` | 不传递 payload。                     |
| `never`                     | 不存在正常调用或返回边。             |

间接传递只使用调用方或现有对象存储，不得仅因聚合较大而强制堆分配。参数求值、副作用和源码参数数量仍按 T32 语义执行，即使某个零载荷参数不占机器 ABI 槽位。

T47 将该分类映射为跨模块稳定调用 ABI；runtime 和标准库私有入口也必须经过独立 ABI lowering，不能直接暴露后端内部类型。

## 表示关系

checker 查询后端无关的：

```text
RepresentationRelation(source, target, context)
```

结果分类：

| 结果                   | 含义                                                 |
| ---------------------- | ---------------------------------------------------- |
| `NoOp`                 | 位模式、身份、GC 和调用表示完全不变。                |
| `InlineRepack`         | 固定大小、无失败、无循环且不分配的字段或 tag 重排。  |
| `StaticAdapter`        | 使用预生成静态入口或 witness，不创建运行时包装对象。 |
| `RequiresAllocation`   | 需要复制、容器重建或动态盒。                         |
| `RequiresRuntimeCheck` | 需要检查且可能失败。                                 |
| `Unsupported`          | 语义或布局不允许转换。                               |

普通隐式转换只接受上游规范明确授权的 `NoOp`、`InlineRepack` 或 `StaticAdapter`。其中：

| 场景                      | 必需关系                                |
| ------------------------- | --------------------------------------- |
| mutable 到 readonly 视图  | `NoOp`。                                |
| 接口打包与上位接口 repack | 固定大小 `InlineRepack`。               |
| 安全函数适配              | 无分配 `StaticAdapter`。                |
| 可变容器元素兼容          | 元素必须 `NoOp` 且写入安全。            |
| readonly 容器协变         | 元素必须 `NoOp` 且布局、对齐、GC 相同。 |

隐式路径不能隐藏分配、循环、失败、数值精度变化或对象重建。其他结果必须使用 T44 定义的显式转换、动态打包或受信任检查。

## `LayoutRecord`

每个闭合运行时类型产生确定的规范记录：

```text
LayoutRecord {
  representationKind
  targetLayoutId
  abiVersion
  size
  alignment
  fields
  presenceBits
  unionEncoding
  niches
  gcShape
  parameterAbi
  returnAbi
}
```

字段记录包含规范字段身份、偏移、大小、对齐和子布局；联合记录包含规范成员到状态的映射。具体属性枚举顺序保存在独立 `EnumerationDescriptor`，不参与固定字段布局身份。

布局指纹由规范序列化后的 `LayoutRecord` 计算，不包含源码路径、调试信息、性能采样、编译器遍历顺序或不可观察的优化选择。链接器不能只信任哈希相等；发生指纹命中时仍可比较规范记录或经过认证的摘要。

私有且只在单个全程序优化单元中使用的值可以采用更紧凑的临时表示，但模块边界、地址逃逸和公开调用前必须恢复规范布局。优化不能改变诊断、身份、枚举或 GC 可观察结果。

## T45、T46 与 T47 的职责

| 章节               | 负责内容                                                                                | 不负责内容                         |
| ------------------ | --------------------------------------------------------------------------------------- | ---------------------------------- |
| T45 类型运行时表示 | 值大小、对齐、字段布局、tag、niche、接口视图、容器头、表示关系、抽象传参和 GC 形状。    | 具体回收器算法和跨模块版本政策。   |
| T46 GC 类型描述    | 把 GC 形状编码为精确扫描描述，定义移动、写屏障、安全点、弱引用、ephemeron 和 OOM 行为。 | 改变语言值布局。                   |
| T47 跨模块 ABI     | 导出类型身份、符号名、布局指纹、witness/描述符 ABI、版本兼容和链接拒绝规则。            | 重新决定单个类型的字段与联合表示。 |

T46、T47 只能消费 T45 的 `LayoutRecord`。布局不一致必须在链接或模块加载前失败，不能运行后再通过字符串名称、字段扫描或动态重建适配。

## 与 TypeScript / JavaScript 的差异

| 场景      | TypeScript / JavaScript                          | Nxts                                        |
| --------- | ------------------------------------------------ | ------------------------------------------- |
| 普通值    | JavaScript 引擎使用动态值表示。                  | 按静态类型使用原生专用布局。                |
| 对象属性  | 动态 shape、原型和字典模式。                     | 固定字段偏移；显式能力才使用扩展状态。      |
| 数组元素  | 可能发生 elements-kind 转换和装箱。              | 创建时固定元素布局，不发生动态种类迁移。    |
| 接口      | TypeScript 擦除。                                | 使用 `dataRef + witness` 实现静态契约调用。 |
| 联合      | TypeScript 擦除，JavaScript 值自行携带动态种类。 | 使用 niche、现有判别或固定 tag。            |
| `unknown` | 与普通 JavaScript value 使用相同底层值。         | 仅显式动态边界使用二字描述符表示。          |
| 泛型      | 运行时通常擦除到 JavaScript 动态值。             | 闭合后专用布局或安全共享机器码。            |

这些差异改变内部表示或缩小 TypeScript strict 的源码接受范围，不允许 Nxts 为相同的已支持 JavaScript 表达式定义相反的可观察求值、身份或枚举结果。

## 性能验收

实现至少分别测量：

| 路径                     | 重点指标                                   |
| ------------------------ | ------------------------------------------ |
| 标量、固定字段和直接函数 | 指令数、吞吐和是否存在装箱或动态查询。     |
| 类字段与虚调用           | 固定偏移、槽位调用成本和继承深度影响。     |
| 数组、元组和字符串       | 分配次数、连续访问、边界检查和缓存局部性。 |
| 联合与可空值             | tag/niche 分支、循环外提升和 GC 扫描成本。 |
| 接口与 `unknown`         | 打包成本、去虚化、装箱次数和检查延迟。     |
| 字典                     | 平均查找、渐进扩容、攻击性碰撞和枚举成本。 |

普通静态标量、固定对象字段、同构数组元素和直接函数调用必须不存在通用值装箱。未使用接口、`unknown`、字典或动态扩展能力的程序不能为这些能力预付实例空间、分支或哈希成本。

## 诊断与测试

静态诊断至少覆盖：

| 场景                               | 预期结果                       |
| ---------------------------------- | ------------------------------ |
| 类型布局超过目标可表示范围         | 编译错误并指出目标限制。       |
| 隐式转换需要分配、循环或运行时检查 | 编译错误并指出所需显式操作。   |
| 跨目标或 ABI 版本布局不一致        | T47 链接前拒绝。               |
| 无法闭合的泛型运行时类型           | 进入 Layout IR 前编译错误。    |
| 不安全 niche 或 tag 冲突           | 布局错误，不能退化为猜测编码。 |

生成代码和 runtime 测试至少覆盖：

| 场景                               | 预期结果                                |
| ---------------------------------- | --------------------------------------- |
| 空值引用、标量空值联合和多成员联合 | 成员可区分且不产生意外装箱。            |
| 同表示字面量与名义成员联合         | 不增加无语义需求的外层 tag。            |
| 联合成员换序和透明别名展开         | 得到相同 tag 映射、payload 与 GC 形状。 |
| 可选属性缺失、写入、删除和重加     | 存在性、枚举顺序和引用清理正确。        |
| 深继承类读取基类可选字段           | 使用稳定基类段偏移和存在位。            |
| 数组各元素布局与扩容               | 身份稳定、payload 连续、GC 精确。       |
| 同构和异构元组                     | 无容量字段，索引和 readonly 视图正确。  |
| 32 位 `i64` / `f64` 动态打包       | 只在进入 `unknown` 时装箱。             |
| 字典碰撞攻击                       | 启动强化重哈希且保持正确结果。          |
| 不可达递归对象图                   | T46 可以按逻辑 GC 形状回收。            |

| 依赖    | 本规范使用的结论                               |

## 待确认项

T45 没有待确认项。GC 描述符的二进制编码、回收算法、屏障、安全点、弱引用和 OOM runtime 入口属于 T46；跨模块元数据格式、符号编码和 ABI 版本兼容属于 T47。
