# 编译期常量求值

- 规范状态：部分定稿
- 最后更新：2026-07-28
- 文档顺序：6

## 目标与边界

本规范定义前端常量求值的内部数值能力、资源边界和向语言类型的提交条件。常量求值不能扩展源码类型集合。

## 任意精度内部整数

编译器可以在字面量解析、常量表达式和越界检查中使用任意精度整数，但该内部值：

- 不能成为 Nxts 语义类型或运行时值。
- 不能进入 Checked HIR 或 Layout IR。
- 必须在提交前验证为目标 `number`、定宽整数或平台整数。
- 超出目标范围时产生编译错误，不能自动改用 bigint。

bigint 字面量虽然可由 Babel 解析，也不能借内部任意精度实现获得语言值。

常量值分派必须可扩展，不能假定所有内部整数都能装入 64 位；该内部表示仍不得泄漏到 Checked HIR。

## 字符串常量

前端保留 cooked UTF-16 code unit 值，可以折叠全常量字符串索引、比较、拼接和无插值/全常量模板。折叠结果必须与 runtime 的 UTF-16、数值格式和长度上限规则一致。

常量折叠不能越过可能抛错或具有副作用的动态表达式，也不能用宿主区域设置或默认浮点格式替代 Nxts 规范格式。结果超过 `i32::MAX` code unit 时编译报错，不生成截断值。

大小写类型与值 intrinsic 使用工具链固定 Unicode 版本。编译时折叠后的内容和 runtime 转换必须一致。

## 资源边界

完整的最大常量位数、表达式深度、求值步数、缓存和诊断策略待常量求值器设计时确定。资源限制必须确定且可诊断，不能使编译器因恶意常量输入失控。
