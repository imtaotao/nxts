# Checker 语义模型

- 规范状态：部分定稿
- 最后更新：2026-07-28
- 文档顺序：5

## 目标与边界

本规范定义 checker 内部规范类型、驻留、关系缓存、复杂度预算和 Checked HIR 输出。它不能改变语言类型规则。

## 类型别名与品牌

别名符号分别记录“未解析、解析中、已解析”状态。普通透明别名展开到目标规范类型；递归别名建立有限类型图回边；泛型别名按规范实参驻留替换结果。缓存不能把持续增长的实例链误判为递归闭包。

`Brand<T, Tag>` 保留独立语义类型身份和底层类型关系，不能被普通交叉类型路径伪造。诊断优先展示源码别名名称，并在需要时附带最短展开路径；诊断名称不参与类型相等、布局或 ABI。

## 联合类型

联合规范化使用驻留 `TypeId`、稳定规范键和集合算法，避免无必要的结构两两比较。处理顺序由 T21 决定，checker 负责确定实现和缓存。

官方编译器必须至少支持规范化后包含 `65535` 个简单成员的平坦联合。简单成员指可按规范身份排序、去重，且不要求结构子类型两两比较或类型级笛卡尔展开的成员。

复杂操作使用独立确定预算：

| 复杂度来源           | 实现要求                           |
| -------------------- | ---------------------------------- |
| 规范身份排序与去重   | 使用驻留 ID 和集合算法。           |
| 结构子类型吸收       | 使用关系预算、缓存和循环检测。     |
| 泛型或高级类型展开   | 独立限制深度、实例数和结果成员数。 |
| 穷尽检查与控制流排除 | 使用规范集合、位集或等价有界表示。 |

预算在同一工具链版本内必须确定，不能依赖优化级别、目标机器速度或遍历偶然顺序。耗尽时报告触发操作，不能删除成员、widening、改用 `unknown` 或动态表示。

## 交叉类型

平坦交叉使用规范身份集合和已缓存下位关系。对象形状按规范属性键合并，同名属性递归计算交叉；顶层联合分配复用联合结果成员预算；递归类型使用 T31 类型图回边。

泛型实例化后必须把符号交叉消解为基础值、精确对象、接口契约、联合、类、容器或 `never`。无法闭合时在进入 Checked HIR 前报错。

复杂度耗尽不能省略约束、扩大结果、改用动态表示或把尚可满足的交叉错误归为 `never`。

## 接口契约

接口规范化使用成员键和成员种类索引，展平继承后驻留结构契约。结构相同的不同名称接口共享契约 `TypeId`，具体对象类型仍保持独立身份。

结构化实现、继承冲突、泛型实例化和递归契约比较使用缓存关系与循环检测。达到预算时报告接口复杂度，不能删除成员、假定兼容、改用 `unknown` 或要求 runtime 扫描成员。

## 递归类型

checker 必须分别维护有限符号类型图和按需具体实例图，不得把递归声明展开为无限类型树：

| 图         | 节点与边                                     | 处理要求                                                         |
| ---------- | -------------------------------------------- | ---------------------------------------------------------------- |
| 符号类型图 | 声明模式、类型参数、成员类型和带替换的递归边 | 绑定完成后以强连通分量检测缺少运行时间接层的透明循环。           |
| 具体实例图 | 当前编译实际需求的“类型构造器 + 规范实参”    | 惰性创建并驻留；回到已有实例时闭合，持续产生新实例时记录增长链。 |

同一类型作用域必须先建立全部类型符号，再解析前向和互相递归引用。纯类型跨模块引用消费 T55 提供的绑定结果；checker 不负责模块解析或运行时初始化顺序。

递归相等和兼容使用有向节点对缓存。缓存键至少包含左右 `TypeId`、关系种类、方向和可变性上下文。首次访问先标记为“比较中”；当前分支再次遇到同一节点对时只闭合该回边，其他有限成员、权限、可选性和类别仍须完整检查。可写成员不能因回边从不变放宽为协变。

递归值不从后续写入反向修改初始化推导。递归函数调用强连通分量必须具有足够的显式返回类型或上下文函数类型，使每条递归返回依赖得到唯一结果；不足时编译报错，不能退化为 `any`、`unknown` 或隐式 `void`。

递归类型运算的缓存键至少包含操作身份、输入 `TypeId` 和规范类型参数。再次遇到相同操作和实参时建立结果回边；每轮产生新实参或新结构且无法形成有限闭包时，在触发位置报告无限类型计算。

| 操作         | 实现与复杂度要求                                                         |
| ------------ | ------------------------------------------------------------------------ |
| 声明循环检测 | 使用强连通分量算法，目标复杂度为 O(V + E)。                              |
| 相等与兼容   | 使用节点对记忆化，不按运行时对象深度重复比较。                           |
| 泛型实例     | 只创建当前需求可达的规范实例。                                           |
| 无限增长     | 报告函数或类型运算、初始实参和重复增长步骤，不等待宿主栈溢出或内存耗尽。 |
| 复杂类型运算 | 使用工具链版本确定的工作预算；预算耗尽产生独立资源诊断。                 |

常规回边不按源码深度持续消耗预算。资源诊断不能假定尚未完成的关系成立或失败，也不能返回 `never`、`unknown`、部分类型或动态运行时表示。

## 函数重载

重载集合保留源码顺序。checker 先按接收者、参数数量、基础类型类别和字面量建立候选索引，再按 TypeScript strict 支持范围执行完整适用性与回调上下文类型检查。候选解析不能读取运行时值，返回类型也不能单独区分参数完全相同的签名。

实现体控制流为每条路径维护仍可能进入该路径的公开重载集合。`typeof`、判别字段、严格相等和其他 T06 收窄同时更新参数类型与活动集合；每个 `return` 必须兼容当前全部活动重载的返回类型。

条件表达式和穷尽局部赋值可以通过有限“前驱条件 + 值类型”来源集合保留返回关联。值进入对象、数组或字典，经过未知调用、闭包或别名写入，或者形成无法有限表达的循环合并时，关联失效；无法继续证明时编译报错，不能插入返回 tag 检查或动态失败路径。

多个重载参数域重叠时，重叠部分的运行时结果必须同时满足所有适用返回契约。参数域包含和交叠检查使用规范类型关系缓存，不能仅依赖声明顺序接受互不兼容结果。

重载不设置较小语言级签名数量上限。候选适用性、参数关系、上下文回调和重复调用组合使用规范 `TypeId` 缓存；复杂关系使用工具链版本确定的工作预算。预算耗尽时报告触发调用、候选规模和主要高成本关系，不得切换启发式、`any`、动态候选表或运行时分派。

## 元组形状

固定元组按元素数量线性检查。optional 元组使用合法长度区间与形状成员图，不枚举无界组合；rest 和递归元组使用规范形状图、回边及节点对记忆化。

兼容关系必须同时检查源的所有合法长度、对应位置类型、写权限以及固定前后缀与 rest 动态区重叠。公开索引结果保持 TypeScript 可表达范围；内部地址证明可以优化固定后缀读取，但不能放宽后续源码检查。

元组不设置 `1024` 等较小语言级成员数量上限。过大的固定元组可以触发统一源码规模或类型工作预算；预算耗尽产生确定性资源诊断，不能返回部分类型、退化为数组或改用 `unknown`/动态表示。

## 泛型推导与实例图

泛型声明基于符号类型参数及其约束检查一次。实例化只能执行类型替换、约束与结果位置验证、规范化及布局合法性检查，不能把声明期非法操作推迟到调用点。

调用推导按普通实参和接收者、回调上下文、回调返回、直接结果上下文、默认参数的顺序建立候选。约束只验证候选，不在无候选时伪造具体结果；不得以 `unknown`、`any`、对象裁剪或隐式转换兜底。

闭合实例使用“泛型声明规范身份 + 规范类型实参列表”驻留。checker 只创建类型检查、布局、调用或导出实际需要的实例，并在进入可执行 Checked HIR 前完成替换。类型实参持续增长且不能形成有限实例图时，诊断必须显示声明、初始实参和重复增长路径。

## 方差求解

方差根据公开类型能力构建有限方向图。公开属性、方法、getter、setter 和公开重载参与；私有实现、重载实现签名、构造器输入和默认值不直接参与。

嵌套位置按协变/逆变方向组合；可写位置产生不变；未使用参数为独立。递归与互相递归声明使用强连通分量和有限状态迭代求稳定结果，不展开无限类型。

显式 `in`、`out` 与 `in out` 必须验证实际使用方向，类与接口可以收紧但不能放宽；透明别名标记只验证展开结果，不能改变规范兼容关系。冲突诊断必须包含最短公开成员路径。

实例数量、类型深度和关系工作使用工具链版本确定的预算。资源耗尽不能默认为不变、独立或双变，也不能生成动态泛型。

## 类型运算符

checker 内部保留以下静态节点：

```text
KeyOf(target)
TypeQuery(valueSymbol, flowPoint)
IndexedAccess(target, key)
ConstAssertion(expression)
```

闭合运算按绑定、透明别名展开、控制流类型、联合/交叉/optional/递归规范化、运算求值、结果联合规范化和驻留的顺序处理。相同操作、输入 `TypeId`、规范键和 flow point 必须得到稳定缓存结果。

`keyof` 使用规范成员索引与集合交并；索引键联合按可命中成员建立结果集合；递归输入使用访问状态和回边；`as const` 只按当前有限字面量 AST 线性访问，不遍历既有运行时引用图。

简单键集合沿用 T21 的联合容量要求，至少支持 `65535` 个简单规范成员。复杂操作使用工具链版本确定的工作预算；超限时报告操作、输入类型和主要来源，不能删除键、扩大到 `string`/`number`/`unknown`、改用 `any` 或生成运行时反射。

开放泛型可以保留符号运算配方；闭合实例必须替换为规范结果类型。类型查询依赖 T57 的值空间绑定并读取指定 flow point 的类型，不重新分析初始化器，也不回写已建立别名。

## 高级类型计算

checker 使用规范类型图表示条件类型、`infer` 变量、映射类型、模板模式、标准工具和延迟运算。开放泛型可以保留符号节点；闭合实例必须按绑定、约束和分支检查、实参替换、运算求值、规范化及驻留的顺序得到唯一结果。

条件分发只对裸类型参数展开。`infer` 候选按方差合并；映射键使用规范键集合；模板字符串优先保留宽前后缀模式，不枚举无限值域。递归计算以操作身份、输入 `TypeId`、规范实参、方差上下文和工具链语义版本作为缓存键。

工作预算至少统计新规范节点、联合与键成员、模板状态及笛卡尔积、`infer` 候选/方差约束和递归实例边。T40 保证的 `65535` 个简单键映射应使用近似线性算法完成。

预算耗尽必须报告工具名称、主要输入和增长来源；不能返回部分成员、删除分支、扩大为 `string`、注入 `unknown` 或转成运行时类型分派。

大小写和受约束模板提取使用工具链固定 Unicode 及数值格式版本。系统区域设置不能影响结果；静态规则版本必须进入跨模块配方摘要。
