# 类型与调用 ABI

- 任务编号：T47
- 规范状态：讨论中
- 文档顺序：1

## 目标与边界

本规范定义跨模块类型身份、布局指纹、调用分类、版本兼容和链接拒绝规则。源代码类型兼容由 `language/types` 定义，物理布局由 `compiler/representation` 定义，ABI 只能消费这些结果。

## 已确认上游约束

以下约束已经由前置规范确定，T47 不能重新解释：

- 跨模块值不能依靠字符串类型名、字段扫描或隐式对象重建适配布局差异。
- 导入方与导出方对规范类型、布局或调用分类的理解不一致时，必须在链接或模块加载前失败。
- 私有 runtime 入口和公开函数使用不同符号边界，但都必须经过明确的 ABI lowering。

## 类型别名与品牌

透明别名不创建独立值布局、调用分类或跨模块类型身份。导出元数据可以保留别名名称和静态配方用于诊断与下游实例化，但兼容判断使用规范目标类型。

品牌额外编码规范底层 `SemanticTypeId` 与标签类型身份。品牌和底层类型共享 `LayoutKey`；品牌建立与丢弃不生成跨模块值适配。别名名称和声明路径不能进入布局指纹。

## 字面量类型

公开签名中的字面量类型编码基础 `SemanticTypeId` 与规范字面量值。布尔、字符串、整数宽度、浮点负零及其他已支持特殊值使用工具链版本固定的规范编码，不能依赖源码拼写或宿主序列化格式。

字面量类型与对应基础类型共享值布局和调用分类。内部已经 widening 的值不携带字面量 ABI 元数据，不同字面量实参也不能仅因静态值不同强制生成不同调用约定。

## 数组

数组参数、返回值和字段保存数组对象引用，不隐式复制元素。`readonly T[]` 与 `T[]` 使用相同运行时数组表示，写权限只属于静态类型元数据。

跨模块数组类型信息至少需要表达：

- 规范元素 `SemanticTypeId`。
- 元素大小、对齐和 GC 描述符指纹。
- 数组与只读数组的静态能力。
- 联合元素布局或数组联合布局。
- 方法回调需要的副作用摘要引用。

数组布局不一致时，不能通过逐元素检查或隐式重建进行适配。

## 字符串

跨模块 `string` 传递管理存储引用，ABI 元数据记录字符串布局版本、Latin-1/UTF-16 编码约定、`i32` code unit 长度上限、GC 描述和确定格式语义版本。

调用边界不能把内部数据指针当作 UTF-8，也不能依赖字符串缓存字段或哈希值作为稳定协议。布局版本不兼容时必须拒绝链接或通过 T48 明确的编码/所有权转换边界处理，不能隐式重解释。

## 元组

跨模块元组参数、返回值和字段默认传递管理引用，不隐式复制 payload。ABI 元数据至少记录：

- 元素顺序、规范 `SemanticTypeId` 和写权限；标签不编码。
- 固定、optional 和 rest 形状及合法长度摘要。
- 固定前后缀与 rest 元素类型。
- 每个布局的大小、对齐和 GC 描述指纹。
- 同构 readonly 数组视图兼容标记。
- ABI 版本和递归类型图引用。

生产方和消费方的形状、布局或 GC 指纹不一致时必须拒绝链接或加载。不能通过运行时字符串类型名、逐元素扫描或隐式重建适配元组。

固定 tuple rest 参数可以按普通参数 ABI 传递；只有函数体实际观察参数元组身份时才物化管理引用。动态 rest 区段不得退化为通用动态实参数组。

## 类

类身份由规范模块身份和声明身份共同确定。同一声明的导入与转导出保持身份；不同模块实例或不同依赖版本中的同名类保持不同身份。

跨模块类元数据至少需要表达：

- 规范类 `SemanticTypeId` 和类家族身份。
- 基类身份与继承摘要。
- 实例布局和可选状态指纹。
- 实例与静态方法槽位签名。
- 构造签名与构造安全摘要。
- 接口 witness 和动态扩展能力。
- 静态字段 schema 与动态类描述符 ABI。

派生类到基类转换保持对象地址，不允许链接器插入字段复制、对象裁剪或指针调整。类布局、方法表或构造签名不一致时必须在链接或模块加载前失败。

## 精确对象

跨模块对象元数据至少需要表达：

- 规范属性身份和字段类型。
- 可选性与写权限。
- 字段偏移、存在位位置、大小和对齐。
- 固定区域 GC 描述。
- 动态扩展能力与定位。
- ABI 版本和布局指纹。

相同规范形状在相同目标和 ABI 版本下必须获得相同固定字段布局。源码属性顺序不参与类型或存储布局身份；枚举描述符单独保持可观察顺序。

布局摘要不一致时必须拒绝链接或加载，不能重新解释对象内存或隐式重建目标形状。

## 字典

跨模块字典元数据至少需要表达：

- 键域、值类型和读写权限。
- 固定成员摘要。
- 原生字典或对象视图来源类别。
- `DictionaryWitness` 和动态扩展定位。
- 值布局、枚举能力和 GC 描述指纹。

抽象函数边界使用统一字典视图 ABI。静态已知来源可以在模块内去除 witness，但不能改变公开边界表示。

兼容转换不能通过逐条复制、重哈希或运行时成员检查实现。扩展状态定位的内联与稀疏回退路径必须具有稳定描述符和版本约束。

## 数值与平台整数

固定宽度整数和浮点按 T45 规范标量布局直接传递。`number` 与 `f64` 即使当前表示相同，跨模块元数据仍保留不同 `SemanticTypeId`。

包含 `usize` 或 `isize` 的产物必须记录：

- 目标平台与架构。
- 指针宽度。
- 数据布局。
- ABI 版本。

不同指针宽度或数据布局的模块不能直接链接，也不能插入运行时宽度转换。包含平台整数的公开布局明确标记为目标相关，不能声明为跨目标稳定 ABI。

合法的固定宽度与平台整数跨模块传递必须保持零运行时转换成本。

## 布尔

跨模块 `boolean` 使用 T45 的规范一字节内存布局，只允许 `0` 与 `1`。目标调用约定可以在寄存器中扩展，但参数、返回、字段和跨模块边界必须使用统一 ABI 分类。

truthiness 是表达式操作，不改变源值 ABI。FFI 若使用不同布尔宽度或真值编码，必须由 T48 显式适配，不能把外部整数无检查重解释为 Nxts `boolean`。

## `void`、`undefined`、`never` 与 `symbol`

| 类型或签名                 | ABI 约束                                                 |
| -------------------------- | -------------------------------------------------------- |
| 同步 `(): void`            | 无返回载荷，公开签名仍保留 `void`。                      |
| 同步 `(): undefined`       | 保持可使用值语义；ABI 可以省略载荷并由调用方产生单例值。 |
| `(): Promise<void>`        | 返回 Promise 引用；成功状态不保存 fulfillment payload。  |
| `(): never`                | 无正常返回边；提供方正常返回属于 ABI 违约。              |
| `symbol` / `unique symbol` | 使用同一标量值 ABI；静态 unique 身份保存在类型元数据。   |

`void` 与 `never` 即使没有返回载荷也不能合并语义类型。只有公开签名为 `never` 时，跨模块调用方才能依赖不返回契约；实现内部推导出的终止状态不改变公开 ABI。

导出 `unique symbol` 必须记录模块和声明身份，并把运行时导出值关联到同一 `SymbolId`。外部整数或指针不能无检查进入 symbol ABI。

## 枚举

枚举按其规范标量布局传参与返回，不附加隐藏描述符或有效性参数。跨模块静态元数据至少记录：

- 名义 `SemanticTypeId` 与底层类别。
- 按声明顺序排列的成员名称和规范值。
- 重复值别名及规范显示名称。
- 空值和联合布局摘要。
- 可选成员表及调试元数据需求。
- 枚举静态契约指纹。

成员增加、删除、改名、改值、改变底层类别或别名关系都会改变静态契约指纹。即使标量调用 ABI 未变化，消费模块也必须重新检查或重新编译，不能继续使用已内联的旧常量。

链接后没有反射、调试或成员遍历需求的名称数据可以删除。编译元数据不构成运行时枚举对象。

## 动态值与类型检查

跨模块 `unknown`、接口值和受信类型检查至少需要：

- 规范动态描述符身份与 payload 布局指纹。
- 类祖先、精确对象、容器和函数签名关系摘要。
- 接口契约指纹与 witness ABI。
- 联合成员描述关系。
- 成功 payload 或接口视图的调用分类。

链接器必须在运行前验证这些元数据并建立快速查询关系。类型指纹或 witness ABI 不兼容时拒绝链接或加载，不能在运行时退化为字段扫描或临时结构适配。

`unknown` 的公开 ABI 使用 T45 的规范二字表示。32 位目标上大型标量或聚合的动态盒属于该目标规范布局，必须进入 ABI 指纹；不能由单个模块自行改变装箱阈值。

## 函数与重载

单一函数 ABI 记录接收者类别、参数顺序、规范参数类型、必选/可选/default/rest 形式、返回类型、物理参数与返回分类以及调用约定版本。参数名称、默认值表达式、函数体、捕获字段顺序和优化后符号名不进入指纹。

参数数量兼容使用按需类型化入口：

| 场景             | 入口行为                             |
| ---------------- | ------------------------------------ |
| 源形参数量较少   | 接收目标签名完整参数并忽略安全尾参。 |
| 源位置可省略     | 为目标未提供槽位传入 `undefined`。   |
| 源具有 rest 参数 | 按 rest 语义构造独立数组。           |

返回协变按表示关系处理：

| 表示关系                                   | ABI 处理                                    |
| ------------------------------------------ | ------------------------------------------- |
| 表示相同                                   | 复用原入口。                                |
| 静态接口打包或重打包                       | 生成只写入底层引用和既定 witness 的短入口。 |
| 静态联合注入或有界重打包                   | 生成只构造确定 tag 与 payload 的短入口。    |
| 需要装箱、分配、复制、运行时检查或可能失败 | 不形成隐式函数兼容。                        |

适配入口具有完全匹配的物理签名，可以内联，并按规范源/目标 ABI 键缓存。所有入口共享同一函数身份、实现、`name` 和 `length`；不能依赖后端容忍不匹配函数指针调用。

导出重载函数还必须保留：

- 有序公开重载签名和语义类型身份。
- 每个签名对应的规范物理 ABI 键。
- 共享函数身份与实现版本指纹。
- 重载解析规则版本。

实现签名保持模块私有。导入方在编译期选择入口，运行时不携带候选表；提供方导出实际需求的入口，链接器可以合并物理签名相同的入口并删除未引用入口。新增、删除或重排公开重载可能改变解析结果，属于公开 API 兼容性变化。

## 泛型

导出的泛型不能只发布生产模块当前生成的机器码。模块产物必须保存可实例化的已检查配方与稳定摘要，至少包含：

- 泛型声明规范身份与版本。
- 类型参数、约束、默认值、`const` 和合法显式方差标记。
- 规范化符号签名与已检查函数体配方。
- 所需 intrinsic、类、接口和递归类型依赖。
- 代码生成、布局、GC 与调用 ABI 兼容版本。
- 自动求得的规范方差摘要。

消费模块和最终链接按实际闭合实参合并实例需求并缓存；不要求原始源码，也不允许 runtime 泛型解释器。不同闭合实例可以具有不同布局和入口，泛型类仍共享一个运行时类家族身份与静态状态。

一等泛型函数值和接口泛型方法只为最终程序静态可达的闭合签名分配固定槽位。槽位键必须包含声明身份、规范实参和物理 ABI；动态库无法提供未知新槽位时必须明确拒绝或要求重新链接，不能退化为哈希查找泛型字典。

方差摘要由公开成员、递归依赖和合法显式标记决定，参与静态契约指纹但不进入值布局、witness 值或 GC 描述。摘要与配方校验不一致时拒绝产物。方差变化即使不改变机器 ABI，也要求消费模块重新执行静态兼容检查。

## 类型运算配方

导出的闭合类型运算优先编码规范结果 `SemanticTypeId`。导出的开放泛型可以编码静态运算配方与依赖摘要，但必须与运行时布局和调用 ABI 元数据分离。

配方摘要至少能够表达固定键集合和键域、属性类型与权限、类和枚举静态成员、数组/元组/字典索引规则、类型查询依赖的导出值签名、const assertion 结果形状以及递归回边。

依赖成员、可选性、写权限、枚举成员或标准类型 API 变化时，消费模块必须重新检查。纯类型查询不能建立运行时初始化依赖，也不能要求保留模块或枚举运行时对象。

## 高级类型配方

闭合高级类型导出编码规范结果 `SemanticTypeId`；开放泛型高级类型编码已绑定的静态计算配方。摘要至少记录操作种类与标准符号身份、条件分发、`infer` 作用域、映射修饰、模板片段和符号模式、依赖类型与递归回边，以及 Unicode、格式、预算和规范化语义版本。

消费模块实例化开放配方时必须得到相同规范结果。摘要、依赖、目标平台格式或语义版本不兼容时，在链接或增量构建阶段拒绝或要求重新检查，不能依赖运行时修补。

高级类型摘要只供编译器和静态工具使用，不进入对象、闭包、普通模块初始化、GC 描述或值调用 ABI。

## 接口

导出接口元数据至少记录：

- 规范契约指纹和成员槽位顺序。
- 成员种类、类型、权限、可选性和方法签名。
- 泛型参数、约束、默认值和实例化配方。
- 具体类型与目标契约的 witness 指纹。
- witness ABI 版本和所需 runtime 能力。

成员槽位按规范键与成员种类确定，不按源码或继承顺序。两个模块独立声明的同结构接口必须得到同一契约指纹。

| 变化                   | ABI 结果                    |
| ---------------------- | --------------------------- |
| 仅调整声明或继承顺序   | 指纹和槽位不变。            |
| 添加必选属性或方法     | 不兼容。                    |
| 修改类型、可选性或权限 | 默认不兼容，重新检查。      |
| 添加只读可选成员       | 由版本化 witness 规则决定。 |

链接器不能因名称相同跳过结构指纹，也不能在不兼容时运行时逐项适配。方法级泛型只导出实际需要的闭合槽位；开放动态库实例策略仍待 T47 定稿。

## 联合类型

跨模块联合元数据至少记录：

- 规范语义成员集合和稳定成员顺序。
- 表示类别、成员到 tag/niche 的映射。
- payload 大小、对齐和每成员 GC 形状。
- 参数与返回 ABI 分类。
- 目标布局和 ABI 版本下的布局指纹。

源码成员顺序和透明别名不创建新 tag 空间。不同成员集合即使赋值兼容，也可以需要 `UnionRepack`；只有布局记录完全兼容时才能在模块内消除。

内部 tag 不构成序列化、网络或 FFI 判别值。导入方摘要不一致时必须在链接或加载前拒绝，不能运行后重解释 payload。

## 交叉类型

闭合交叉只导出规范化后的具体类型身份和布局摘要，不建立独立交叉 ABI。`A & B` 与 `B & A` 规范化结果相同时，必须得到相同 ABI 记录。

导出的泛型配方可以保存符号交叉约束，但每个闭合实例必须在生成调用 ABI 前完成规范化。未闭合交叉不能跨模块按动态值传递。

## 递归类型

导出的递归类型使用规范强连通分量生成稳定指纹。指纹至少编码类型类别、规范成员、权限、可选性、泛型参数位置、递归边和边上的类型替换。

指纹不能包含源码文件遍历顺序、进程内 `TypeId`、指针地址或临时编号。同一递归结构在不同声明顺序、文件顺序和遍历顺序下必须得到同一结果。

增长型泛型递归只编码有限声明模式和替换边，不枚举无限具体实例。模块元数据同时引用 T45 的布局记录和 T46 的 GC 描述；链接器必须验证类型指纹、布局版本和描述符 ABI 一致。

T47 负责指纹编码、版本校验与描述符链接；T55 负责模块解析、导出图和运行时初始化顺序。类型循环合法不表示模块初始化循环安全。

## 待确认项

- 元数据二进制格式和版本字段。
- 符号编码、布局指纹验证和冲突诊断。
- witness、类描述符、泛型实例和函数重载的二进制表示。
- ABI 兼容升级与明确拒绝策略。
